### 手持与空手

1. 聚焦道具格有道具，玩家即处于手持状态，并显示该道具。
2. 切换聚焦后，以新聚焦道具格的内容更换手持显示；新聚焦道具格为空则变为空手。
3. 聚焦道具格为空时，玩家处于空手状态，可以通过符合条件的交互取得道具并放入此格，随即变为手持。
4. 空手由当前聚焦格决定，不要求整个道具栏为空。
5. 用户指出玩家已有手持相关接口；当前代码可确认的是手持挂点、引用及摆动连接，尚未具备完整道具切换流程，见第四节。

由以上规则可直接推导：当前格已占用时，不能因为其他格有空位，就自动把从原药组取得的原药塞到其他格。需要先切换到空格。切换聚焦仅改变当前手持对象，不能清空原先道具格。

### 原药

原药可以从原药组或原药放置架获得。单个原药自身也是可交互物；不在原药组中的世界原药可以直接交互取走，例如放在架上的原药。

### 原药组

1. 原药组是提供对应原药的交互点。
2. 玩家空手时交互一次，获得一个对应原药，放入当前聚焦的空格并显示为手持。
3. 原药组本身不发生变化，不减少陈列原药，也不扣减库存。
4. 玩家当前不是空手时，不满足取药条件。

原药组与单个原药的区别：原药组持续提供新原药；架上的单个原药是在玩家与世界之间转移。不能把原药组中的某个陈列物直接移走作为取药结果。

### 原药放置架

1. 每个架子具有相应数量的槽位，仅有空槽位时才能放入原药。
2. 玩家手持原药，与架子交互即可放置。
3. 放置后的原药位置为对应槽位的位置。
4. 架上的原药能够再次取下，架子用于临时存放。
5. 放入时按槽位编号从小到大选择第一个空位，不按距离或准星位置选择。
6. 取回时必须瞄准具体原药，取得被瞄准的这一件；交互架体不自动挑选原药取回。
7. 咖啡因与苯甲酸钠可以混放，共用架上全部槽位，不按原药类型划分区域。两类原药均从全部槽位中按编号选择第一个空位。

按转移含义推导：成功放置应移出当前道具格，使玩家变为空手，聚焦仍停留在原格；成功取回后，该架子槽位重新空出。此处不是新增“复制原药”的机制。

## 二、状态变化与边界分析

| 当前状态 | 行为 | 结果或待确认点 |
| --- | --- | --- |
| 聚焦空格 | 交互原药组 | 当前格得到一个对应原药；显示手持；原药组保持不变。 |
| 聚焦有道具格，其他格为空 | 交互原药组 | 不获得原药；其他空格不参与自动分配。 |
| 手持原药 | 切换到空格 | 原药留在旧格；玩家变为空手。 |
| 空手 | 切换到有道具格 | 显示新聚焦格的道具。 |
| 手持原药，架子有空位 | 交互架子 | 原药移入编号最小的空槽位；当前格清空。 |
| 架上已有另一种原药，仍有空位 | 手持原药交互架子 | 允许混放；仍选择全部槽位中编号最小的空位。 |
| 手持原药，架子已满 | 交互架子 | 无法放置；原药仍保留在玩家当前格。 |
| 空手，架上有原药 | 瞄准具体原药并交互 | 被瞄准的原药进入当前格并显示手持；对应架子槽位空出。 |
| 空手 | 交互空架子 | 没有可以放置或取回的原药；反馈形式待定。 |
| 手持其他类型道具 | 交互原药架 | 本轮只定义架子接收原药；其他类型的交互效果没有定义。 |

一致性建议，尚未确定实现形式：先验证接收位置及道具合法性，再完成转移；失败不得先删除手中或架上的原药。手持显示应从聚焦格内容派生，避免道具格显示为空而手上仍残留道具。

数量核对条件：成功从原药组取药一次，玩家与架子中的实际原药总数增加1；玩家与架子之间一次放入或取回，总数不变；失败操作和滚轮切换，总数不变。原药组陈列不计入可转移库存。

## 三、界面尺寸核对

已核实 degauss（消磁）当前参考格子为80×80像素，格间距配置为10像素。用户已确认沿用资源、格子尺寸、10像素格间距及聚焦效果。道具图标来源和外围留白尚未指定。

按单行4格计算，格子与格间距合计宽度为4×80＋3×10＝350像素，高80像素；此范围不计额外外围留白。

用户已确认80像素指道具栏下边缘距屏幕底边。因此在1920×1080设计画布上，道具栏上边界为1080－80－80＝920，下边界为1000；若采用上述350像素总宽度，左边界为（1920－350）÷2＝785，右边界为1135。

以上是算式推导，不是运行测量；间距已确认，整体边界仍需区分格子范围和可能的外围留白。其他分辨率下保持设计比例还是保持实际像素尺寸，尚未指定。

## 四、当前代码与场景证据

### 1. 参考格子资源与尺寸已找到

实际来源位于本机参考项目：[格子场景](/D:/cogito/addons/cogito/InventoryPD/UiScenes/Slot.tscn:6)引用[消磁格子边框贴图](/D:/cogito/assets/textures/ui/inventory/degauss_inventory_slot_border.png)。[格子场景第29行](/D:/cogito/addons/cogito/InventoryPD/UiScenes/Slot.tscn:29)开始定义格子，最小尺寸和初始边界均为80×80。

[参考道具界面脚本](/D:/cogito/addons/cogito/InventoryPD/UiScenes/InventoryUI.gd:5)明确设置格子尺寸80、格间距10、容器内边距20；第17行起在运行配置中再次设置格子为80×80。[格子脚本](/D:/cogito/addons/cogito/InventoryPD/UiScenes/Slot.gd:42)在父节点为网格容器时调用该尺寸设置。

因此，80×80有场景和脚本两处依据。20像素是参考背包容器内边距，不能直接追加为本轮道具栏要求。当前核查未进行运行画面尺寸验证。

补充核对聚焦效果：[参考格子脚本](/D:/cogito/addons/cogito/InventoryPD/UiScenes/Slot.gd:176)在获得焦点时显示 Highlight（填充高亮）并播放配置音效，在第182行起的失焦处理中隐藏填充。运行时写入的颜色四分量为（255，255，255，0.1）；这里只记录代码值，最终显示颜色与亮度仍需运行核对。[高亮面板配置](/D:/cogito/addons/cogito/InventoryPD/UiScenes/Slot.tscn:52)使用白色填充样式。

Selected（选中边框）是[另一独立面板](/D:/cogito/addons/cogito/InventoryPD/UiScenes/Slot.tscn:60)，由[设置选中状态的方法](/D:/cogito/addons/cogito/InventoryPD/UiScenes/Slot.gd:151)等路径控制，不能将其直接描述为普通道具格的聚焦效果。用户本次确认沿用参考聚焦效果；本轮仅补充其代码依据，未复制旧界面的鼠标悬停切换规则，新道具栏的聚焦输入仍按已确认的滚轮规则。

### 2. 参考背包的拾取方式与本轮规则不同

[参考背包脚本](/D:/cogito/addons/cogito/InventoryPD/cogito_inventory.gd:228)的 pick_up_slot_data（拾取道具格数据）先遍历背包寻找可合并对象，再遍历寻找可以放入的空位。[参考拾取组件](/D:/cogito/addons/cogito/Components/Interactions/PickupComponent.gd:33)在背包接收失败时返回，成功后于第49行释放对应世界物体。

可参考的部分是“接收成功后再移除世界物体”。需要调整的部分是接收位置：本轮要求当前聚焦空格，而参考实现会寻找整个背包中的可用位置。不能直接沿用其自动合并与自动找空格规则。

### 3. 玩家已有手持挂点，但尚无完整道具栏

[玩家脚本](/D:/autolysis/main-autolysis/player/autolysis_player.gd:126)保存 wieldables（手持物容器）引用。[玩家场景](/D:/autolysis/main-autolysis/player/autolysis_player.tscn:152)在头部下配置 Wieldables（手持物容器），挂载摆动脚本，并在第165行连接鼠标移动通知。[摆动脚本](/D:/autolysis/main-autolysis/player/components/wieldables_sway.gd:9)负责位置回正和鼠标引起的位移。

本轮检索当前主项目脚本并核查完整玩家脚本：未发现道具格数据、滚轮切格或根据聚焦内容装卸手持显示的完整流程。挂点可以作为后续接入基础，不能等同于功能已经完成。

### 4. 原药与原药组尚未接入交互

两种[单体咖啡因](/D:/autolysis/main-autolysis/scenes/prefabs/prefab_raw_materials/rm_caffeine_0.tscn:38)与[单体苯甲酸钠](/D:/autolysis/main-autolysis/scenes/prefabs/prefab_raw_materials/rm_sodium_benzoate_0.tscn:38)均以 StaticBody3D（静态三维物理体）为根节点，具有碰撞和模型，当前场景没有业务脚本或交互组件。

[咖啡因组](/D:/autolysis/main-autolysis/scenes/prefabs/prefab_raw_materials/rm_caffeine_group_0.tscn:28)与[苯甲酸钠组](/D:/autolysis/main-autolysis/scenes/prefabs/prefab_raw_materials/rm_sodium_benzoate_group_0.tscn:28)均实例化4个对应单体场景作为陈列，组本身也有物理碰撞。

实现约束分析：若以后直接给单体场景添加拾取能力，组内实例也会继承相关配置。必须区分“组内陈列”和“独立世界原药”，确保组内实例不能单独取走；同时验证组内物理碰撞不会挡住原药组交互入口。具体采用独立展示场景还是配置开关，尚未决定。

### 5. 当前原药架有36个槽位，容量不应从外观猜测

[原药放置架](/D:/autolysis/main-autolysis/scenes/prefabs/prefab_place_shelf/place_shelf_workroom_rm_0.tscn:49)具有槽位父节点及编号0至35的36个直接子槽位。第51行起为下层18个槽位，第123行起为上层18个槽位，最后一个槽位在第191行。当前没有占用管理、放置或取回脚本。

槽位在场景内使用局部位置，架子根节点本身带有旋转。放置实现需正确继承架子和槽位的空间关系；不能把槽位局部坐标直接当作世界坐标。用户只明确了位置，原药朝向及手持时的姿态尚未指定。

[架子碰撞形状](/D:/autolysis/main-autolysis/scenes/prefabs/prefab_place_shelf/place_shelf_workroom_rm_0.tscn:6)是一个整体盒体。用户已确认取回必须直接瞄准原药，因此后续必须在实际场景验证原药碰撞可以先被射线命中。此处记录待验证风险，不宣称已经发生遮挡故障。

### 6. 已有直接交互入口，需要接入道具条件

[当前射线脚本](/D:/autolysis/main-autolysis/player/components/interaction_raycast.gd:11)只检查中心射线的首个碰撞，要求命中物属于可交互分组。[交互控制器](/D:/autolysis/main-autolysis/player/components/autolysis_interaction_controller.gd:54)从被命中物的直接子节点查找唯一交互组件，并依据组件能否交互来更新准星。

[基础交互组件](/D:/autolysis/main-autolysis/components/interactions/autolysis_interaction_component.gd:19)的 can_interact（能否交互）当前检查启用状态、模式、有效物理父节点及唯一有效接收者，没有原药、空手和架子容量判断。第35行的 try_interact（尝试交互）成功返回仅表示请求已分发，不能作为道具转移成功的依据。

实现分析：原药组应检查当前格为空；架子放入应检查手持原药且有空槽位；单体取回应检查当前格为空。建议让准星可用状态与最终执行使用相同的业务条件，避免显示可操作却无法取放。接入形式仍属后续设计。

[当前项目配置](/D:/autolysis/project.godot:83)已有鼠标左键直接交互动作；文件尚无显示分辨率与缩放配置，也没有道具栏滚轮动作。1920×1080是本轮用户要求，不能误写成当前工程已经设置。

丢弃、使用或消耗原药、扩充道具栏、数字键切换、存读档、跨场景持久化均未在本轮定义，暂不加入功能要求。

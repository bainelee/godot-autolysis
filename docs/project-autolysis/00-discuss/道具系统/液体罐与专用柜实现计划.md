## 一 需求与本次实现边界

| 用户要求 | 实现结果 |
| --- | --- |
| 液体罐是可拾取的重要道具 | 世界中的可拾取液体罐进入当前选中空道具格；成功提交后才移除世界来源。 |
| 液体罐可以放在物品栏内 | 使用现有四格道具栏，每格一罐，不堆叠；选中该格显示手持液体罐。 |
| 液体罐可以放在专属位置 | 本次接入柜子现有零号、一号槽，每槽最多一罐，只接受液体罐。 |
| 柜子最多放置两个液体罐 | 柜子维护两个独立槽位，满载时拒绝第三罐，保留玩家手中来源。 |
| 柜门直接交互打开与关闭 | 沿用现有鼠标左键直接交互；命中柜门时只开关门。 |
| 打开后可以取罐或放罐 | 只有柜门完全打开、无取放事务时允许取放；关闭及开关动画期间均拒绝。 |
| 参考之前实现的架子 | 放入编号最小的空槽；空手瞄准哪一个罐就取哪一个；所有失败保持来源与既有占用。 |

以下为本计划提出的实施选择，不冒充用户已逐项确认的需求：默认关闭柜门，登记场景现有两罐为初始满载；以当前会话内取放为本期范围；三个机器中现有嵌入罐暂按固定装配保留。机器专属槽位业务、液体种类和容量、灌装与消耗、自由丢弃、长期存档另行定义。本期不凭“重要道具”推定液体参数或存档机制。

“手持”始终由当前选中道具格决定。其他格有罐而当前格为空，仍为空手；当前格有道具，即使其他格有空位，也不自动换格接收。依据见 [领域术语](/D:/autolysis/docs/project-autolysis/00-discuss/道具系统/CONTEXT.md) 与 [接收许可](/D:/autolysis/main-autolysis/player/components/autolysis_inventory_controller.gd:58)。

## 三 玩家行为与状态规则

| 准星首命中目标 | 当前手持状态 | 柜门状态 | 允许效果 |
| --- | --- | --- | --- |
| 柜门 | 空手、液体罐或其他道具 | 完全关闭 | 只开始打开，不同时拾取内部罐。 |
| 柜门 | 任意 | 完全打开 | 只开始关闭，保留柜内占用。 |
| 柜门 | 任意 | 正在打开或正在关闭 | 拒绝重复请求，不中断或重启动画。 |
| 柜内液体罐 | 当前格为空 | 完全打开 | 取回首命中的那一罐，另一槽不变。 |
| 柜内液体罐 | 当前格已有任意道具 | 完全打开 | 不交换、不覆盖，不另找其他空格。 |
| 柜内放置入口 | 手持液体罐且存在空槽 | 完全打开 | 放入编号最小的空槽，只转移一罐。 |
| 柜内放置入口 | 手持液体罐但两槽均满 | 完全打开 | 拒绝，当前格及手持模型不变。 |
| 柜内目标 | 任意 | 非完全打开 | 拒绝取放；从侧面、背面或直接调用业务入口也必须拒绝。 |
| 柜子 | 手持原药或其他非罐道具 | 任意 | 不放入柜子；实际命中门时仍可正常开关门。 |
| 柜外独立可拾取罐 | 当前格为空 | 无所属柜 | 允许世界拾取；不依赖柜门状态。 |
| 机器中固定装配罐 | 任意 | 无所属柜 | 本期不允许取走。 |

保持现有2单位直接交互距离、鼠标左键及滚轮切格。沿用现有交互许可与准星可用提示，不增加柜子专用背包窗口或聚焦会话。关闭门、场景暂停、玩家输入禁止、目标失效及转移忙碌时，显示许可与执行许可必须一致。

## 四 道具和专用柜模块设计

### 4.1 液体罐定义与显示

新增液体罐道具定义，复用 AutolysisItemDefinition（道具定义）。拟用 item_id（道具标识）值 liquid_tank（液体罐），中文名称“液体罐”，is_raw_material（是否原药）显式设为假。柜子接收条件核对该标识、有效定义及合法液体罐世界场景；不能用“不是原药”作为全部接收条件。

从当前 mesh（模型容器）及其子网格制作纯显示场景，保留材质和几何。世界罐实例引用该显示场景，道具定义的 visual_scene（纯显示场景）也引用它。保持当前世界罐原点、碰撞尺寸、资源路径及场景唯一标识。原实施阶段保留原资产拼写；2026年10月2日已统一更正为 liquid（液体），场景路径、节点名称及代码引用同步更新。

图标从纯显示场景实际渲染生成。沿用现有图标目录和道具栏显示方式；[现有图标渲染脚本](/D:/autolysis/main-autolysis/systems/item-system/tests/render_item_icons.gd:3)硬编码原药名称和相机参数，需新增液体罐入口或明确参数化，不能只追加名称而沿用未经检验的原药构图。手持位置、旋转、缩放通过实际画面检查确定，不把原药默认姿态视为罐的最终参数。

### 4.2 液体罐世界物体

新增 AutolysisLiquidTank（液体罐世界物体），继承 StaticBody3D（三维静态物理体），负责道具定义、所属柜、槽编号、固定装配标记和拾取完成标记。直接子级仅配置一个 AutolysisInteractionComponent（交互组件）。

罐的许可查询必须只读：核对定义、当前选中空格、拾取状态和来源；柜内罐还须核对所属柜有效、柜门完全打开、该柜确实登记此罐且实际父节点为指定槽。不得在所属柜失效时退回“无主世界罐”而绕过门禁。固定装配标记即使父设备失效，也不得自动解除。

成功拾取后立即隐藏罐、关闭其交互和碰撞、移出可交互分组，再排队释放，参考 [原药完成拾取](/D:/autolysis/main-autolysis/systems/item-system/autolysis_raw_material.gd:51)。固定装配罐只关闭拾取组件和可交互分组，保留现有物理碰撞；如改用纯显示模型，须先证明机器已有等效物理阻挡。

### 4.3 专用柜占用

新增 AutolysisLiquidTankCabinet（液体罐专用柜），负责两个锚点、两个占用记录、活动门状态、放置入口和柜级转移锁。显式绑定 liquid_tank_slot_0（液体罐零号槽）及 liquid_tank_slot_1（液体罐一号槽），校验编号和引用不重复；不沿用原药架的节点前缀自动收集。

初始化扫描两个锚点下现有液体罐并登记双向归属。每槽零件或一件合法罐均可初始化；两个或更多子罐、非法类型、同一实例重复登记及失效引用应明确报错并禁用柜内取放，不能覆盖、删除或额外生成来源罐。

提供只读空槽查询、指定槽取物、归属核对，以及挂接、释放、候选回滚、开始和结束转移等内部入口。挂接时使罐局部变换归一，登记柜和槽编号；释放时只解除该罐对应槽，不影响另一槽。回滚核对本次候选身份，不清理整个槽的子节点。该顺序参考 [架子挂接和释放](/D:/autolysis/main-autolysis/systems/item-system/autolysis_raw_material_shelf.gd:67)。

### 4.4 库存控制器接入

在 [库存控制器](/D:/autolysis/main-autolysis/player/components/autolysis_inventory_controller.gd)新增液体罐专用的世界拾取、柜内放置与许可查询入口，复用现有四格数据、手持准备、提交及通知。原药架、原药世界工厂和混合槽的类型限制保持独立。

新增液体罐世界场景校验与准备函数：查询阶段只读取场景描述，验证根脚本为 AutolysisLiquidTank（液体罐世界物体）、定义标识一致、资源可实例化及非固定装配；执行阶段才实例化，检查实际根类型和定义。不得把现有 _get_world_scene（获取世界场景）中的原药类名校验删掉，也不得宽泛接受任意物理体。

现有 [道具栏显示](/D:/autolysis/main-autolysis/ui/inventory/autolysis_inventory_bar.gd:49)读取定义的图标和名称，原则上无需新增罐专属界面分支。本期仅保留同类罐的数量和占用，不声明能保存每个罐不同的液体内容。若后续要求逐罐数据，应先引入道具实例数据，再调整所有转移和持久化入口，不能把可变液体量写入共享定义资源。

## 五 柜门动画与检测分层

### 5.1 柜门状态与直接交互

柜门使用“完全关闭、正在打开、完全打开、正在关闭”四态。直接交互组件必须挂在 cabinet_door_left_root（左柜门活动根）物理体的直接子级，不能挂到其网格子级。门体加入 interactable（可交互）分组，组件保持直接动作模式，并同步接收一次请求。

接受开门请求后立即进入正在打开状态，再由现有 AnimationPlayer（动画播放器）播放 open（打开）动画；接受关门请求后立即进入正在关闭状态，倒放同一动画。只在匹配动画结束后进入完全打开或完全关闭。非循环动画和倒放端点需实际验收；不得通过开门请求已经发出、固定时间估算或参考项目的“门状态变化”信号提前开放取放。

开闭期间拒绝重复门请求和所有取放。柜级转移锁持有期间拒绝开关门；动画被停止、播放器被释放或配置失效时关闭取放许可，不留下逻辑已开而物理未开的状态。暂停期间沿用当前玩家输入门禁，恢复后继续完成动作。

参考 [混合槽四态和倒放](/D:/autolysis/main-autolysis/scenes/prefabs/prefab_machines/scripts/autolysis_blend_slot.gd:72)及[匹配动画结束](/D:/autolysis/main-autolysis/scenes/prefabs/prefab_machines/scripts/autolysis_blend_slot.gd:180)。该脚本具有聚焦会话限制，本期只取状态与事务模式，不直接继承其业务。

### 5.2 已有动画验证的限制

现有 [柜门验证结果](/D:/autolysis/docs/project-autolysis/00-discuss/交互系统/柜门打开动画验证/验证结果.json)记录：实际播放通过、重置通过、打开终态约75度；物理同步通过为假，总通过为假。它证明已有动画能播放，也留下了尚需复核的物理姿态差异；不是柜门与取放已验收的证明。

实施第一步复核该检查的采样阶段、对比对象、误差计算和物理帧时序，再用当前场景逐帧比较门体、网格、碰撞形状和物理服务器姿态。当前记录没有附带可复跑的验证脚本，不能据此直接判定差异根因。保留 callback_mode_process（动画回调处理模式）的当前物理帧配置；若需调整 sync_to_physics（物理同步），必须结合实际动画驱动方式和运行证据，不直接复制不相同的父子结构设置。适用依据见 [动画混合器处理模式](https://docs.godotengine.org/en/4.6/classes/class_animationmixer.html#enum-animationmixer-animationcallbackmodeprocess)及[可动画物理体同步说明](https://docs.godotengine.org/en/4.6/classes/class_animatablebody3d.html#class-animatablebody3d-property-sync-to-physics)。

### 5.3 碰撞对象与查询安排

拟沿用架子的交互分层模式：柜体继续阻挡玩家，交互射线忽略整体外壳；门体始终可检测；柜内新增薄的独立放置物理体，仅持有液体罐时加入查询。放置体位于关闭门板后方、柜内罐前方，避免柜体正面与门板共面竞争首命中。当前外壳的静态几何存在正面三角面；本轮未执行射线查询，凹面正背面响应和实际首命中仍须运行核查，不能把几何穿越直接当作已实测遮挡。

| 对象或查询 | 拟配置 | 作用 |
| --- | --- | --- |
| 柜体根 | 第4层，位值8 | 保留现有整体物理外壳，移出第1层；玩家及现有实体探测仍检测此层。 |
| 活动门体 | 第1、2层，位值3 | 空手、持罐、持原药均可命中实际门碰撞。 |
| 可拾取罐 | 第1、2层，位值3 | 空手实际瞄准罐体拾取，业务门禁独立验证。 |
| 柜内独立放置体 | 新第7层，位值64 | 只提供专用柜放置入口，具有一个直接子交互组件。 |
| 空手或其他普通道具查询 | 掩码3 | 忽略柜体和放置体，保留普通墙体、柜门及罐体检测。 |
| 手持原药查询 | 掩码19 | 保留原药架行为，不检测柜内罐放置入口。 |
| 手持液体罐查询 | 掩码67 | 检测第1、2、7层，关闭门优先阻挡；开门后放置入口位于罐前方。 |

第7层为本计划的新分配；实施开始时复核工程全局占用后再登记“液体罐柜放置入口”。第6层保持聚焦内部对象用途。玩家根、台阶、蹲伏、脚步与既有物理探测是否已纳入第4层，须按 [架子分层测试](/D:/autolysis/main-autolysis/systems/item-system/tests/shelf_layers_test.gd)逐项复核；本次不把新增第7层放置体当作玩家阻挡体。

在 InteractionRayCast（交互射线检测器）的 refresh_target（刷新目标）增加默认关闭的液体罐柜检测参数，保留现有首个原药架布尔参数含义和旧调用兼容性。每次刷新重建基础掩码，分别设置第5层和第7层，不能累计上一次状态的检测位。AutolysisInteractionController（交互控制器）从当前定义判断是否持罐，提交和切格后及时刷新。

可复算位运算：8与3、19、67按位与均为0；64与67按位与为64，与3或19按位与为0；3与上述三种查询按位与均为3。层号仅表示过滤类别，不提供目标优先级。射线仅检测其掩码包含的层并返回最近命中，依据见 [射线掩码与首命中说明](https://docs.godotengine.org/en/4.6/classes/class_raycast3d.html#class-raycast3d-property-collision-mask)和[碰撞对象层说明](https://docs.godotengine.org/en/4.6/classes/class_collisionobject3d.html#class-collisionobject3d-property-collision-layer)。

该分层允许射线穿过整体柜壳，但不取消门禁。必须测试从侧后瞄准、射线起点在形状内和业务接口直接调用。若后续要求柜壁也遮挡交互，应增加独立普通实体碰撞，不能把整体外壳重新加入基础掩码而堵住已打开的前侧。

## 六 转移顺序与失败处理

### 6.1 放入柜子

1. 只读检查玩家、当前格、液体罐定义、柜门完全打开、空槽和合法世界场景；确定编号最小的空槽。
2. 记录当前格编号、定义、柜和锚点，锁定库存及柜级转移；此后拒绝切格、重入转移和开关门。
3. 准备世界罐候选，此时不清空玩家来源；候选绑定预定柜内存放模式，避免入树回调短暂暴露无主拾取。
4. 复核来源、门状态、锚点和空槽，挂入候选；候选入树回调完成后再次核对存活、实际父节点、定义及唯一占用。
5. 登记柜内归属，清空原道具格和手持显示，在所有占用已一致后只发出一次库存通知。
6. 结束本次转移锁。任一步失败只撤销本次候选和本次登记，玩家来源及原有罐保持不变。

实施参照 [架子放置提交](/D:/autolysis/main-autolysis/player/components/autolysis_inventory_controller.gd:119)与[混合槽入树复验](/D:/autolysis/main-autolysis/player/components/autolysis_inventory_controller.gd:152)。若通知期间观察者再次查询，允许读到已提交状态；同一通知期间仍禁止再次写入。

### 6.2 取回液体罐

1. 核对首命中的罐、当前选中空格、柜门状态以及柜、槽、罐和实际父节点的相互归属；柜外无主罐使用独立来源规则。
2. 锁定库存和所属柜，准备纯手持模型；准备失败不得释放来源占用或删除世界罐。
3. 准备完成后复核玩家当前格、门、来源和归属，再释放指定槽登记。
4. 写入当前格，立即关闭来源罐的可见性、拾取与碰撞并排队释放，提交手持显示；占用一致后只通知一次。
5. 结束锁。来源已释放、门状态改变、模型无效、其他对象抢占或来源被移走时拒绝，不能补取另一槽。

参考 [世界拾取顺序](/D:/autolysis/main-autolysis/player/components/autolysis_inventory_controller.gd:86)、[混合槽取回](/D:/autolysis/main-autolysis/player/components/autolysis_inventory_controller.gd:193)以及[原项目先接收后删除的证据](/D:/autolysis/docs/project-autolysis/00-discuss/道具系统/液体罐与专用柜实现参考证据.md)。

### 6.3 数量和归属不变量

对测试中的有限可转移液体罐，满足“所有参与玩家库存中的罐数＋柜内有效占用数＋柜外可拾取罐数＝初始可转移罐数”。固定装配罐和纯手持显示模型不计入。候选在事务提交前不作为新增道具计数；通知观察点不得出现多一罐或少一罐。

每个有效柜槽最多登记一个罐；每个柜内罐只能登记到一个柜的一个槽；格子清空仅发生于世界候选成功提交之后；世界来源删除仅发生于库存接收准备和来源复核成功之后。此处验证数量与归属，不宣称现有定义引用能提供逐罐持久身份。

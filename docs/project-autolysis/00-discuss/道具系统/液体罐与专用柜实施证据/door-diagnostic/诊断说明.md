# 柜门同步时序诊断

日期：2026年10月1日。当前生产柜门保留原有物理同步设置、零点二秒横轴动作以及八十度回落至七十五度的关键帧。

本诊断在修改两目标场景前运行；实例化当时正式柜子及其门。保存基线位于上一层的基线目录。首次沙箱内进程发生引擎原生崩溃，其错误日志保留；随后经自动审批在沙箱外执行，基线与对照均生成结果。该崩溃不能用作门动画错误的证据。

比较对象包括门节点全局姿态、网格全局姿态、碰撞节点姿态及物理服务器门体和形状姿态。误差取原点差与三个基向量差长度的最大值，不能全部解释为米。每个阶段对预期形状内部九点执行真实点查询，并同时按物理服务器姿态查询九点。打开及关闭分别采样十八个物理帧；较晚普通回调按实际普通帧采样，数量随引擎帧率变化。

逐条数据见[基线四阶段结果](baseline-phases.json)与[关闭同步对照结果](sync-disabled.json)。包装器的参数、退出码分别见[基线运行记录](baseline-phases.run.json)和[对照运行记录](sync-disabled.run.json)。脚本中的原比较断言要求随后普通帧零差异，因此基线退出码为一，对照为零；该判据本身没有证明所有采样阶段均同步。四阶段数据表明：关闭同步会把不符现象移到较晚物理回调，不能将它称为全面修复。

此前提出的三项可否证预测及结果为：单变量关闭同步能否消除普通帧差异，结果为能；将普通帧信号采样延后到普通回调能否消除差异，结果为不能；按实际服务器姿态执行查询能否命中当前门碰撞，结果为所有阶段均能。

[指定版本引擎源码](https://raw.githubusercontent.com/godotengine/godot/4.6.1-stable/scene/3d/physics/animatable_body_3d.cpp)的局部变换通知路径第97至107行先提交物理目标，再还原节点到上一有效物理姿态；第67至79行在物理状态回调时更新节点。当前基线数据与该时序一致。[官方同步属性说明](https://docs.godotengine.org/en/4.6/classes/class_animatablebody3d.html#class-animatablebody3d-property-sync-to-physics)将动画驱动门列为同步用途。因此生产场景保留默认同步，业务在运动期间禁止取放；后续验收分别记录物理回调查询和稳定终态，不能把不同阶段姿态的差异直接判定为碰撞脱离门板。

可复跑入口为[诊断包装器](run_diagnostic.ps1)。基线参数为默认标签，单变量对照增加关闭同步开关。脚本目前加载正式柜场景；重跑实施后的正式柜可验证其物理时序，历史基线数据仍以已保存场景与本目录结果为准。

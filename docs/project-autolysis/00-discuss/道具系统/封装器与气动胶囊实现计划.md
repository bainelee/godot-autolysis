# 封装器与气动胶囊实现计划

编制日期：2026年10月3日。状态：需求已确认，等待实施。本次仅编写计划与保留参考证据，未修改功能代码、场景或材质，未进行封装功能的引擎验收。

本计划覆盖封装器聚焦、两类物品取放、胶囊架取用、类型选择、2秒封装、产物数据与材质、临时内容界面及胶囊废弃。依据为本次用户需求及确认答复、当前工作区实际代码和场景、原项目实际实现与官方文档。下文“拟新增”“拟扩展”均表示实施方案，不表示功能已经存在。

## 一 已确认规则与实施范围

### 1.1 用户补充确认

| 确认事项 | 最终规则 |
| --- | --- |
| 舱门与启动 | 完全打开或完全关闭均可启动；开门中、关门中均不能启动。胶囊放入、取出必须在舱门完全打开后进行。 |
| 再次点击当前类型 | 关闭当前开关，取消类型选择；没有选择时不能启动。 |
| 机器初始物品 | 两个槽位初始为空。场景当前预置的空罐和空胶囊仅作为摆放参考，实施时不登记为初始物品。 |
| 胶囊完成标识 | mesh_packing_info（封装信息网格）使用与指示灯相同的指定绿色发光材质。 |
| 胶囊废弃 | 空胶囊与已封装胶囊都允许整件丢弃。 |

当前行为需求没有剩余待确认项。设备提交至气动管道的后续操作没有给出，本文先保存可供提交读取的完整产物数据；不把提交设备的交互流程加入本次实施。相位及波形重构设备的加工算法、液体体积、长期存档和新增音效也不属于本次要求。

### 1.2 物品与槽位

封装器需要“有液体的液体罐＋空气动胶囊”才能准备封装。取放许可和加工许可分开：液体罐槽允许空罐、满罐；胶囊槽允许空胶囊、已封装胶囊。槽位只判断物品种类及实例有效性，不用内容状态限制存放。

两槽均为单件占用。手持对应种类且槽位空时放入；当前选中道具格为空且槽位有物品时取回；已占用时不交换、不覆盖。错误种类和空手点击空槽不改变任何物品。空手沿用项目定义：当前选中道具格为空，其他格是否有物品不影响空手状态，见[道具术语](D:/autolysis/docs/project-autolysis/00-discuss/道具系统/CONTEXT.md)。

胶囊架为无限供给入口。空手与架子交互，在当前空格获得一个独立的新空胶囊；架上的两个展示胶囊、架子位置及外观不变。手持物品时不能领取。

### 1.3 聚焦与加工

与 collision_machine_packing（封装器碰撞）交互，使用 focus_camera（聚焦相机）进入该设备聚焦；右键退出。两槽、舱门、三个开关及开始按钮的业务操作仅在稳定聚焦该封装器时执行。

有效输入物品齐备时允许操作三个互斥开关。类型映射固定为：type_switch_0（类型开关零）对应针剂，type_switch_1（类型开关一）对应酊剂，type_switch_2（类型开关二）对应粉剂。开启播放对应打开动画并保持末帧，对应灯切换为指定绿色发光材质。点击另一个类型关闭旧开关并打开新开关；再次点击当前开关关闭并取消选择。

启动前成功取走任一输入物品，全部开关关闭、选择清除、各灯恢复自己的原材质。重新放入合法输入不会自动恢复此前选择。

点击合法开始按钮时立即进入2秒封装，锁定全部机器交互入口，仍可右键退出。退出不取消计时。沿用配药器实际行为，运行期间退出后不能重新进入该机器聚焦，完成后可以重新进入，见[配药器进入许可](D:/autolysis/main-autolysis/scenes/prefabs/prefab_machines/scripts/autolysis_blend_machine.gd:327)。

完成时同时得到空液体罐和已封装胶囊。胶囊完整继承原药条目、相位重构、波形重构，并增加本轮封装类型。完成后可以取回两件物品；先取液体罐不重置开关，成功取回本轮产物胶囊才重置开关。

## 四 胶囊逐件数据与显示

### 4.1 数据规则

空胶囊的封装内容为空引用；封装胶囊具有合法封装内容。由内容推导空／封装状态，避免另存布尔状态与数据不同步。所有胶囊共用道具定义，各自持有独立道具实例；共享定义不保存某轮加工结果。

| 封装数据 | 存储与校验 |
| --- | --- |
| 原药 | 复用源内容的一至四条合法原药标识；保留原始顺序和重复条目，不因界面合并显示而删除条目。 |
| 相位重构 | 完整复制源三维向量，保持原数值；不重新置零或添加未定义的范围。 |
| 波形重构 | 完整复制四个布尔坐标和一个0至6的整数；显示形式保持五项坐标。 |
| 封装类型 | 只允许针剂、酊剂、粉剂三种有效值；空胶囊没有类型。机器的“未选择”值不能写入产物。 |

拟在现有逐件实例增加 packing_contents（封装内容）及胶囊身份查询、赋值和合法性检查。液体罐只允许液体内容；胶囊只允许封装内容；原药不允许带这两类内容。拟新增胶囊封装数据的外部读取接口对数组或可变内容返回副本，赋值建立本件副本。液体罐现有 liquid_contents（液体内容）读取返回本件资源引用的契约及变化通知继续保留，避免破坏现有库存事务的来源核对。

封装内容复用 AutolysisLiquidContents（液体内容资源）的 copy_contents（复制内容）取得完整副本，不能只用原药标识创建默认重构值的新内容。源罐清空后，胶囊仍持有独立数据；之后同一罐再次装填或另一胶囊加工都不得改变之前产物。

### 4.2 材质与临时界面

空胶囊标识网格保持原灰色；已封装胶囊标识网格切换为[指定绿色发光材质](D:/autolysis/main-autolysis/assets/materials/glow_color/mat_glow_green_0.tres)。世界显示、机器槽内显示和手持显示使用同一状态规则。只替换当前网格的覆盖材质引用，不修改共享材质属性，不改变其他网格。

复用当前临时内容面板，手持封装胶囊时显示：气动胶囊已封装、原药名称及数量、相位三项、波形五项、封装类型。原药合并显示和相位数字格式继续沿用当前液体罐规则。手持空胶囊或其他不显示内容的物品时隐藏面板；切换道具格、丢弃或实例变化后立即刷新。

胶囊道具定义使用非原药类别，配置中文名称、可辨认图标、世界场景与独立纯显示场景；手持姿态在实际相机画面中校验后确定，不在计划中虚构位置数值。

## 五 聚焦入口与两槽取放

### 5.1 场景装配与命中

整机增加唯一聚焦交互组件和聚焦描述；门、两槽、三开关、按钮各自增加唯一直属交互组件，显式登记所属设备。聚焦控制继续由玩家现有相机控制器负责，设备仅提供参考相机姿态。

两槽分别增加独立取放物理体，现有碰撞形状挂入对应物理体，保留名称与实际世界位置；挂点仍按现有摆放参考对齐。初始删除两挂点下作为参考的物品实例，保留挂点和变换，初始占用记录为空。不要保留可碰撞的假胶囊或固定罐冒充真实占用。

聚焦目标扩展为显式封装器配置入口；有效性检查接受本设备完整登记，不再要求该设备具有配药器原药槽。现有配药器登记、所属设备检查与专用拉杆规则继续成立。聚焦进入的运行锁检查同步覆盖封装器。

射线只把当前封装器明确登记的物理体解释为门、两槽、开关或按钮。非本机物体仍然阻挡；不扩大为任意穿透。关闭的舱门阻挡胶囊取放，完全打开时胶囊槽能被命中。已放入物品的普通拾取组件停用，由槽位托管；处理物品碰撞层，避免物品自身抢占槽位射线。

胶囊架陈列物改用纯显示实例或关闭其独立取物及检测碰撞，保留架子整体阻挡和供给碰撞。验收时同时点击架体和陈列物可见范围，核对射线实际归属，避免陈列物挡住架子入口。

### 5.2 取放事务

沿用[库存现有机器转移流程](D:/autolysis/main-autolysis/player/components/autolysis_inventory_controller.gd:372)：取得库存和目标槽锁，准备候选显示或世界节点，复查当前选中格、同一道具实例、槽占用、聚焦会话和许可，再提交，成功后移除来源并发布通知。失败只撤销本次候选，来源和目标保持原样。

液体罐增加封装器存储归属，覆盖存储准备、普通拾取禁用、所属槽验证和释放；不能复用要求空罐的配药器准备入口。胶囊同样保存明确机器槽归属。候选节点入树前绑定原道具实例；同一物品转移时保留实例身份和全部内容。

仅成功提交取物才触发选择重置；许可查询、拒绝点击、候选模型失败及回滚均不能提前重置。点击入队后若切换了道具格、实例或聚焦会话，拒绝旧请求，沿用[当前点击快照复查](D:/autolysis/main-autolysis/player/components/autolysis_interaction_controller.gd:302)。

## 六 状态许可与完成后的取物顺序

### 6.1 状态划分

设备保存加工阶段、唯一选中类型及本轮完成胶囊的实例身份。舱门、开关动画和取放锁分别保存自己的运动或事务状态；物品空满状态从逐件数据读取。不能以“液体罐槽为空”作为所有阶段通用的复位条件。

| 阶段 | 输入与选择 | 允许的主要操作 |
| --- | --- | --- |
| 待装入 | 没有合法满罐与空胶囊组合；无本轮待取产物 | 可操作门及按种类取放；不能选择类型或启动。 |
| 可选择 | 有合法满罐与空胶囊，无选中类型 | 可取放、开关门、选择类型；不能启动。 |
| 已选择 | 上述组合仍在，唯一类型已选中 | 可切换或取消类型、取放、开关门；启动还要求门静止、开关动作完成、没有取放事务。 |
| 封装中 | 批次已锁定，计时未完成 | 全部机器入口拒绝；右键退出保持有效。 |
| 完成待取胶囊 | 本轮封装胶囊仍在槽内；罐可以留在或被取走、替换 | 门及取放恢复；保持本轮选择，类型开关与启动禁用。 |
| 产物已取走 | 本轮胶囊成功取回，解除完成记录 | 重置选择与灯；按当前物品重新判断待装入或可选择。 |

门完全打开或完全关闭都不影响合法满罐与空胶囊组合成立；门运动只额外禁止启动，并阻止胶囊取放。门操作本身不清除已选类型。技术方案：开关动画进行时拒绝新的开关点击和启动，仍允许取物；若此时取物使准备条件失效，从当前动画位置反向归位，旧完成回调不得恢复选择。

### 6.2 完成保留与重置矩阵

| 操作顺序 | 开关与加工结果 |
| --- | --- |
| 启动前取满罐或空胶囊 | 成功取物后立即清除选择，开启中的或已开启的开关反向归位，灯恢复原材质。 |
| 完成后先取空罐 | 选择和亮灯保持；胶囊仍是本轮封装结果，不能再次启动。 |
| 上一行之后补入另一满罐 | 选择继续保持；因槽内是封装胶囊，不能改类型或再次启动。 |
| 完成后取出本轮胶囊 | 无论罐是否还在，成功取物后清除完成记录并重置开关及灯。 |
| 先取胶囊，空罐仍在，再放空胶囊 | 选择保持关闭；空罐不满足加工条件，换入满罐后才允许新选择。 |
| 先取空罐，再取胶囊，再装两件合法输入 | 先保留、后重置；两件装好后重新选择并开始下一轮。 |
| 从库存放回已封装胶囊 | 完整保留该胶囊数据，可再取回；不恢复机器此前类型，不建立新的本轮完成记录，也不允许二次封装。 |
| 取回产物失败 | 保持产物占用、完成记录和选择；不进入下一轮。 |

## 七 开关与门的动画实现

参考[配药器独立动画播放器装配](D:/autolysis/main-autolysis/scenes/prefabs/prefab_machines/scripts/autolysis_blend_machine.gd:43)，保留现有动画资产，分别给门、三个开关和按钮配置独立 AnimationPlayer（动画播放器），使用相同的整机轨道根节点及物理帧回调。原场景播放器作为动画资产来源停用，避免同时写入同一属性。

独立播放器允许旧开关反播、新开关正播互不覆盖。初始化每个控制件到自身首帧；开关正播完成保持末帧，反播完成保持首帧。互斥选择与亮灯在同一业务提交中更新，任何时刻最多一个类型被选中、一个灯处于发光材质。复位不改变舱门位置。

逐灯保存初始化时的原覆盖材质，关闭时分别恢复。不能统一恢复灰色，因为零号灯的实际原材质不同。开启、关闭回调必须匹配本次动作及设备阶段；取消、重置、退出聚焦后到达的旧回调不能重新选中类型。

舱门完全关闭时点击正播打开，完全打开时再次点击反播关闭；开门中、关门中拒绝重复门点击。退出聚焦不撤销已经接受的门或开关动作，重新聚焦时显示设备实际状态。

动画反播与位置更新依据[官方动画播放器方法](https://docs.godotengine.org/en/4.6/classes/class_animationplayer.html#class-animationplayer-method-play-backwards)。中途复位从实际播放位置返回，不先跳到打开末帧。两秒计时从合法按钮点击被接受时开始，现有0.12秒按钮动作同时播放，不把动作时长额外加到封装时长。

## 八 2秒批次与两件物品同步提交

1. 实际点击时重新核对稳定聚焦、合法满罐与空胶囊、唯一类型、静止舱门、开关动作完成及无取放事务。
2. 先设置运行锁，再记录批次标识、两个世界节点及道具实例身份、完整源内容副本和类型。源罐仍有液体，胶囊仍为空。
3. 设备自己的单次 Timer（计时器）运行2秒，参考[配药器计时配置](D:/autolysis/main-autolysis/scenes/prefabs/prefab_machines/scripts/autolysis_blend_machine.gd:95)。拟沿用物理帧、游戏时间及场景树暂停时停止计时；右键退出聚焦不暂停设备。计时精度受物理帧采样影响，见[官方计时器说明](https://docs.godotengine.org/en/4.6/classes/class_timer.html)。
4. 完成前预检：仍是同一有效批次和两件实例、槽位归属正确、罐源内容未被外部改变、胶囊仍为空、封装结果合法。源内容按原药顺序、相位三项、波形五项与启动快照逐项比较，不能只比较资源引用。提前调用完成或重复回调不允许提交。
5. 先完整准备产物资源和可用显示更新，在无外部通知的同步提交段写入胶囊封装内容、清空同一罐的液体内容、记录本轮产物身份。两个修改必须共同成功；若任一修改可能失败，保留旧值并执行成对恢复，禁止只清空罐或只写胶囊。
6. 两件业务状态都提交后再更新外观、发实例及设备完成通知，释放运行锁。通知观察者只能读取完整的“空罐＋封装胶囊”。参考[配药器静默提交顺序](D:/autolysis/main-autolysis/scenes/prefabs/prefab_machines/scripts/autolysis_blend_machine.gd:216)。
7. 进入完成待取胶囊阶段，保留所选开关。产物成功取走后才清除完成记录并归位。

配置缺失、来源失效或预检失败时不消耗源内容，不伪造成功结果；记录明确失败原因并阻止重复提交。设备释放时停止计时、使旧批次失效；不访问已释放节点。本期不把未定义的场景卸载恢复行为写成存档功能。

自定义资源在两件状态一致后发布变化，参考[官方资源变化通知](https://docs.godotengine.org/en/4.6/classes/class_resource.html#class-resource-method-emit-changed)。完整复制优先使用项目已验证的显式复制方法，不假定任意资源复制调用都会复制所有运行字段。

## 九 胶囊架与废液罐接入

胶囊架借鉴[原药组无限取用入口](D:/autolysis/main-autolysis/systems/item-system/autolysis_raw_material_group.gd:16)，创建新的空胶囊实例，再调用库存接收流程。只在实际成功接收后通知；候选手持模型或库存许可失败时无物品产生，不修改展示胶囊。

废液罐继续要求现有罐盖完全打开、罐体处置入口有效、玩家和库存可操作，见[废液罐行为](D:/autolysis/main-autolysis/scenes/prefabs/prefab_machines/scripts/autolysis_waste_liquid_storage_tank.gd:98)。新增胶囊种类许可后，空胶囊和封装胶囊都从当前道具格整件移除，清除手持显示和临时面板；不留下可重复取用的空壳，也不生成世界掉落物。

原药整件丢弃、满液体罐倒空后仍持有空罐、空液体罐不能倒空的既有行为保持，胶囊根据种类进入自己的销毁分支。

原项目参照已核对：InventoryItemPD（上游库存道具定义）保存共享道具资料，InventorySlotPD（上游库存格数据）保存逐格状态；库存成功接收后世界拾取物才删除。见[上游共享定义](D:/cogito/addons/cogito/InventoryPD/CustomResources/InventoryItemPD.gd:1)、[上游格数据](D:/cogito/addons/cogito/InventoryPD/CustomResources/InventorySlotPD.gd:8)、[上游接收提交](D:/cogito/addons/cogito/InventoryPD/cogito_inventory.gd:237)、[上游拾取提交](D:/cogito/addons/cogito/InventoryPD/cogito_pickup.gd:9)。本项目沿用已经实现的独立四格库存，参照资源职责和提交通知顺序。

# 液体罐内容与配药器装填实现计划

编制日期：2026年10月2日。状态：已按本计划完成实施与自动验收。本文保留计划编制时的设计和基线索引；实际接口、修改、命令、结果及边界见[实施记录](D:/autolysis/docs/project-autolysis/00-discuss/道具系统/液体罐内容与配药器装填实施记录.md)。

本计划实现空罐进入配药器、原药混合、2秒装填、满罐取回及手持内容显示。实施依据为当前工作区实际代码、场景、用户需求及下文官方资料。已有液体罐与专用柜功能继续使用；本计划补充逐罐内容数据，覆盖原有取放链路。

## 一 已确认需求与范围

### 1.1 液体罐与内容物

液体罐具有“空罐”和“有液体”两种状态。内容物最多记录四条原药标识，允许重复，不因显示合并而删除重复记录。配药器最多同时容纳四份原药，至少需要一份。

| 内容 | 数据要求 | 未重构默认值 |
| --- | --- | --- |
| 原药 | 最多四条 String（字符串）标识；配药结果为一至四条，允许相同标识重复 | 空罐无内容物 |
| 相位重构 | Vector3（三维向量），游戏中按 r（红）、g（绿）、b（蓝）命名 | （0，0，0） |
| 波形重构 | 四个 bool（布尔值）与一个 int（整数）；第五项取值0至6 | （0，0，0，0，0） |

波形显示将前四项转换为数字0或1，例如（1，0，1，1，4）。本期只提供相位、波形的数据存储、读写及校验接口，配药完成后两项均为默认值。相位取值范围尚未定义，本期不自行限定为0至1，也不实现重构仪操作或重构算法。

现有两种原药的实际资源标识为 caffeine（咖啡因标识）和 sodium_benzoate（苯甲酸钠标识）。对应[咖啡因定义](D:/autolysis/main-autolysis/systems/item-system/items/caffeine.tres:9)、[苯甲酸钠定义](D:/autolysis/main-autolysis/systems/item-system/items/sodium_benzoate.tres:9)及用户指定的[咖啡因场景](D:/autolysis/main-autolysis/scenes/prefabs/prefab_raw_materials/rm_caffeine_0.tscn)、[苯甲酸钠场景](D:/autolysis/main-autolysis/scenes/prefabs/prefab_raw_materials/rm_sodium_benzoate_0.tscn)。内容保存原药标识，界面通过对应定义取得中文名称。

### 1.2 液体罐取放

操作位置为 machine_blend_0（零号配药器）的 liquid_tank_place_0（零号液体罐放置体）；命中 collision_liquid_tank_slot_0（零号液体罐槽位碰撞）后，通过其所属物理体执行取放。放入的罐对齐 liquid_tank_slot（液体罐锚点）。

只有稳定聚焦当前配药器时允许取放。手持空罐且罐位为空时允许放入；空手且罐位有罐时允许取走空罐或满罐。手持满罐、原药或其他道具时不允许放入；罐位已占用时不交换或覆盖。空手沿用当前项目定义：当前选中道具格为空，其他格中有道具不改变空手状态。

### 1.3 配药与拉杆

配药启动必须同时满足：设备配置有效且未运行、罐位有空罐、一至四槽有原药、四个槽门全部完全关闭。空槽的门同样必须关闭；开启中和关闭中均不满足条件。

正常拉杆到达现有最低点时启动配药。启动时记录原药快照，运行2秒后消耗本轮原药、清空对应槽位并向该罐写入内容。装填完成使用材质替换表现。满罐留在配药器中时，再放入原药仍不能启动下一轮。

设备配置有效且空闲，但空罐、原药或关门条件不足时，拉杆可进行受限拖动：最低局部位置为（0，0.08，0），鼠标位移比例为正常比例的一半，松手返回顶部。每次实际开始受限拖动时发送一次“禁止拉动拉杆”消息，供后续音效和提示灯接入。

运行期间全部配药器交互入口均拒绝操作，运行期间点击或拖动拉杆不发送禁止消息。允许玩家退出聚焦，配药器继续运行并完成装填。

### 1.4 用户确认记录

| 问题 | 已确认规则 |
| --- | --- |
| 原药消耗时机 | 启动时记录，2秒完成后消耗并清空槽位。 |

## 三 逐罐数据设计

以下名称和接口属于拟议技术方案，尚未存在于实际代码中。

### 3.1 共享定义与道具实例

保留 AutolysisItemDefinition（共享道具定义），继续保存图标、中文名称、世界场景及手持姿态。拟新增 AutolysisItemInstance（道具实例）资源，包含 definition（共享定义引用）与可空的 liquid_contents（液体内容）。原药实例仅需要共享定义引用；每个液体罐拥有独立道具实例。

空罐的 liquid_contents（液体内容）为空引用；满罐对应独立的 AutolysisLiquidContents（液体内容资源）。空罐读取重构信息时返回两组零值。罐状态由是否存在合法内容推导，避免另存状态标志造成空满状态与内容不一致。

每个新增罐独立创建道具实例，仅满罐持有独立内容资源。转移同一罐时传递原实例，不通过重新加载共享定义生成一份默认空罐。此选择依据当前共享定义库存结构，以及 [Resource（资源）官方说明](https://docs.godotengine.org/en/4.6/classes/class_resource.html#description)中的资源引用和路径缓存规则。

### 3.2 液体内容字段与接口

| 拟议字段 | 类型 | 约束 |
| --- | --- | --- |
| raw_material_ids（原药标识数组） | Array[String]（字符串类型数组） | 满罐一至四条；每条非空，能够解析为合法原药定义；顺序与重复条目完整保留。 |
| phase_rgb（相位红绿蓝向量） | Vector3（三维向量） | 默认全零；分量仅验证为有限数值；对外对应 r（红）、g（绿）、b（蓝）。 |
| wave_flag_0（波形零号布尔坐标）至 wave_flag_3（波形三号布尔坐标） | 四个 bool（布尔值） | 默认均为假；显示时逐项转换为0或1。 |
| wave_level（波形第五坐标） | int（整数） | 默认0，合法范围0至6；非法写入拒绝，保留旧数据。 |

相位采用 x（向量第一分量）对应 r（红）、y（向量第二分量）对应 g（绿）、z（向量第三分量）对应 b（蓝）；界面保留 r（红）、g（绿）、b（蓝）名称。波形采用明确字段，避免用含糊的通用数组表示五种混合类型。

拟提供内容校验、完整读取、相位写入、波形写入及内容变化通知。创建配药结果时一次提交原药和两组默认重构值。外部读取原药数组返回副本，禁止通过读接口改变内部顺序或数量。自定义资源变化需要显式发送 changed（变化信号），依据 [Resource（资源）变化信号说明](https://docs.godotengine.org/en/4.6/classes/class_resource.html#class-resource-signal-changed)。字段和数组声明遵循 [GDScript（引擎脚本语言）类型数组规范](https://docs.godotengine.org/en/4.6/tutorials/scripting/gdscript/gdscript_basics.html#typed-arrays)。

### 3.3 库存兼容与完整转移

库存内部四格改为保存道具实例。现有 get_slot_item（读取槽位定义）和 get_focused_item（读取选中定义）继续返回共享定义，保持道具栏图标、分类查询与既有调用兼容。新增 get_slot_instance（读取槽位实例）和 get_focused_instance（读取选中实例），供罐状态、取放事务与内容界面读取。

必须覆盖以下链路：独立世界罐到道具栏、柜内罐到道具栏、道具栏到专用柜、道具栏到配药器、配药器到道具栏、切换道具格重建手持显示、世界与柜中初始罐初始化。原药接收、药架取放、配药槽取放也同步适配实例存储，继续保持每格一件和现有定义读取接口。

所有转移沿用“准备候选外观或世界节点、校验来源与目标、提交、成功后移除来源、通知”的现有结构。候选节点在提交前绑定原实例。失败只销毁候选，原罐、原内容和库存占用保持不变。事务与延迟点击核验实例身份，避免两个同定义罐被当成同一来源；依据[现有点击快照](D:/autolysis/main-autolysis/player/components/autolysis_interaction_controller.gd:232)及[罐世界节点准备](D:/autolysis/main-autolysis/player/components/autolysis_inventory_controller.gd:403)。

## 四 配药器液体罐聚焦取放

拟新增 AutolysisBlendTankPlace（配药器液体罐放置位）脚本，挂在现有液体罐放置物理体上。负责单罐占用、锚点归属、空罐接收、空手取回、取放事务与设备运行门禁；配药器统一注入设备、聚焦目标和库存依赖。

在放置物理体直接子级添加唯一交互组件，沿用当前聚焦内部对象碰撞层。现有碰撞形状继续用于命中判定，锚点继续用于对齐，初始罐位为空。初始化校验物理体、碰撞、锚点、单接收者及占用记录；配置失败关闭入口并保留场景来源。

| 稳定聚焦当前设备 | 设备运行 | 当前手持 | 罐位 | 结果 |
| --- | --- | --- | --- | --- |
| 否 | 任意 | 任意 | 任意 | 拒绝取放。 |
| 是 | 是 | 任意 | 任意 | 拒绝取放，不改库存或罐位。 |
| 是 | 否 | 空罐 | 空 | 转移该空罐并对齐锚点。 |
| 是 | 否 | 空手 | 有空罐或满罐 | 取回到当前选中空格，完整保留实例和内容。 |
| 是 | 否 | 满罐或其他道具 | 任意 | 拒绝放入。 |
| 是 | 否 | 任意手持道具 | 已占用 | 拒绝交换或覆盖。 |
| 是 | 否 | 空手 | 空 | 不产生效果。 |

聚焦目标新增放置位登记、存活校验和所属设备校验；聚焦射线新增该放置位的首命中解析。已放入罐的自身拾取入口由放置位托管，关闭其普通世界拾取入口；罐的可检测碰撞需避免抢占放置位首命中，并保持必要玩家阻挡。实施时通过真实射线确认空位、空罐及满罐均命中指定取放入口，不扩大已有槽位二次查询的穿透规则。

专用柜的两槽取放继续接受液体罐，保存和恢复对应实例。其他机器中既有固定装配罐继续保留固定标记及其取走限制，参见[液体罐固定装配处理](D:/autolysis/main-autolysis/systems/item-system/autolysis_liquid_tank.gd)。

## 五 启动判定与拉杆反馈

### 5.1 两种许可

“能否开始拉杆拖动”与“能否启动配药”分别判断。设备空闲、稳定聚焦、拉杆可接受新操作时允许尝试拖动；此时依据加工条件选择正常拖动或受限拖动。运行期间两种拖动均不允许开始。

加工条件统一由配药器提供只读查询：合法空罐、一至四份合法原药、全部槽门完全关闭、无取放事务、设备未运行且配置有效。受限拖动的原因可包含缺罐、满罐、无原药及槽门未完全关闭。统一结果供拉杆和设备启动入口使用，实际启动前再次核验，不以视觉提示代替执行许可。

### 5.2 正常与受限参数

| 参数 | 正常拖动 | 受限拖动 |
| --- | --- | --- |
| 顶部局部位置 | （0，0.12，0） | （0，0.12，0） |
| 最低局部位置 | （0，−0.12，0） | （0，0.08，0） |
| 最大纵向行程 | 0.24 | 0.04 |
| 鼠标位移比例 | 当前配置，现值约0.001 | 当前正常配置的一半，现值约0.0005 |
| 到达下限 | 发送一次正常完成信号，进入既有保持与返回 | 保持在受限下限；松手后返回，不发送正常完成信号 |
| 提前松手 | 沿用既有自动返回 | 沿用既有自动返回 |
| 禁止消息 | 无 | 每次实际开始受限拖动时一次 |

位移继续采用“当前纵坐标减去鼠标纵向位移乘本轮比例，再限制到本轮上下限”的现有换算。受限行程为0.12−0.08＝0.04；在当前配置下，从顶部到受限下限对应累计有效向下鼠标位移80单位。比例在运行时由正常配置除以2计算，不另设容易失配的硬编码值。

拟沿用现有返回速度1.2局部单位／秒，受限满行程返回的理论时长为0.04÷1.2≈0.03333秒；实际画面按物理帧采样。该返回速度属于保留既有行为的技术选择，用户要求为松手返回。参数算术见[数值与显示规则核验](D:/autolysis/docs/project-autolysis/00-discuss/道具系统/液体罐内容与配药器装填计划证据/规则核验记录.txt)，该记录不代表引擎运行验收。

### 5.3 消息与输入边界

拟增加 handle_pull_denied（禁止拉动拉杆信号），携带操作角色与禁止原因。每次受限拖动开始只发一次；持续移动、停在下限、松手、回弹、悬停查询均不重复发送。后续音效与提示灯订阅该信号，本期不实现音效或灯状态。

正常拖动完成继续使用 interaction_completed（交互完成信号）启动设备。受限下限不触发此信号。若正常拖动期间加工前提失效，取消本次正常拖动并返回，禁止完成和启动；下一次新按下重新选择拖动模式。保留现有事件顺序、指针边缘循环、窗口失焦取消与右键退出处理。

## 六 2秒运行与原药消费

### 6.1 运行顺序

1. 接到正常拉杆完成信号，重新校验空罐、原药、全部门关闭及设备空闲状态。
2. 先进入运行状态并关闭交互，防止同步回调重入或同帧再次启动。
3. 按槽号0至3记录本轮原药节点、标识及目标罐实例；跳过空槽，保留重复标识。原药仍在槽中，罐仍为空。
4. 配药器自身计时2秒。拟使用 Timer（计时器）节点单次计时，显式配置为可暂停处理模式并采用游戏时间；场景树暂停时暂停，仅退出聚焦不停止计时。设置与帧采样依据[官方计时器说明](https://docs.godotengine.org/en/4.6/classes/class_timer.html)。
5. 计时结束，先完整校验本轮槽内来源、目标罐、内容资源及显示依赖仍有效，再同步提交原药消费与罐装填。全部来源通过核验后才开始修改，提交期间保持运行锁，不在中间发送外部通知。
6. 清除本轮原药的槽位归属、关闭来源交互与显示并释放来源节点；空槽保持为空，四门保持关闭。罐写入一至四条原药和零值重构数据，切换为满罐材质。
7. 完整提交后恢复设备交互入口并发送一次完成通知。此时允许开槽门、放入新原药及空手取罐；满罐占位仍使拉杆进入受限模式。

运行结束的内部提交只核验当前批次与设备来源，不要求启动玩家仍处于聚焦状态；允许退出后的完成流程与玩家交互取放许可分开。

拉杆自身的0.1秒保持和0.2秒返回可以在配药运行中继续推进。运行锁关闭新交互请求，保留拉杆自动返回处理，不关闭整台设备的计时或必要处理。

### 6.2 原药消费接口

槽位拟新增完全关闭查询、加工来源核验及加工消费入口。消费入口仅接受所属配药器的当前运行批次，核验快照中原药仍是本槽记录的实例且归属正确。普通开门取放事务保持原契约；加工消费入口负责运行完成后的关门消耗。

校验阶段只读取；全体通过后，同步清除归属和节点。出现配置失效、来源被外部移除或目标罐失效时，停止本轮完成提交，记录实际故障并保持设备交互关闭；不生成替代罐、不补造原药、不提交部分配方。故障处置属于防止无效提交的技术方案，需通过故障用例验证。

### 6.3 运行交互锁与聚焦退出

运行锁覆盖四个槽门入口、四个原药取放入口、液体罐取放入口、拉杆入口及设备根的聚焦进入入口。组件许可和公开业务接口均检查设备运行状态。恢复时根据配置、拉杆自动阶段及各入口原有条件重新计算许可，避免无条件开启全部入口。

现有聚焦会话可继续观察，也可退出；退出不会取消批次。运行中不接受新的设备聚焦进入请求，完成后恢复进入许可。运行锁不使已存在聚焦目标变为无效，不主动踢出当前聚焦会话。此处将根进入入口纳入“全部设备交互”的实现范围。

运行期间任何拉杆点击均不建立拖动、不改变位置、不发送禁止信号。完成时外部通知只发送一次，过期计时回调不能再次装填或重复消费。设备释放时停止计时并使当前批次失效；场景卸载后的长期恢复不属于本期范围。

## 七 材质表现与手持内容界面

### 7.1 空罐与满罐材质

使用现有 liquid_tank_liquid（液体罐内容网格）作为材质切换对象，玻璃与罐体网格保持原结构。拟配置空罐材质与满罐材质两份引用；空罐材质表现为无内容，满罐材质表现为有药液。具体颜色和透明度属于实施时的视觉配置，当前未指定最终颜色，也不依据原药或重构值生成颜色。

世界罐、配药器中的罐、柜中罐及手持罐均读取同一实例状态设置对应网格材质。使用 material_override（实例材质覆盖）替换引用，避免直接改变共享材质属性而使其他罐同步变满，依据[官方实例材质覆盖说明](https://docs.godotengine.org/en/4.6/classes/class_geometryinstance3d.html#class-geometryinstance3d-property-material-override)。

纯显示场景继续不附带脚本或碰撞。手持展示器在候选模型提交前按实例状态设置材质；内容变化后刷新当前模型。新增视觉参数须在正式场景实际画面中核验，包括玻璃遮挡、空满辨识及两罐互不污染。

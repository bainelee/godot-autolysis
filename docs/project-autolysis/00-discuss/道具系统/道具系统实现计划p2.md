# 道具系统第二部分实现计划：架子整体碰撞盒与碰撞分层

编制日期：2026年9月25日。

状态：已于2026年9月25日按本计划完成实现及必要验证，见[第二部分实施记录](/D:/autolysis/docs/project-autolysis/00-discuss/道具系统/道具系统p2实施记录.md)。下文保留实施前设计与依据；其中“当前”“计划”“尚未提供”等表述描述编制时基线，最终代码、执行调整和验收结果以实施记录为准。

需求依据：[第二部分讨论](/D:/autolysis/docs/project-autolysis/00-discuss/道具系统/道具系统讨论p2.md:71)。既有行为依据：[第一部分实施记录](/D:/autolysis/docs/project-autolysis/00-discuss/道具系统/道具系统p1实施记录.md)。

## 一、实施目标与范围

恢复原药放置架及仓库货架的整体物理碰撞盒，通过 layer（碰撞层）分类和交互射线掩码配置解决架体遮住药品的问题。玩家身体仍被架子阻挡，架体模型外观不额外决定射线遮挡。

| 已确认需求 | 第二部分实现结果 |
| --- | --- |
| 整体盒可穿透时不区分模型正反面 | 空手射线忽略整体架体盒；从正面、背面或视觉层板方向都按实际射线路径检测药品。 |
| 手持原药时放置架不可穿透 | 射线纳入原药架类别，命中架体后检查原有放置许可；允许则放入编号最小的空槽位。 |
| 空手时穿过放置架取药 | 射线排除原药架类别，只拾取实际命中的一件药品，写入当前选中空格。 |
| 需要隔板时另加不可穿透碰撞 | 独立遮挡对象参与两种状态的查询；模型层板本身不自动增加碰撞。 |
| 本部分不实现聚焦交互 | 不增加聚焦状态、相机、按钮归属或聚焦专用层。 |

保留2单位交互距离、中心射线首命中、四格物品栏、每格一件、原药组无限供给、两种原药混放、每架36槽和失败时不转移道具的行为。不增加自动拾取未瞄准物品、穿过不可用目标寻找后方物品、丢弃功能或新的交互反馈。

原药放置架与仓库货架分别配置：仓库货架当前没有放置业务，不因手持原药而变成放置目标。其他家具、机器及瓶子放置架不在本次整体盒迁移清单中。

## 三、碰撞层与掩码安排

### 3.1 层号分配

保留现有前三层含义和对象归属，在工程设置中补充中文名称，并新增两个明确职责的类别。第1层当前包含普通实体和部分可交互原药，不能直接改名为“纯遮挡”并假定其中没有交互目标。

| 层号 | 位值 | 计划名称 | 使用规则 |
| --- | --- | --- | --- |
| 1 | 1 | 常规实体 | 保留现有墙、地面、普通物理目标等；交互射线始终检测。 |
| 2 | 2 | 既有交互检测 | 保留现有使用，不批量重分配门、开关或原药。 |
| 3 | 4 | 玩家探测体 | 保留现有玩家探测体配置，本次交互查询不纳入。 |
| 4 | 8 | 交互可穿透实体 | 整体架体用于阻挡玩家和物理查询；交互射线不检测此层。 |
| 5 | 16 | 原药架放置入口 | 只供原药放置架使用；交互射线仅在手持原药时检测。 |

第4层的“可穿透”仅指交互射线，不表示玩家身体、蹲伏或地面查询可以穿过。

### 3.2 对象与查询配置

| 对象或查询 | 当前值 | 实施值 | 说明 |
| --- | --- | --- | --- |
| 原药放置架的 collision_layer（碰撞层） | 场景未显式设置，沿用默认第1层 | 24，即第4、5层 | 同一个整体盒承担物理阻挡和放置入口；移出第1、2层。 |
| 仓库货架的 collision_layer（碰撞层） | 场景未显式设置，沿用默认第1层 | 8，即第4层 | 两种手持状态的交互查询均可穿过，无放置入口。 |
| 空手交互射线的 collision_mask（碰撞掩码） | 3 | 3，即第1、2层 | 忽略两类架体，继续检测药品和墙体。 |
| 手持原药交互射线的 collision_mask（碰撞掩码） | 3 | 19，即第1、2、5层 | 增加原药架命中，保留普通目标和遮挡。 |
| 玩家根物理体的 collision_mask（碰撞掩码） | 场景未显式设置，默认1 | 9，即第1、4层 | 玩家移动仍撞到整体架体。 |
| 台阶射线的 collision_mask（碰撞掩码） | 场景未显式设置，默认1 | 9 | 保留物理实体检测。 |
| 蹲伏射线的 collision_mask（碰撞掩码） | 3 | 11，即第1、2、4层 | 起身检查不能漏过新层架体。 |
| 玩家脚步检测的 ground_collision_mask（地面碰撞掩码） | 脚本默认3 | 玩家场景显式设11 | 修改本项目玩家实例配置，保留脚步脚本的通用默认。 |
| 投放形状查询的 collision_mask（碰撞掩码） | 3 | 11 | 维护现有物理探测能力，不新增道具丢弃玩法。 |

原药架和仓库架自身的 collision_mask（碰撞掩码）不承担“被射线穿透”的切换职责，不因手持状态修改。玩家运动算法使用自身物理体进行运动测试，见[台阶运动查询](/D:/autolysis/main-autolysis/player/autolysis_player.gd:535)，因此根物理体掩码必须一并更新。

可复核的位运算：24与3按位与为0，24与19按位与为16，8与3或19按位与均为0，8与9或11按位与均为8。新增第4层后若架体仍留在第1层，空手查询就仍会被挡住，属于配置错误。

额外隔板使用独立的 StaticBody3D（三维静态物理体），放在第1层；可作为架子子节点随架移动，但不能只在第4、5层架体根下再添加一个碰撞形状就期待得到不同过滤结果。碰撞层属于物理对象，依据见[碰撞形状官方说明](https://docs.godotengine.org/en/4.6/classes/class_collisionshape3d.html)。正式场景本次恢复整体盒，不自动增加未要求的隔板；独立隔板在验证场景覆盖。

## 四、代码修改设计

### 4.1 目标查询模块

在 [InteractionRayCast（交互射线检测器）脚本](/D:/autolysis/main-autolysis/player/components/interaction_raycast.gd:11)中扩展 refresh_target（刷新目标）：增加 include_place_shelves（是否检测放置架）布尔参数，默认关闭，以兼容独立射线和现有无手持状态的调用。

每次调用依次完成：

1. 根据参数设置第5层检测位，保留第1、2层基础掩码，始终排除第4层。
2. 保留玩家自身和玩家探测体的现有射线例外；不得清空例外列表。
3. 调用 force_raycast_update（立即刷新射线），取得本次最近命中。
4. 继续执行现有节点存活、交互分组与目标变化通知逻辑；普通墙命中后返回无交互目标，不跳过墙继续查询。

层号常量及掩码组合集中在射线模块，不在每个架子或按钮脚本中重复实现。此处不创建全局碰撞管理器，也不引入多次射线、候选排序或运行时改变架体层号。

射线场景保留默认掩码3和2单位距离。将 hit_from_inside（从形状内部检测命中）设为开启，并保留自身例外，用于覆盖贴近架子时射线起点位于整体盒内部的情况；该属性能检测有体积形状内的起点，依据见[官方属性说明](https://docs.godotengine.org/en/4.6/classes/class_raycast3d.html#class-raycast3d-property-hit-from-inside)。新增内部起点用例及门墙回归，不把此设置视为已经通过实测。

### 4.2 交互控制模块与装配

在 [AutolysisInteractionController（自溶交互控制器）](/D:/autolysis/main-autolysis/player/components/autolysis_interaction_controller.gd:24)的 configure（配置）入口显式注入现有道具栏控制器，不让检测器寻找玩家节点或读取道具资源。

在 refresh_state（刷新状态）的共同路径中：

1. 先检查玩家、射线、输入许可回调和已注入道具栏依赖是否有效。
2. 通过 get_focused_item（读取当前选中格道具）取得最新手持定义。
3. 当定义存在且 is_raw_material（是否原药）为真时，要求射线检测原药架；其余状态使用基础掩码。
4. 取得目标后仍要求恰好一个直接子交互组件，并复用现有 can_interact（能否交互）和 try_interact（尝试交互）流程。

掩码选择仅取决于当前手持类别，不调用 can_place_on_shelf（能否放到架子）来决定是否穿透。否则满架会被错误排除，违背“不能放置时不执行”的规则。

空手以当前格为空为准。非原药手持使用基础掩码作为本计划工程默认；拾取仍由原有当前格占用检查拒绝，不新增其放置能力。这是对未扩展物品类型的保守处理，不记作用户已确认的新玩法。

在[玩家初始化](/D:/autolysis/main-autolysis/player/autolysis_player.gd:132)中先完成道具栏依赖配置，再配置交互控制器；继续使用 inventory_changed（道具栏状态已改变）触发统一刷新。初始化后主动刷新一次；点击前、交互提交后均从实际当前格重新读取，避免使用旧掩码。

交互结束后的刷新只更新目标及准星，不自动向新目标再次分发本次输入。例如放置后变为空手，可以立刻显示瓶体可取状态，但同一次按下不能又取回它。

### 4.3 继续复用的业务

[架子脚本](/D:/autolysis/main-autolysis/systems/item-system/autolysis_raw_material_shelf.gd:135)、[原药脚本](/D:/autolysis/main-autolysis/systems/item-system/autolysis_raw_material.gd)、[道具栏控制器](/D:/autolysis/main-autolysis/player/components/autolysis_inventory_controller.gd:112)保留原有槽位归属、最小空槽选择、资源检查和同步转移保护。第二部分通过检测规则选择架子或药品，不另写一套取放事务。

满架、无效资源和失效目标依旧不可操作；不能因为本次命中对象不满足业务条件，就忽略它寻找后方对象。正常门与开关继续走原有直接交互入口。

保留两个预制体的根节点、原主碰撞节点标识、模型、材质、原药架脚本、交互组件及36个槽位的名称和变换。主场景中上架高度1.3、下架高度0.72继续保留，不恢复到第一部分净空修正前的位置；见[主场景架子实例](/D:/autolysis/main-autolysis/scenes/01-autolysis-test.tscn:1306)。

编制时已按36个槽位位置及[咖啡因瓶碰撞尺寸](/D:/autolysis/main-autolysis/scenes/prefabs/prefab_raw_materials/rm_caffeine_0.tscn:8)、[苯甲酸钠瓶碰撞尺寸](/D:/autolysis/main-autolysis/scenes/prefabs/prefab_raw_materials/rm_sodium_benzoate_0.tscn:8)核对：瓶体保守联合范围约为下限（−0.57，0.03999999，−0.35000007）、上限（0.58，0.56，−0.08999997），位于原整体盒范围内。这是静态配置计算，不替代运行射线验证。

直接恢复原高度会使上架盒下界约为1.30000002、下架盒上界约为1.31999998，形成约0.02高的重叠带；同方向入口面可能等距，盒内起点也可能同时落在两架体内。碰撞层不提供这种等距情况下的架体优先级，因此本计划明确校正整体盒高度，而不是给查询增加任意排序。

采用高度0.57、中心高度0.285后，盒体局部高度范围为0至0.57；比药品联合最高点0.56高0.01。下架整体盒世界上界为1.29，上架整体盒世界下界为1.3，形成0.01间隙。当前架体模型上层板位于局部约0.34至0.38，亦处于新盒内。原来的重叠高度区间此时只属于上架，目标预期明确。

以上为基于实际尺寸制定的计划值。实施时用实际资源再次测量全部药品碰撞和架体模型范围，并验证间隙两侧、原重叠区及盒内起点的命中；间隙内水平射线不应凭空选取任何架体。如果验证暴露覆盖不足或其他相邻重叠，只校正有证据的空余盒体边界并保留数值记录，不移动主场景架子、模型或槽位，也不扩大交互距离。

## 七、实施顺序与阶段产物

1. **建立本部分基线。** 保存实施前工作区状态及本清单文件快照，核对新增层号未被占用。当前工作区已有未提交修改与未跟踪文件，禁止通过还原整个工作区完成迁移。
2. **隔离验证输出。** 为单项入口增加 EvidenceRoot（证据根目录）参数，并向有输出的测试传递 --evidence-dir（证据目录参数）。所有本部分调用必须显式使用“道具系统第二部分实施证据”下的本次执行子目录；实现前检查真实输出路径，不能只修改外层日志目录。现有旧入口默认行为可保留，但本部分不得覆盖第一部分记录。
3. **配置层与整体盒。** 按第三、五节修改工程名称、两个架体和玩家物理查询。完成后静态核对层归属、主碰撞节点、模型及槽位变换差异。
4. **接通手持状态查询。** 修改射线、控制器和玩家装配；对每次提示刷新与点击前检查使用同一状态读取流程，保持取放事务不变。
5. **调整并执行针对性验证。** 先完成导入与脚本加载，再运行道具业务、逐槽双状态射线、遮挡及物理层回归；发现错误后先定位，不带错继续堆叠测试。
6. **执行真实图形及主场景联调。** 用实际玩家、射线、鼠标点击和滚轮覆盖取放循环、重叠目标、状态刷新；另用启用物理处理的玩家验证撞架与蹲伏。保留真实命中对象、坐标、手持状态及截图。
7. **整理实施记录。** 写入变更清单、层表、各项通过或失败、保护项差异和最终证据入口。全部必要条件通过后再标记完成，不把旧通过数量当作新版本验收。

## 八、验证设计与验收矩阵

### 8.1 修正旧测试的具体位置

- [道具测试的射线辅助方法](/D:/autolysis/main-autolysis/systems/item-system/tests/item_system_test.gd:357)当前扫描全部层，恢复整体盒后会再次被架体挡住。改为明确接收本次查询掩码，分别记录空手和手持原药结果，并增加通过真实交互控制器的集成验证；不能给射线直接排除被测架子的例外来伪造通过。
- [逐槽测试](/D:/autolysis/main-autolysis/systems/item-system/tests/item_system_test.gd:369)保留两种原药各36槽的空手命中覆盖；同组位置增加手持原药命中架体的覆盖。每条记录包含状态、掩码、起点、命中对象与距离，区分单瓶逐槽和满架场景。
- [背面旧断言](/D:/autolysis/main-autolysis/systems/item-system/tests/item_system_test.gd:414)及[下方旧断言](/D:/autolysis/main-autolysis/systems/item-system/tests/item_system_test.gd:430)改为整体盒可穿透时命中药品；另行加入独立第1层背板、隔板阻挡用例。保留普通墙的正向遮挡验证。
- [组件迁移测试](/D:/autolysis/main-autolysis/player/tests/component_migration_test.gd:22)明确掩码3是空手默认，新增手持19与恢复3的检查；[投放断言](/D:/autolysis/main-autolysis/player/tests/component_migration_test.gd:27)更新为11并保留原距离与形状检查。
- [净空测试](/D:/autolysis/main-autolysis/systems/item-system/tests/shelf_clearance_test.gd:40)验证的是模型几何，保留上架与药瓶不交叠的要求，不把整体物理盒包住药瓶判为模型净空失败。
- [主场景图形测试](/D:/autolysis/main-autolysis/systems/item-system/tests/item_system_rendered_test.gd:221)目前关闭玩家物理处理后定点摆放。它可以验证输入与取放，不能单独证明玩家不会穿架；真实移动验证必须另行保留物理处理。

### 8.2 必须通过的行为

| 编号 | 条件与操作 | 预期及证据 |
| --- | --- | --- |
| 1 | 空手瞄准架内两种原药，各36槽 | 穿过架体命中对应瓶体；距离不超过2单位。 |
| 2 | 同一瞄准方向切换为手持原药 | 命中罩住内部药品的架体；允许放置时只新增一瓶至编号最小空槽。 |
| 3 | 手持原药瞄准满架，或放置资源无效 | 准星不可用，点击后原格与架子数量不变，不穿过架体拾取瓶体。 |
| 4 | 空手对准架体空白处、偏离瓶体或超出2单位 | 不取药，不补选旁边或后方未命中药品。 |
| 5 | 只有整体盒，从背面及视觉层板方向瞄准瓶体 | 空手查询可命中瓶体；模型外观不产生额外遮挡。 |
| 6 | 前方增加独立墙体或隔板 | 两种手持状态都先命中遮挡物，不越过它操作；移除后恢复。 |
| 7 | 连续切格、拾取、放置；当前格空但其他格有物品 | 检测与准星按当前格更新；一次点击只转移一件，后续刷新不重复执行。 |
| 8 | 前方药品不可用、移走或删除 | 不自动忽略不可用首命中找后方药品；实际移除碰撞后下一次查询按新物理结果更新。 |
| 9 | 两个原药架交替操作、满架与混放 | 槽位独立，守恒和回滚成立；不改动原有36槽及编号规则。 |
| 10 | 仓库架外空手瞄准两种原药组 | 穿过仓库整体盒可领取；手持时也不把仓库架变成放置目标。 |
| 11 | 正常移动撞向两类整体架体 | 玩家不能穿入；使用实际移动结果和接触记录，不只断言掩码数值。 |
| 12 | 新层实体用于头顶、台阶、脚下及投放探测 | 起身检查、运动检测、脚步命中、投放查询均能检测它；原地面配置继续有效。 |
| 13 | 射线起点位于放置架盒内，以及贴近门墙 | 手持时仍命中架体；空手仍可排除架体；自身例外与墙体遮挡正常。 |
| 14 | 普通门、开关、暂停及界面输入限制 | 原有直接交互和准星显示正确，禁用输入时不执行操作。 |
| 15 | 实际主场景上下架和仓库架 | 两种原药取放链成立；上下架整体盒无重叠，分别检测间隙上下两侧、原重叠区和单盒内部起点。原重叠区手持查询命中上架；间隙内水平射线不误选架体。原有模型净空和场景位置保持。 |
| 16 | 两个查询者以不同手持状态检测同一个架子 | 各自得到架体或药品，架体层值始终固定；不增加多人玩法，仅验证查询状态没有写入共享对象。 |
| 17 | 当前目标可用时，道具栏依赖排队释放或立即失效 | 提示清空，点击拒绝，不访问失效对象；不能把失效依赖当作正常空手。 |

| 显示状态 | 判定与进入时机 | 材质与动态行为 |
| --- | --- | --- |
| 默认或未就绪 | 无完成罐待取凭据且未运行时：初次加载；无罐；无原药；槽门打开或正在开闭；转移事务忙碌；启动条件不成立。 | 红色，停止闪烁。 |
| 就绪 | can_start_processing（可开始加工）返回真。 | 橙色常亮，发光能量倍率2.0。 |
| 运行 | try_start_processing（尝试开始加工）实际成功，机体已设置运行状态。 | 橙色，发光能量倍率在0至2.0之间线性往返。 |
| 完成待取 | 本机成功提交加工批次，当前罐位仍合法持有该批次完成的同一个满罐实例。 | 立即停止橙色闪烁，换为绿色常亮。 |
| 完成罐取走 | 罐位成功释放完成罐并结束转移事务。 | 清除完成凭据，恢复红色。后续再次满足完整启动条件时可重新变橙色。 |
| 加工失败 | 机体进入现有故障状态。 | 停止闪烁，恢复红色；沿用原有故障锁定。 |

正常显示优先级为：已确认故障、正在运行、完成罐待取、可启动、默认。非运行阶段配置失效时使用红色。完成态不受玩家退出聚焦、重新进入聚焦或打开空槽门影响，只要完成罐仍在原罐位就保持绿色。

绿灯保存成功批次罐的实例身份作为显示凭据，不另建加工成功业务状态。不能只用“罐非空”判定本机完成：[现有测试](D:/autolysis/main-autolysis/systems/item-system/tests/liquid_contents_blend_test.gd:170)会直接在罐位装填内容；该操作不是本机批次完成。绿灯凭据只在实际成功提交后建立，在取走、归属失效或故障时清除。

## 三 闪烁算法与资源隔离

用户要求每秒两次从0到2.0或从2.0到0的 lerp（线性插值）。每次单向插值时长为0.5秒，完整往返为1秒。就绪倍率为2.0，因此建议运行开始从2.0下降，避免切入运行时瞬间跳为零：

1. 从2.0线性降到0，持续0.5秒。
2. 从0线性升到2.0，持续0.5秒。
3. 循环以上两段，直到真实加工成功或失败。

参考采样如下。时间使用有效游戏时间，不包含暂停时长。

| 运行后秒数 | 预期橙色发光能量倍率 |
| --- | --- |
| 0 | 2.0 |
| 0.25 | 1.0 |
| 0.5 | 0.0 |
| 0.75 | 1.0 |
| 1.0 | 2.0 |
| 1.25 | 1.0 |
| 1.5 | 0.0 |
| 1.75 | 1.0 |

以上参考值已经计算并保存为[线性插值校核数据](D:/autolysis/docs/project-autolysis/00-discuss/交互系统/配药器状态指示灯计划证据/线性插值校核.json)。这属于计划数学校核，尚未执行引擎闪烁验收。加工仍由已有两秒计时器完成，不通过闪烁循环次数推断完成。

实现采用单个 Tween（补间动画），两个顺序 tween_property（属性补间），明确设置 Tween.TRANS_LINEAR（线性过渡），通过 set_loops（设置循环）持续往返。补间属性为 emission_energy_multiplier（发光能量倍率）。这些调用及属性有[补间动画官方依据](https://docs.godotengine.org/en/4.6/classes/class_tween.html)和[材质发光倍率官方依据](https://docs.godotengine.org/en/4.6/classes/class_basematerial3d.html#class-basematerial3d-property-emission-energy-multiplier)。

每台设备初始化时用 duplicate（复制资源）创建独立橙色材质；只修改这个副本的数值，纹理继续共享。红色和绿色资源只作为固定材质引用。切换显示通过 material_override（覆盖材质），覆盖整个指示灯网格。依据为[资源复制官方说明](https://docs.godotengine.org/en/4.6/classes/class_resource.html#class-resource-method-duplicate)和[覆盖材质官方说明](https://docs.godotengine.org/en/4.6/classes/class_geometryinstance3d.html#class-geometryinstance3d-property-material-override)。

补间绑定本机节点，设置与加工计时器一致的物理更新、暂停和时间缩放行为：暂停游戏时同时暂停，恢复后继续；退出聚焦不停止。离开运行态、故障、设备退出场景或指示灯失效时调用 kill（终止补间动画）并清除引用。再次加工创建新补间；重复刷新同一运行态不得重置相位或新增循环。相关生命周期依据为[补间绑定与终止说明](https://docs.godotengine.org/en/4.6/classes/class_tween.html#class-tween-method-bind-node)。

发光倍率为零仅表示自发光贡献为零，橙色基础表面仍可见。验收对象是指定材质属性及实际亮度变化，不要求网格在最低值时完全不可见。

初始化时校验指示灯引用和三份材质类型，完成现有设备配置后计算初始显示。显示依赖缺失应报告明确错误并关闭指示灯更新，不增改现有业务启动规则。

槽与罐位通知只安排一次合并的延后刷新，避免在库存转移中间或节点入树回调中读取半提交状态。已取走罐的变化监听必须断开；释放或移出场景后重新核验实际归属。门关闭完成和事务结束均必须触发刷新，否则最后一项条件达成时可能继续显示红色。

机体直接控制三个批次接点：

1. 实际成功启动并设置运行状态后，在发出 processing_started（加工开始）之前同步进入橙色闪烁。
2. 原药消费和罐内容写入期间保持运行显示，不在 consume_processing_item（消费加工原药）的静默提交段新增外部通知。内容变化通知期间现有运行锁仍有效。
3. 在 _clear_batch（清除批次）之前，将完成罐与原批次罐实例保存为局部引用。装填成功、机体仍存活且 _processing（加工中）设为假之后，核验罐位仍拥有同一合法满罐实例，建立完成凭据并切绿，再发出 processing_completed（加工完成）。失败时，在发出 processing_failed（加工失败）前停止闪烁并切红。

此顺序保持[现有原子提交测试](D:/autolysis/main-autolysis/systems/item-system/tests/machine_batch_atomic_test.gd:96)的契约：内容回调期间完整提交但仍锁定，完成回调时已解除运行状态。

## 六 实施与验收步骤

1. 重新核对工作区差异及证据散列，沿用现有指示灯，绑定机体显示引用和三个指定材质。
2. 增加槽门、槽事务、罐位事务的刷新通知，接入机体统一显示求值。
3. 接入实际加工开始、成功、失败与退出场景时的补间生命周期及完成罐凭据。
4. 扩展装填集成验收，再运行现有批次原子提交、槽位转移与拉杆行为回归。
5. 使用真实渲染采集红色、橙色就绪、橙色明暗变化、绿色完成、取罐后红色画面，保存实际命令、退出码与数值报告。

引擎采用用户指定的 Godot（戈多引擎）4.6.1版。自动验收沿用[现有检查包装器](D:/autolysis/main-autolysis/systems/item-system/tests/run_item_check.ps1:1)，将新证据输出到本功能独立目录。图形检查采用隐藏窗口；计划阶段不执行运行验收。

| 验收情形 | 通过标准 |
| --- | --- |
| 无原药、无罐；仅原药；仅空罐 | 均为红色。 |
| 一至四份合法原药与空罐，所有槽门完全关闭且事务结束 | 橙色常亮；无正在运行的闪烁补间。 |
| 就绪后开门，再关门 | 开门和关门动画期间红色，完全关闭后橙色。 |
| 移走最后一种原药或空罐 | 转移结束后红色；失败回滚则按实际最终状态恢复。 |
| 拉杆未成功完成或启动被拒绝 | 不产生运行闪烁。 |
| 正常成功启动 | 橙色副本按参考波形变化；单段约0.5秒，允许对应采样更新的一帧误差。 |
| 重复刷新运行状态 | 不创建第二个补间，不重置已有相位。 |
| 游戏暂停与恢复；退出聚焦 | 暂停时计时与倍率均冻结，恢复后继续；退出聚焦仍加工和闪烁。 |
| 本机真实加工成功 | 内容提交并解除运行状态后绿色，无残留橙色循环。 |
| 完成后再次开关空槽门或退出再进入聚焦 | 完成罐仍在时持续绿色。 |
| 成功取走完成罐 | 恢复红色，完成凭据和旧罐监听清除。 |
| 完成罐取回的候选准备失败 | 原罐仍在原罐位，保持绿色，不清除完成凭据。 |
| 外部直接填充罐或加工失败 | 不建立本机完成凭据；不显示绿色完成。 |
| 连续两批加工 | 每批仅一个新补间，完整重复红、橙、闪烁、绿、红过程。 |
| 两台设备同时存在 | 一台闪烁不改变另一台橙色材质倍率，原始资源保持2.0。 |
| 设备或当前罐被释放、移出场景 | 不访问失效节点；设备退出时无残留循环；实际罐归属失效时不保留绿色。 |
| 既有业务回归 | 原药消费、满罐内容、事务回滚、运行锁、拉杆受限行为及完成通知时序保持通过。 |

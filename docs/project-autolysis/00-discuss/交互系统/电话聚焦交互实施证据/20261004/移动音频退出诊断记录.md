# 移动专项音频退出诊断记录

执行日期：2026年10月4日。正式移动专项原先84条业务断言通过，但退出报告9个资源仍被使用。本子任务只增加专属诊断脚本与记录，不修改电话、库存、玩家或脚步音频生产代码，不修改根代理拥有的移动专项。最终定位为测试立即退出时，原生音频播放实例的异步引用释放尚未完成；结束条件应读取实际对象消失，不能把固定清理帧数或没有退出错误作为对象已释放的证明。

## 反馈信号与最小复现

[正式移动诊断基线](D:/autolysis/docs/project-autolysis/00-discuss/交互系统/电话聚焦交互实施证据/20261004/movement-diagnostic-baseline/movement-diagnostic-baseline.json)独立复现84条业务通过、退出码零但9资源残留。退出错误检查因此为失败。根代理此前的清理复核、关闭运行期输出和完整继承封装均保留，不能因业务断言通过将其计入最终验收。

[最小音频脚本](D:/autolysis/main-autolysis/player/tests/telephone_audio_cleanup_audit.gd:18)只创建原生 AudioStreamPlayer3D（三维音频播放器），加载正式石材脚步资源，播放45物理帧，排队释放测试节点并等待3帧；不加载主场景，不建立电话或库存会话。[最小音频基线](D:/autolysis/docs/project-autolysis/00-discuss/交互系统/电话聚焦交互实施证据/20261004/audio-resource-baseline/audio-resource-baseline.json)仍实际产生同样的9资源退出错误，证明电话、库存和主场景不是触发本问题的必要条件。[仅加载不播放对照](D:/autolysis/docs/project-autolysis/00-discuss/交互系统/电话聚焦交互实施证据/20261004/audio-resource-no-playback/audio-resource-no-playback.json)只删除播放动作，3帧后资源数从11降为2，播放实例和音频资源弱引用均失效，退出没有错误。

## 九个资源的实际身份与引擎机制

[资源身份复核](D:/autolysis/docs/project-autolysis/00-discuss/交互系统/电话聚焦交互实施证据/20261004/audio-resource-identities/最小音频退出复核.json)保存全部实际对象编号与来源：1个 AudioStreamRandomizer（随机音频资源）、4个 AudioStreamOggVorbis（压缩音频流）和4个 OggPacketSequence（音频数据包序列）。实际来源由[石材脚步资源配置](D:/autolysis/main-autolysis/systems/dynamic-footstep-system/footstep-profiles/stone_footstep_profile.tres:1)取得，数据包序列来自每个音频流的实际 packet_sequence（数据包序列）属性。该轮播放后资源总数11；实际72毫秒、12480处理帧后，最后音频资源和播放实例失效、资源数降到2，退出无错误。九个资源的对应关系由实际实例图与释放前后资源差值共同确认，不只依据数量猜测。

引擎官方4.6.1稳定版的[原生播放器实现](https://raw.githubusercontent.com/godotengine/godot/4.6.1-stable/scene/audio/audio_stream_player_internal.cpp)在删除通知中向音频服务器请求停止，再清本地播放列表。[音频服务器实现](https://raw.githubusercontent.com/godotengine/godot/4.6.1-stable/servers/audio/audio_server.cpp)的 stop_playback_stream（停止播放流）设置待淡出删除状态；混合处理删除列表项，随后主线程更新清理列表并取消播放实例引用。[随机音频实现](https://raw.githubusercontent.com/godotengine/godot/4.6.1-stable/servers/audio/audio_stream.cpp)的播放实例持有随机音频资源，随机资源又保留其四个音频流。以上解释了节点已删除而音频资源仍暂存的实际状态。

官方[无图形音频驱动实现](https://raw.githubusercontent.com/godotengine/godot/4.6.1-stable/servers/audio/audio_driver_dummy.cpp)以独立线程和实际延迟处理音频缓冲；固定模拟帧数不等于音频线程完成一次停止与主线程释放。根据该源码和弱引用实测，可推断本问题是测试退出发生在异步音频释放完成之前。详细日志改变后退出差异已记录，但未单独测定其具体时间影响，不把“日志延迟导致通过”写成已验证事实。

## 正式专项结束条件及保留范围

根代理根据有效证据修改其[正式移动专项](D:/autolysis/main-autolysis/player/tests/telephone_movement_test.gd:112)：在全部运动业务结束后停玩家物理处理，捕获实际音频播放实例的 WeakRef（弱引用），停止脚步和落地播放器，释放场景；以同步布尔助手读取弱引用，等待所有记录实例实际消失，最大实际2000毫秒只是失败上限。该处理只用于测试退出，不新增生产取放计时或业务许可阈值。[最终正式检查](D:/autolysis/docs/project-autolysis/00-discuss/交互系统/电话聚焦交互实施证据/20261004/movement-audio-cleanup-final/telephone-movement.json)85条通过、退出码零、非预期错误为空；其中新增一条明确验证退出前播放实例已释放。其整体来源、轨迹与最新整合结果由根代理实施记录引用。

[完整诊断脚本](D:/autolysis/main-autolysis/player/tests/telephone_movement_resource_audit.gd:1)与最小音频脚本保留为专属诊断入口，非默认正式验收项。两者只修改本次测试实例、读取缓存与弱引用，不修改正式音频资产或生产脚本。所有运行均含无图形参数，未启动图形测试窗口、未激活应用、未定位或注入系统指针。

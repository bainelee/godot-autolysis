# 聚焦交互与原药混合器讨论第一部分

记录日期：2026年9月26日。

状态：功能讨论。本文区分用户已确认规则、当前文件事实和待确认建议，不表示功能已经实现。

讨论对象：[原药混合器预制体](/D:/autolysis/main-autolysis/scenes/prefabs/prefab_machines/machine_blend_0.tscn)。本轮以用户已经修改的当前场景为准。

## 一、本轮范围

讨论聚焦模式的进入、退出、相机、输入，以及四个混合槽位的开闭和原药取放。

当前设备还包含 liquid_tank_slot_0（液罐槽位零）和 switch_handle_blend_mechine_can_reset（可复位混合器开关手柄），本轮不定义这两类对象的功能。节点标识沿用场景实际拼写。

本轮仅记录讨论文档及配套术语。未修改游戏代码、场景和输入配置，未执行引擎运行测试。

## 二、用户已确认的规则

### 2.1 进入与退出聚焦

| 项目 | 已确认规则 |
| --- | --- |
| 进入目标 | 根节点下的外部碰撞体代表整台设备的聚焦入口。 |
| 进入操作 | 普通交互射线命中该外部碰撞体后，点击鼠标左键进入聚焦。 |
| 相机过渡 | 角色摄像机用0.2秒移动至 focus_camera（聚焦相机）的目标位置，同时匹配其视野等相机数据。用户原始表述为 lerp（线性插值）过渡。 |
| 聚焦瞄准 | 相机固定，显示鼠标指针，交互射线跟随鼠标指针位置。 |
| 普通角色操作 | 聚焦期间，非聚焦模式中的角色移动操作无效；固定相机意味着鼠标移动用于指向设备内部对象。 |
| 道具切换 | 鼠标滚轮切换道具继续生效。 |
| 手持模型 | 聚焦期间继续显示，跟随聚焦后的角色相机。 |
| 退出操作 | 鼠标右键退出聚焦。 |
| 相机恢复 | 用0.2秒恢复进入前的位置、朝向和视野。 |
| 设备状态 | 退出不清空原药，不复位槽位开闭状态；再次进入时继续操作当前设备状态。 |

用户明确要求移动角色摄像机。设备中的参考相机提供目标位置与参数，不能未经确认改成直接切换设备相机。

### 2.2 槽位开闭

四个目标分别是 blend_slot_0（混合槽位零）、blend_slot_1（混合槽位一）、blend_slot_2（混合槽位二）、blend_slot_3（混合槽位三）。

- 进入聚焦后，射线命中对应槽位的开闭碰撞体，左键打开；再次交互关闭。
- 打开使用已经制作的对应动画；关闭倒放同一段动画，时长0.2秒。
- 四个槽位可以同时保持打开，不采用打开一个就自动关闭其他槽位的规则。
- 某槽位开闭动画尚未结束时，忽略对该槽位的重复点击；动画结束后再接受操作。其他槽位仍可操作，不因一个槽位播放动画而锁住整台设备。

### 2.3 原药取放

| 条件 | 命中目标与输入 | 结果 |
| --- | --- | --- |
| 槽位打开，玩家手持原药 | 左键交互该槽位的原药取放交互区 | 将原药放入该槽位，使用其原药放置锚点的位置。 |
| 槽位打开，槽内有原药，玩家空手 | 左键交互该槽位的原药取放交互区 | 从该槽位取出原药。 |

用户所述 collision_rm_place_slot（原药取放碰撞形状）和 rm_place_slot（原药放置锚点）在实际场景中均带有0至3的编号后缀。前者决定是否命中取放区域，后者决定原药摆放位置；两者位置不能混用。用户允许将放入的原药作为对应锚点的子节点。

空手沿用现有道具系统：当前选中的道具格为空即可，其他格有药不影响空手判定。取回进入当前选中的空格，不自动寻找其他空格，不切换选中格。依据为[既有规则](/D:/autolysis/docs/project-autolysis/00-discuss/道具系统/道具系统讨论p1.md:29)及[当前道具接收实现](/D:/autolysis/main-autolysis/player/components/autolysis_inventory_controller.gd:58)。

本次取放必须针对鼠标命中的具体混合槽位，不能套用原药放置架“自动寻找编号最小空位”的规则。取回指定命中对象是槽位的取放交互区，也不能自动套用放置架“直接命中药品本体”的规则。

射线获取的是碰撞对象，不能假定直接返回碰撞形状子节点。对现有结构而言，开闭目标与取放目标可以分别对应槽位物理体和锚点物理体；如需精确识别形状，还应取得命中形状索引。依据为[射线官方文档](https://docs.godotengine.org/en/4.6/classes/class_raycast3d.html#class-raycast3d-method-get-collider-shape)。这属于实现解释，不要求用户改名或重建现有结构。

### 3.2 动画

当前四段打开动画各长0.2秒，仅修改对应槽位的旋转。[槽位零动画](/D:/autolysis/main-autolysis/scenes/prefabs/prefab_machines/machine_blend_0.tscn:167)、[槽位一动画](/D:/autolysis/main-autolysis/scenes/prefabs/prefab_machines/machine_blend_0.tscn:183)、[槽位二动画](/D:/autolysis/main-autolysis/scenes/prefabs/prefab_machines/machine_blend_0.tscn:199)、[槽位三动画](/D:/autolysis/main-autolysis/scenes/prefabs/prefab_machines/machine_blend_0.tscn:215)均已实际读取。

场景只有一个 AnimationPlayer（动画播放器），其动画库包含四段打开动画和 RESET（重置动画），未见独立关闭动画。[动画库](/D:/autolysis/main-autolysis/scenes/prefabs/prefab_machines/machine_blend_0.tscn:231)及[播放器](/D:/autolysis/main-autolysis/scenes/prefabs/prefab_machines/machine_blend_0.tscn:650)为依据。

用户已经确认倒放关闭。引擎提供 play_backwards（倒放动画）方法，可以复用已有动画；具体调用仍需后续实现。[官方倒放说明](https://docs.godotengine.org/en/4.6/classes/class_animationplayer.html#class-animationplayer-method-play-backwards)。

RESET（重置动画）同时设置四个槽位的旋转，因此不能用它代替“只关闭当前槽位”。“四个槽位可同时保持打开”与“四段动画能同时播放”也是两个不同问题。用户进一步确认一个槽位运动时其他槽位仍可操作，因此后续必须支持不同槽位动作互不打断。当前单播放器的动画调度需要在实施时处理，不能将现有节点数量视作已满足并行动画的证明。

## 四、现有系统与参考项目的衔接分析

### 4.1 普通入口与聚焦内部操作需要不同的命中条件

当前[交互射线](/D:/autolysis/main-autolysis/player/components/interaction_raycast.gd:13)只接受首个碰撞并检查可交互分组；[射线配置](/D:/autolysis/main-autolysis/player/components/interaction_raycast.tscn:5)为相机中心向前2个场景单位。已确认的鼠标点选需要根据鼠标屏幕位置构造射线。[相机官方文档](https://docs.godotengine.org/en/4.6/classes/class_camera3d.html#class-camera3d-method-project-ray-origin)提供屏幕坐标到世界射线的投影方法。

讨论建议：普通模式只允许设备入口；聚焦模式识别当前设备内部的开闭与取放目标，并对设备整体入口盒进行查询过滤。角色身体仍需要设备的物理阻挡，不能为射线操作直接全局关闭外部碰撞。必要机壳与场景遮挡如何配置，应依据实际命中测试决定，不能宣称目前已无遮挡问题。

此方向与[既有聚焦扩展讨论](/D:/autolysis/docs/project-autolysis/00-discuss/道具系统/道具系统讨论p2.md:102)一致；该历史章节明确仅为建议，不作为本轮已经完成的实现。

### 4.2 移动、滚轮与聚焦操作需要分开许可

[玩家配置](/D:/autolysis/main-autolysis/player/autolysis_player.gd:144)把滚轮切换和普通交互都接到 is_interaction_input_allowed（交互输入许可）。[许可实现](/D:/autolysis/main-autolysis/player/autolysis_player.gd:149)要求移动未暂停、鼠标被捕获等条件；[滚轮处理](/D:/autolysis/main-autolysis/player/components/autolysis_inventory_controller.gd:145)确实检查该许可。

因此，直接采用“暂停移动并显示鼠标”会使现有滚轮入口被拒绝。用户要求的是禁止普通移动而保留道具切换，后续不能仅复用一个移动暂停开关来完成聚焦控制。

### 4.3 道具转移沿用现有数据语义

当前道具格保存道具定义，手持模型是独立生成的展示节点。[手持展示器](/D:/autolysis/main-autolysis/player/components/autolysis_held_item_presenter.gd:8)实例化展示场景；[世界原药创建](/D:/autolysis/main-autolysis/player/components/autolysis_inventory_controller.gd:167)使用另一条创建流程。

因此，“把原药作为锚点子节点”可以满足摆放要求，但不应理解为必须把手持展示节点直接搬到设备中。建议按现有道具定义创建槽内原药，并使其归属对应槽位；原药跟随槽位运动。放入成功后清空当前道具格，取出成功后填入当前空格；失败保留原状态，不复制或丢失原药。

上述是衔接建议，不表示已实现混合器占用管理。现有道具控制器的放置入口针对原药放置架，混合器需要表达“用户命中的指定槽位”，不能伪装成自动分配空位的架子。

另外，[现有世界原药](/D:/autolysis/main-autolysis/systems/item-system/autolysis_raw_material.gd:38)具有自身拾取入口，未包含设备聚焦和槽位开闭条件。若继续使用此世界原药场景，需要让设备管理该入口及碰撞参与方式，保证只能按本轮规定从取放交互区取药，不能通过药品自身入口绕过聚焦或打开条件。此结论为代码结构推导，不表示当前尚未接入的设备已经出现运行故障。

### 4.4 手持模型跟随聚焦后的角色相机

[角色相机](/D:/autolysis/main-autolysis/player/autolysis_player.tscn:119)与[手持物容器](/D:/autolysis/main-autolysis/player/autolysis_player.tscn:158)处于不同节点分支；[手持展示器](/D:/autolysis/main-autolysis/player/autolysis_player.tscn:164)在手持物容器下。单独移动相机不会自动带动这套手持展示节点。

用户已确认：手持模型继续显示，并跟随聚焦后的角色相机。后续需把相机与手持展示的跟随关系一并处理；滚轮换药、放入后空手、取出后持药的显示仍由当前道具格决定。

### 4.5 参考项目可借鉴的实际内容

参考项目具有[保险箱聚焦脚本](/D:/cogito/main-degauss/prefabs/box/scripts/degauss_lockable_focus_object.gd:36)：区分未聚焦、进入、聚焦、退出四种状态；[进入段](/D:/cogito/main-degauss/prefabs/box/scripts/degauss_lockable_focus_object.gd:89)处理相机过渡；[射线段](/D:/cogito/main-degauss/prefabs/box/scripts/degauss_lockable_focus_object.gd:141)使用鼠标位置；[输入段](/D:/cogito/main-degauss/prefabs/box/scripts/degauss_lockable_focus_object.gd:173)处理右键；[退出段](/D:/cogito/main-degauss/prefabs/box/scripts/degauss_lockable_focus_object.gd:214)恢复观察状态。

该脚本属于参考项目的具体游戏对象，并非 COGITO（参考框架）的统一聚焦契约。其设备相机切换方式和默认0.4秒过渡不同于本轮要求；可参考状态与输入组织，不能直接照搬这些行为。

## 五、建议补齐的行为边界

以下均为讨论建议，除明确注明用户已确认外，不擅自升级为需求。

| 情境 | 建议规则 | 状态 |
| --- | --- | --- |
| 一次左键进入聚焦 | 只触发进入，不在同一次按下中再打开槽位或放药。 | 待后续确认或实施设计。 |
| 相机0.2秒过渡期间 | 暂不执行槽位开闭与原药取放。 | 待后续确认或实施设计。 |
| 单个槽位正在开闭 | 忽略该槽位的重复点击，结束后继续；其他槽位仍可操作。 | 用户已确认，列于此处便于和其余边界对照。 |
| 槽内有原药时点击开闭区域 | 仍可关闭，原药留在槽内。 | 对“再次交互关闭”的解释，未单独确认，不作为额外已确认规则。 |
| 原药放入条件 | 槽位完全打开且空置，当前格为原药；每槽放一个原药。 | 单槽容量及动画完成门槛为建议，尚未单独确认。 |
| 槽内已有原药，玩家也持有原药 | 不覆盖、不自动交换。 | 待确认建议。 |
| 关闭的槽位 | 不接受放入原药。 | 用户原话已限定槽位打开时放入。 |
| 取出的开闭门槛 | 同样要求槽位打开。 | 本轮按用户对取放的连续描述理解，见第二节；用户未单独描述关闭时取出。 |
| 正在开闭的槽位 | 除开闭重复点击外，原药取放也等待动画结束。 | 对动画期间“再操作”限制的建议展开。 |
| 持有非原药或空手点击空取放区 | 不转移道具；是否显示提示另行定义。 | 待确认建议。 |
| 聚焦期间滚轮改变选中格 | 下一次点击按当时的手持状态判断，不保留上一次瞄准时的道具状态。 | 依据现有即时许可流程提出的建议。 |

对“相机等数据”的具体范围，目前明确了位置、朝向和视野；投影、裁剪与其他相机配置的匹配清单留到后续实施设计收敛。对原药的摆放朝向，用户目前明确的是位置和允许的父子关系，具体姿态尚未单独指定。

退出保留状态在本轮指当前运行场景中的设备状态，不据此新增存读档、跨场景保存或药品加工流程。

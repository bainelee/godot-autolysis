## 4. 接口契约与更新顺序

### 4.1 物体组件：AutolysisInteractionComponent（自溶交互组件）

基于 Node3D（三维节点），通过组合附加到物理体。只暴露必要配置和两个操作：

| 成员 | 类型与契约 |
| --- | --- |
| is_enabled（是否启用） | bool（布尔值），默认启用；物体锁定或忙碌时由物体业务设置。 |
| interaction_mode（交互模式） | 枚举，值 DIRECT（直接交互）与 FOCUS（聚焦交互）；默认前者，后者本期仅保留标识并返回不可直接执行。 |
| can_interact（能否交互） | 接收 actor（执行者），类型 Node3D（三维节点）；返回 bool（布尔值）。只查询，不执行效果。 |
| try_interact（尝试交互） | 接收同类型执行者；返回 bool（布尔值）。再次检查可用性；合格时恰好发出一次请求。 |
| interaction_requested（交互请求信号） | 恰好一个参数 actor（执行者），类型 Node3D（三维节点）。每个接收方法保持相同签名。 |

可用条件必须同时满足：组件与执行者有效且未排队释放、处于场景树中、物理父节点有效且未排队释放、组件启用、模式为直接交互、请求信号具有唯一有效效果接收者。本期此信号仅连接一个实际效果方法，采用同步连接；日志在该方法内记录，不额外连接纯日志观察者。使用 get_connections（获取连接列表）核对数量恰好为一，取得其中的 Callable（可调用对象）并检查其有效性、接收节点仍在场景树且未排队释放；缺失、重复或失效时不显示可执行准星。连接检查只能证明结构正确，不能证明方法确实完成业务效果，后续门与开关实际运行验收仍不可省略。

组件内部用一个非导出的分发中标记防止同一次信号回调递归调用交互入口。该标记只防重入，不承担动画忙碌状态；物体需要延迟操作时自行维护启用状态。组件不保存玩家的长期引用，不操作准星，不读取输入。

返回真只表示“本次请求已经分发”，返回假表示“未分发”；不将其解释成门动画已结束。物体负责提前将真实业务条件映射到启用状态，确保准星与业务状态一致。正式业务新增复杂条件时扩展此查询契约，不在界面脚本内复制条件。

### 4.2 射线：保留 InteractionRayCast（交互射线检测类）

保留现有 interactable_seen（发现交互物信号，单参数）和 interactable_unseen（未发现交互物信号，无参数），继续满足现有测试用途。参数若补充类型，逐个核对现有连接。

新增 refresh_target（刷新并返回目标）：返回 Node3D（三维节点）或空引用。内部强制更新射线、读取首个碰撞对象、检查对象有效性及分组，再更新目标和通知。仅当目标引用变化时发出目标变化信号。

普通墙体被命中时直接返回空目标；不能把墙加入临时排除列表继续向后查，也不能查询周围辅助形状。读取碰撞对象后先检查实际类型，不假设返回的一定是物理体。

由玩家交互控制器每个显示帧调用一次刷新，并在执行点击前额外刷新。删除检测器原先独立的逐帧更新入口，避免双重更新职责。保留射线节点本身及实际物理排除配置。

### 4.3 玩家控制器：AutolysisInteractionController（自溶交互控制器）

基于 Node（节点）。控制器接收依赖，不自行寻找全局玩家或界面管理器。

configure（配置依赖）接收 actor（执行者，Node3D（三维节点））、detector（检测器，InteractionRayCast（交互射线检测类））、input_allowed（输入许可查询，Callable（可调用对象））。许可查询为零参数、返回 bool（布尔值）、无副作用。未配置或依赖失效时默认不可执行。

控制器发布 direct_availability_changed（直接交互可用状态变化信号），恰好一个 available（可用状态）参数，类型 bool（布尔值）；准星的 set_direct_available（设置直接交互可用状态）接收相同参数。

每次状态刷新顺序：

1. 核对依赖及执行者存活；任一失效时清空当前目标与组件，将可用状态置为假并通知变化，然后返回，不能保留上一帧的四根细线。
2. 刷新射线目标。
3. 只遍历命中物体的直接子节点，查找新交互组件；不递归查子孙，也不向父节点猜测归属。
4. 组件数量不为一时，判为不可执行；多组件配置错误仅在配置/目标改变时报告一次，不能每帧刷屏。
5. 同时查询玩家许可与组件可用性，得到本帧是否可以直接执行。
6. 只在布尔状态改变或初次配置时发出可用状态通知。对象不变时仍重新计算，保证禁用、恢复和模式变化能够刷新准星。

玩家脚本新增 is_interaction_input_allowed（是否允许交互输入），统一检查：场景树未暂停、移动未暂停、没有显示界面、没有处于落地眩晕、鼠标处于捕获模式。以上为对当前玩家输入状态的兼容门控，不新增游戏系统。

玩家父节点在自己的 _ready（就绪回调）末尾完成装配：保留原初始化和碰撞排除，连接状态信号到准星，最后调用控制器配置。子控制器就绪时不得提前读取父玩家尚未初始化的引用。

### 4.4 输入的唯一执行入口

新增输入动作 interact_direct（执行直接交互），默认只绑定鼠标左键。动作名在控制器集中定义，不在各物体中重复配置。

仅控制器的 _unhandled_input（未处理输入回调）分发交互；不再在玩家输入回调或逐帧轮询中添加第二个执行入口。收到该动作的按下事件时：

1. 排除回声事件，检查玩家输入许可。
2. 立即重新执行同一状态刷新，避免使用上一帧目标或上一帧可用性。
3. 对刚核实的唯一组件调用尝试交互方法。
4. 已分发时将输入标为已处理，防止其他入口重复消费。
5. 执行后重新刷新，处理效果导致的目标移动、禁用、模式变化或释放；不得继续访问已释放的旧组件。

一次按下只产生一次请求；松开和长按期间不重复分发。没有目标或被门控时不缓存请求，不在恢复游戏或重新瞄准后补发。

### 4.5 准星：AutolysisCrosshair（自溶准星）

基于 Control（控件），放在 CanvasLayer（画布层）中，全屏锚定。所有覆盖屏幕的控件都使用 MOUSE_FILTER_IGNORE（忽略鼠标输入），且不抢键盘焦点。

用填充矩形绘制，不引入贴图、字体、图片生成或线段端点样式。中心白块始终绘制；仅当直接交互可用时绘制四个细矩形。状态或尺寸变化时请求重绘，不每帧无条件重绘。

以准星中心为坐标原点，矩形数据如下：

| --- | ---: | ---: | ---: | ---: |
| 中心白块 | -1 | -1 | 2 | 2 |
| 上线 | -1 | -29 | 2 | 20 |
| 下线 | -1 | 9 | 2 | 20 |
| 左线 | -29 | -1 | 20 | 2 |

# 聚焦碰撞跟随修复记录

日期：2026年9月26日。对应问题：原药取放碰撞形状未随槽位旋转；调整场景后零号槽配置失败。

## 已确认原因与修复

1. [当前场景](/D:/autolysis/main-autolysis/scenes/prefabs/prefab_machines/machine_blend_0.tscn)中零号槽的 raw_material_anchor（原药锚点）引用为空。实际直接运行该场景复现了用户报告的零号槽配置失败。已恢复到 rm_place_slot_0（零号原药取放体）。[原始场景快照](聚焦碰撞跟随修复证据/machine-user-before.tscn.snapshot)、[实际复现日志](聚焦碰撞跟随修复证据/user-scene-reproduction.stderr.log)。
2. 四个 rm_place_slot（原药取放体）都是嵌套的 AnimatableBody3D（三维可动画物理体），原先默认开启 sync_to_physics（物理同步）。父槽动画改变全局姿态时，子体独立物理同步会回写旧姿态。已只对四个子取放体关闭该设置；负责动画的四个父槽继续保留物理帧同步。
3. [槽位配置校验](/D:/autolysis/main-autolysis/scenes/prefabs/prefab_machines/scripts/autolysis_blend_slot.gd)现在返回具体失效原因，包括锚点未绑定、父子关系不正确、组件错误或随动子体再次开启独立物理同步。[设备初始化](/D:/autolysis/main-autolysis/scenes/prefabs/prefab_machines/scripts/autolysis_blend_machine.gd:35)将具体原因附在报错路径后。

没有移动碰撞形状、改节点类型或重新制作动画。执行期间另观察到参考相机位置由（0，0.3，1.66）变为（0，0.227，1.678）；这不是本次修复操作产生的变化，已保留。[实际场景差异范围](聚焦碰撞跟随修复证据/scene-change-scope.json)记录原94个节点均保留，除锚点引用、四处同步设置及上述相机调整外，场景内容一致。

## 先前验收的更正

上一轮聚焦测试对随动的检查不充分，没有对整段动画持续读取物理服务器姿态及实际碰撞。不能以先前测试通过宣称子碰撞已正确跟随。本次已建立能在原配置失败、修复后通过的真实物理回归。

修复后首次图形回归209项通过、1项失败。失败项为遮挡测试预设两次命中之间存在间隙，但其选点落在两个盒体的共同边界，不能在该点布置夹层墙；该失败保留在[图形首轮结果](聚焦碰撞跟随修复证据/focus-rendered.json)。随后对取放盒屏幕投影进行37250次像素查询，其中16590次依次命中本槽及其取放体，最大正向间距仅约0.00000058989，仍不足以放入独立墙体；该次200项通过、1项失败的结果保留在[全像素搜索结果](聚焦碰撞跟随修复证据/focus-rendered-final.json)及[实际射线记录](聚焦碰撞跟随修复证据/focus-rendered-final/focus-interaction-report.json)。这与两个盒体局部上边界同为0.4的正式几何一致。

最终仅在内部墙遮挡测试中，把运行时玩家相机临时移至原外盒侧面外0.02，朝向原内盒中心。中央像素（640，360）的2单位射线依次命中位置（0.22，1.207892，-0.000283）与（0.15，1.207892，-0.000283），实测正向间距0.0699999928474426。将独立墙体置于这两次命中之间后，正式查询返回槽开闭区，真实鼠标点击未取走墙后的原药。该段验证的是原有几何上的两次查询遮挡规则；当前正式参考视角的四槽操作由其余图形断言覆盖。

夹具结束后恢复玩家相机与手持姿态，并验证正式参考相机保持原值；生产几何、射线距离和排除规则没有因测试而调整。已删除临时全像素穷举代码。[最终包装器结果](聚焦碰撞跟随修复证据/focus-obstruction-fixture-authorized.json)、[212项断言及射线观测](聚焦碰撞跟随修复证据/focus-obstruction-fixture-authorized/focus-interaction-report.json)、[最终场景差异复核](聚焦碰撞跟随修复证据/final-scene-scope.json)。另保留一次沙箱内启动失败的日志；该进程未进入测试脚本，不计入测试断言结果。

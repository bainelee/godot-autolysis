按钮显示优先级为：实际故障、正在封装、完成胶囊待取、普通阶段可点击、普通阶段不可点击。运行和完成待取期间虽然按钮不可再次点击，仍按用户指定的阶段显示闪烁或蓝色常亮。

完成提示灯仅在成功封装和成功取走本轮胶囊后的重置边界切换材质。普通阶段的就绪变化、类型选择、舱门动作和按钮闪烁不得反复写入这两个网格的材质，也不得给它们添加闪烁。

## 三 可点击状态的判定与刷新

本计划将“可点击”定义为当前玩家已进入本机聚焦状态，且 start_interaction.can_interact（开始交互组件可交互）对该玩家返回真；不要求鼠标正在悬停按钮。该查询已经调用 can_start（按钮可启动），最终复用 can_start_processing（机器可开始封装）及其完整拒绝条件。

普通阶段因此需要同时满足：有效液体内容的罐、合法空胶囊、有效封装类型、取放事务结束、舱门与类型开关停止运动且状态合法、无运行批次、无故障、无完成胶囊待取、配置及交互入口有效、玩家聚焦许可有效。取消类型选择、打开界面、退出聚焦或控制件开始运动后，按钮按实际许可恢复红色。重新满足完整许可后恢复蓝色常亮。

刷新采用以下范围：

1. 场景初始化完成后刷新一次；就绪状态由实际许可计算。
2. 在封装机既有 _physics_process（物理帧更新）的早退判断前检查按钮显示，覆盖聚焦进出、取放结束、门或开关动画结束及启用标记变化。仅在显示状态改变时应用材质。
3. 在真实启动、成功完成、批次失败和成功取走本轮胶囊的接点同步刷新，保证业务通知的观察者立即读取到对应灯态。
4. 运行状态重复刷新时保留当前补间及相位，不重复创建循环。

当前聚焦目标没有反向获取玩家的接口。本计划通过已有 Player（玩家）组取得候选，筛选有效的 AutolysisPlayer（项目玩家类型），再调用完整交互许可。该组还包含 DegaussPlayerFoundArea（玩家发现区域），不能直接取第一个组节点。证据见[玩家根节点组配置](D:/autolysis/main-autolysis/player/autolysis_player.tscn:43)和[发现区域入组](D:/autolysis/main-autolysis/player/autolysis_player.gd:145)。此方式也覆盖现有测试直接进入聚焦控制器的路径，无需更改共享聚焦组件。

完成待取直接复用 _completed_capsule_instance（已完成胶囊实例）这一现有成功批次记录，不通过“槽里存在满胶囊”自行推断本机完成。退出聚焦、再次进入、开关舱门或先取空罐均不清除该完成记录，因此按钮和两个完成灯继续保持。

## 四 闪烁算法与材质隔离

用户要求每秒两次从0到2.0或从2.0到0的 lerp（线性插值）。单向插值时长为0.5秒，完整往返周期为1秒。

本计划选择与已实施配药器相同的起始方向：进入运行态时将独立材质的 emission_energy_multiplier（发光能量倍率）设为2.0，先用0.5秒线性降至0，再用0.5秒线性升至2.0，持续循环。起始方向属于本次实现选择，用户要求的幅度和每秒两次单向插值保持不变。

| 运行后的有效游戏时间 秒 | 预期发光能量倍率 |
| --- | --- |
| 0 | 2.0 |
| 0.25 | 1.0 |
| 0.5 | 0.0 |
| 0.75 | 1.0 |
| 1.0 | 2.0 |
| 1.25 | 1.0 |
| 1.5 | 0.0 |
| 1.75 | 1.0 |

已实际计算13个采样点并与独立预期序列比较，结果一致，见[线性插值校核数据](D:/autolysis/docs/project-autolysis/00-discuss/交互系统/封装机提示灯计划证据/线性插值校核.json)。这是计划数学校核，尚未证明引擎实际闪烁；两秒封装仍由原有计时与累计物理游戏时间判定，不根据灯循环次数提交产物。

每台封装机只为按钮运行材质调用 duplicate（复制资源），建立独立的 StandardMaterial3D（标准三维材质）副本，纹理继续共享。按钮运行时只修改该副本。两个完成灯直接使用未修改的零号蓝色资源，红色、灰色和一号蓝色也作为固定引用。这样按钮闪烁不会改变完成灯、另一台机器或原始资源。依据为[资源复制官方说明](https://docs.godotengine.org/en/4.6/classes/class_resource.html#class-resource-method-duplicate)。

显示使用 material_override（覆盖材质）替换对应网格的材质，不修改网格表面共享资源。依据为[覆盖材质官方说明](https://docs.godotengine.org/en/4.6/classes/class_geometryinstance3d.html#class-geometryinstance3d-property-material-override)。

闪烁采用本机绑定的单个 Tween（补间动画），串行执行两个 tween_property（属性补间），明确设置 Tween.TRANS_LINEAR（线性过渡）和 set_loops（设置循环）。采用物理帧更新、暂停时停止推进并遵守游戏时间缩放，与当前加工计时一致。每次离开运行态、故障或设备退出场景时 kill（终止补间）并清空引用；新批次创建新补间。依据为[补间线性、循环与生命周期官方说明](https://docs.godotengine.org/en/4.6/classes/class_tween.html)。

倍率为0只消除自发光贡献，基础蓝色表面仍可见。验收检查发光倍率和明暗变化，不将最低点完全不可见作为通过条件。

显示校验单独检查网格引用、节点归属、网格存在和材质类型。按钮网格必须属于本机开始按钮，两个完成网格必须属于本机完成提示节点。显示依赖失效时报告错误并停止相关灯更新和补间，不改变已有封装业务许可和故障处理规则。

业务接入按以下顺序执行：

1. **初始化**：先建立显示引用和独立运行材质，保持红色按钮和灰色完成灯；现有机器配置完成后计算普通阶段按钮许可。
2. **开始**：在 try_start_processing（尝试开始封装）已接受请求、设置运行状态并启动计时后，立即切入按钮闪烁，随后发出 processing_started（封装开始）。按钮按压动画仍与封装计时并行。
3. **提交**：两件数据及外观共同提交、内容变化通知期间维持运行显示。不能在静默提交段增加外部通知，也不能看到完成胶囊记录就提前结束闪烁。
4. **完成**：在 _complete_batch（完成批次）中将 _processing（封装中）设为假后，先停止按钮闪烁并切为一号蓝色，同时将两个完成灯切为零号蓝色，再发出 processing_completed（封装完成）。
5. **重置**：在 on_packing_item_taken（接收封装物品取走）确认本轮胶囊成功取走、清除完成记录及取消选择后，同步恢复红色按钮和灰色完成灯。先取罐或取回失败的分支保持原灯态。
6. **失败与退出**：批次失败通知之前停止闪烁并恢复红色；在 _exit_tree（退出场景树）清理补间。仅停止显示，不增设自动故障恢复。

完成灯的材质操作集中在完成与重置两个方法接点，普通阶段每帧刷新只处理按钮。显示状态未改变时直接返回，避免运行相位被重置。

## 七 实施与验收步骤

1. 重新读取当前工作区差异和材质资源，与保存的基线对照；保留已有修改。
2. 修改场景默认材质并绑定三个网格，增加机体集中显示控制和独立运行材质。
3. 接入普通阶段许可检查，以及真实启动、完成、失败和成功取胶囊重置边界。
4. 补充现有封装链路灯态断言及专项验收，执行相关回归。
5. 采集实际倍率时间数据和真实渲染画面，保存命令、退出码、断言结果、资源隔离结果及画面证据。

| 验收情形 | 通过标准 |
| --- | --- |
| 初始无输入；只放罐或只放胶囊；未选类型 | 按钮红色，两个完成灯灰色。 |
| 已聚焦，有合法满罐、空胶囊和稳定有效类型 | 按钮使用一号蓝色材质常亮；两个完成灯保持原材质。 |
| 相同合法输入，舱门完全打开或完全关闭 | 两种状态均按现有许可显示就绪；移动期间红色，运动结束后重新计算。 |
| 类型开关移动、取消选择、转移忙碌、交互入口禁用 | 按钮红色，不产生运行闪烁。 |
| 普通就绪时退出聚焦，再完成进入聚焦 | 退出时红色，重新满足完整许可后蓝色常亮。 |
| 实际按钮点击被接受 | 同步进入零号蓝色材质副本的闪烁；不等待按钮动画完成。 |
| 点击被拒绝 | 无新补间，维持按实际许可计算的普通显示。 |
| 运行中的倍率采样 | 范围0至2.0，每段约0.5秒，时间误差容许一个实际物理更新帧；完整周期约1秒。 |
| 运行中重复刷新 | 补间实例与相位保持，只有一个循环；两个完成灯材质不变。 |
| 游戏暂停、恢复及退出聚焦 | 暂停期间批次时间和倍率均冻结；恢复继续。运行中退出聚焦仍继续封装与闪烁。 |
| 成功封装与完成通知回调 | 回调观察到按钮一号蓝色常亮、双完成灯零号蓝色倍率2.0；无残留运行补间。 |
| 完成后先取空罐、开关舱门或退出再进入聚焦 | 三个灯保持完成显示。 |
| 取胶囊候选或来源复核失败 | 产物与完成记录保留，三个灯保持完成显示。 |
| 本轮胶囊成功取走 | 在库存变化通知前按钮已红、完成双灯已灰；现有选择已取消。 |
| 封装失败或原子提交回滚 | 按钮停止闪烁并红色；不亮完成双灯；原有来源保留和故障锁通过。 |
| 连续两轮封装 | 每轮完整经历红色、就绪蓝色、运行闪烁、完成常亮、取走重置；旧补间不残留。 |
| 两台机器并存 | 一台按钮闪烁不改变另一台及共享零号蓝色资源；完成灯常亮倍率始终为2.0。 |
| 按钮灯或整机退出场景 | 不再访问失效显示节点，无残留循环。 |
| 既有封装回归 | 两秒加工、双物品共同提交、来源变化失败、暂停、聚焦、取放回滚、开关运动与重置顺序保持通过。 |

实施验收使用用户指定的 Godot（戈多引擎）4.6.1版及[项目现有检查包装器](D:/autolysis/main-autolysis/systems/item-system/tests/run_item_check.ps1:1)。相关回归包括[封装行为验收](D:/autolysis/main-autolysis/systems/item-system/tests/packing_machine_behavior_test.gd:1)、[封装批次原子性验收](D:/autolysis/main-autolysis/systems/item-system/tests/packing_batch_atomic_test.gd:1)、[封装运动物理验收](D:/autolysis/main-autolysis/systems/item-system/tests/packing_motion_physics_test.gd:1)和[封装开关重复操作验收](D:/autolysis/main-autolysis/systems/item-system/tests/packing_switch_repeat_test.gd:1)。真实渲染应至少留存初始红色、就绪蓝色、运行明暗、完成三灯及取走重置画面；自动图形检查采用隐藏窗口。

## 一 已接入的显示规则

| 实际业务阶段 | 开始按钮 | 两个完成灯 |
| --- | --- | --- |
| 初始、普通阶段不可交互 | 指定红色基础材质，无补间 | 指定灰色基础材质 |
| 玩家已聚焦，正式开始交互完整许可有效 | 指定一号蓝色发光材质常亮，倍率沿用资源 | 保持原材质 |
| 真实开始请求已被接受 | 指定零号蓝色材质的本机副本，倍率在2.0和0之间往返 | 保持原材质 |
| 成功完成，胶囊尚未取走 | 一号蓝色常亮，停止运行补间 | 零号蓝色常亮，倍率2.0 |
| 完成后先取空罐、舱门运动、退出再进入聚焦或胶囊取回失败 | 继续完成待取显示 | 继续常亮 |
| 成功取回本轮胶囊 | 同步恢复红色并清理运行补间 | 同步恢复灰色 |
| 本轮封装失败 | 停止补间并恢复红色，保留原故障锁 | 不进入完成显示 |

按钮优先级为实际故障、运行、完成胶囊待取、普通就绪、普通不可交互。完成凭据复用本机已完成胶囊实例，没有根据槽位中的封装胶囊另建完成状态。普通状态通过正式开始交互的完整只读许可查询计算，候选只取玩家组中的实际项目玩家，过滤同组发现区域。舱门完全打开和完全关闭均可继续满足原有启动规则。

## 三 闪烁与资源隔离

按钮运行材质使用 duplicate（复制资源）建立本机独立的 StandardMaterial3D（标准三维材质）副本。只有该副本的 emission_energy_multiplier（发光能量倍率）参与补间，两个完成灯继续引用未修改的零号蓝色材质。所有网格通过 material_override（覆盖材质）显示，不写入共享网格表面材质。

运行态从倍率2.0开始，先用0.5秒线性降到0，再用0.5秒线性升到2.0并持续循环。Tween（补间动画）使用物理处理、暂停停止推进并遵守游戏时间缩放。运行状态重复刷新不重新创建补间；离开运行、显示节点退出或设备退出均终止补间。加工仍使用原两秒计时和累计物理游戏时间，未改用灯循环计数提交产物。

零号蓝色资源显式倍率为2.0，见[零号材质实际内容](D:/autolysis/main-autolysis/assets/materials/glow_color/mat_glow_blue_0.tres:10)；一号蓝色资源未序列化倍率，见[一号材质实际内容](D:/autolysis/main-autolysis/assets/materials/glow_color/mat_glow_blue_1.tres:8)，沿用引擎默认倍率1.0。倍率0只移除自发光贡献，基础蓝色表面仍可见，专项以倍率与真实画面变化核验。

资源导入首轮引擎退出码为0，但实际日志包含编辑器用户数据目录、配置目录和用户目录无法访问等错误，检查包装器因此判定失败。该记录保留在[资源导入首轮检查](D:/autolysis/docs/project-autolysis/00-discuss/交互系统/封装机提示灯实施证据/检查/提示灯实现资源导入.json)及[首轮错误日志](D:/autolysis/docs/project-autolysis/00-discuss/交互系统/封装机提示灯实施证据/检查/提示灯实现资源导入.stderr.log)。具备引擎用户目录权限的进程再次执行相同导入参数后通过；没有通过忽略错误取得通过结果。

提示灯专项首轮检查保留在[首轮专项检查记录](D:/autolysis/docs/project-autolysis/00-discuss/交互系统/封装机提示灯实施证据/检查/封装提示灯专项无图形验收.json)及[首轮专项完整输出](D:/autolysis/docs/project-autolysis/00-discuss/交互系统/封装机提示灯实施证据/检查/封装提示灯专项无图形验收.stdout.log)。首轮存在测试前提失败及其后续空补间访问错误，不能据其部分通过断言将专项认定完成。当前修正依据如下。

1. 实际开始交互模式不匹配会使聚焦目标校验失效；[聚焦控制器](D:/autolysis/main-autolysis/player/components/autolysis_focus_controller.gd:119)会中止会话。恢复交互模式后需通过正式入口重新进入稳定聚焦，不能假设旧会话自动恢复。修正见[专项模式恢复检查](D:/autolysis/main-autolysis/systems/item-system/tests/packing_indicator_test.gd:207)。
2. [正式玩家菜单输入](D:/autolysis/main-autolysis/player/autolysis_player.gd:220)实际切换移动暂停标记，并同步暂停聚焦过渡及取消拖拽，没有将菜单动作直接等同于界面显示标记。专项改为核对真实菜单许可，并另外使用既有界面标记夹具核验独立界面分支，见[专项菜单和界面检查](D:/autolysis/main-autolysis/systems/item-system/tests/packing_indicator_test.gd:217)。
3. 成功取胶囊会取消类型并启动现有复位动画。连续第二轮必须等待该真实动画结束后再选择类型，不能在运动锁仍有效时假设下一轮已经就绪。修正见[连续批次复位时序](D:/autolysis/main-autolysis/systems/item-system/tests/packing_indicator_test.gd:372)。

上述调整针对验收前提和失败后的空引用保护，生产业务许可、聚焦失效处理及类型动画规则保持原实现。过程中的阶段复验955项无图形断言及954项图形断言均通过，记录分别保留在[阶段无图形检查](D:/autolysis/docs/project-autolysis/00-discuss/交互系统/封装机提示灯实施证据/检查/封装提示灯专项无图形修正验收.json)和[阶段图形检查](D:/autolysis/docs/project-autolysis/00-discuss/交互系统/封装机提示灯实施证据/检查/封装提示灯专项图形验收.json)。追加事务边界和归属覆盖后的1019项无图形及1016项图形最终验收作为完成依据，阶段数据不重复计入最终总数。

## 八 最终事务失败与跨机归属验证

共同提交回滚专项通过正式库存及开始按钮入口启动真实批次，使用仅拒绝静默清空的液体罐实例实施故障注入。实际预检通过后，胶囊已写入封装内容，静默清罐恰好拒绝一次，原满罐源内容静默写回一次，胶囊恢复为空；失败通知恰好一次，完成记录为空。正式两槽占用、原实例身份与满罐及空胶囊外观均保留，按钮恢复红色、双完成灯保持灰色、旧补间被终止且既有故障锁保持。见[真实共同提交回滚验收](D:/autolysis/main-autolysis/systems/item-system/tests/packing_indicator_test.gd:414)及[同步失败通知断言](D:/autolysis/main-autolysis/systems/item-system/tests/packing_indicator_test.gd:405)。

取回来源复核专项先正式完成封装，再在真实合法手持候选已生成后同步替换来源实例身份，使正式库存事务的来源复核拒绝请求。实际候选被释放、原胶囊槽占用保留、库存仍为空、取放事务结束、完成记录仍为本轮原实例，库存变化通知数为0；三灯继续完成常亮。恢复原来源与正式显示器后成功取回本轮胶囊才触发三灯复位。见[来源身份复核失败验收](D:/autolysis/main-autolysis/systems/item-system/tests/packing_indicator_test.gd:450)。上述两种失败边界的实际记录位于[最终无图形报告](D:/autolysis/docs/project-autolysis/00-discuss/交互系统/封装机提示灯实施证据/专项无图形最终/packing-indicator-report.json)和[最终图形报告](D:/autolysis/docs/project-autolysis/00-discuss/交互系统/封装机提示灯实施证据/专项图形最终/packing-indicator-report.json)的事务失败边界字段。

跨机归属专项分别检查误绑定另一台的开始按钮、同时误绑定另一台的开始按钮与按钮网格，以及混入另一台完成网格的情况，均被本机归属校验拒绝。运行中再将按钮网格误绑定另一台并刷新时，显示及补间停止且引用清空，另一台原材质不受污染；本机原业务仍继续运行并成功完成封装，没有新增业务故障。见[跨机归属验收](D:/autolysis/main-autolysis/systems/item-system/tests/packing_indicator_test.gd:489)及[开始按钮与网格同时误绑定断言](D:/autolysis/main-autolysis/systems/item-system/tests/packing_indicator_test.gd:498)。最终专项报告保存这些断言的实际通过结果。

# 任务文件打印讨论第一部分

记录日期：2026年10月7日。状态：需求讨论与容量核算，已回填逐行显示、空行收尾、聚焦获取、首份委托内容与测试事件；页面排版采用暂定参数。

本轮讨论 quest_machine_0（任务打印机零号）的任务文件打印动作、逐行数据显示、空行跳过、物品获取及设备提示。该设备在游戏中称为“通知中心”。按首行纵向位置-0.10、每行下降0.02、最低纵向位置-0.50且最低位置仍打印一行计算，共有21个机械打印行位置；全部非空时，最多执行21行打印动作。任务文件的数据可以超过21行，超出机械动作范围的剩余内容在打印完成时同步显示。

## 一 节点位置与运动范围

| 节点 | 初始位置 | 运动范围或目标位置 |
| --- | --- | --- |
| print_bar_horizontal_axis（打印横轴） | （0，0，0） | 首行位置（0，-0.10，0）；最低位置（0，-0.50，0）。 |
| print_bar_main（打印头） | （0.10，0，0） | 最左位置（-0.07，0，0）；最右位置（0.27，0，0）。 |

用户首行位置原文为“（0.-0.1,0）”；本轮讨论及容量计算按（0，-0.10，0）记录。

## 二 打印动作时序

### 首行打印

1. print_bar_horizontal_axis（打印横轴）用0.2秒从初始位置移动至（0，-0.10，0）。
2. 到达后等待0.5秒。
3. 若首行非空，print_bar_main（打印头）用0.2秒从初始位置移动至最左位置（-0.07，0，0）；若首行为空，则暂不执行首次移左，等到首次非空行开始打印前再执行。
4. 若首行非空，print_bar_main（打印头）用5秒移动至最右位置（0.27，0，0），并在该动作结束时显示该行数据；若首行为空，则跳过横向打印动作。
5. 若首行非空且不是本次末行，print_bar_main（打印头）用0.4秒返回最左位置（-0.07，0，0）；若首行就是本次末行，则直接按收尾流程归中与复位。空行不执行普通横向回程。

上述流程构成首行打印。首行或前若干行为空时，按行位置向下推进；首次移左只在首次非空行开始打印前执行一次。

### 后续普通行打印

1. print_bar_horizontal_axis（打印横轴）用0.2秒向下移动0.02，到达下一行位置。
2. 若该行非空，print_bar_main（打印头）用5秒从最左位置移动至最右位置（0.27，0，0），并在该动作结束时显示该行数据；若该行是首次非空行，则先执行0.2秒首次移左。
3. 若该行非空且不是本次末行，print_bar_main（打印头）用0.4秒返回最左位置（-0.07，0，0）。
4. 尚有后续机械行位置时，继续下降并重复上述流程；本次末行按下述收尾流程归中与复位。

### 最低位置的最后一行与复位

下述横向打印动作按最低位置对应非空行记录。该行为空时仍跳过横向打印，并按本节空行收尾规则归中与复位。

1. print_bar_horizontal_axis（打印横轴）最后一次向下移动后，到达（0，-0.50，0）。
2. print_bar_main（打印头）用5秒移动至最右位置（0.27，0，0），在该动作结束时显示该行数据。
3. print_bar_main（打印头）用0.2秒返回初始位置（0.10，0，0）。
4. print_bar_horizontal_axis（打印横轴）用1秒返回初始位置（0，0，0）。

最低位置对应非空行时仍执行一行打印。该行结束后的打印头回程目标为初始位置，回程时长为0.2秒。

### 不足21行时的收尾与完成时点

用户补充确认：数据不足21行时，在最后一个数据行后直接执行打印头归中与打印横轴复位，不继续打印至第21行位置。归中与复位沿用收尾流程：打印头用0.2秒回到（0.10，0，0），打印横轴随后用1秒回到（0，0，0）。

两根打印杆全部复位后，才判定整份文件打印完成；此时补全超出21行的剩余内容，并允许玩家取走任务文件。复位期间仍不可取走。

### 空行末尾的收尾顺序

用户补充确认：最低位置对应空行，或末尾连续为空行时，仍跳过相应横向打印动作。收尾先使 print_bar_main（打印头）回到初始位置（0.10，0，0），再使 print_bar_horizontal_axis（打印横轴）回到初始位置（0，0，0）；打印头归中发生在打印横轴回归之前。归中与复位沿用0.2秒、1秒的收尾时长。

## 三 逐行显示与空行处理

用户补充确认：每行数据在5秒横向打印动作结束时，直接显示在任务文件的 UI（用户界面）上。显示发生在该行回程之前，不采用逐字显示。整份文件仍需等待归中与复位全部完成后才开放取走。

用户补充确认：机械打印中的“一行”按任务数据中的换行计数。自动折行只影响页面排版，不增加机械打印行数，也不额外占用打印横轴的行位置。空行判断同样对应任务数据中的行。

若数据行为空行，则跳过该行的横向打印动作；打印横轴移动至下一行对应位置，继续处理下一行。空行仍占用一个机械行位置，不会增加21个机械行位置的容量；数据总行数仍可超过21行。

例如，完整处理21个行位置，其中3行为空行时，实际执行18行横向打印动作；其余3行只占用对应行位置并跳过横向打印。

## 四 最大打印行数与计算证据

从首行纵向位置-0.10到最低纵向位置-0.50，距离为0.40。每下一行下降0.02，因此共有20个下降间隔；加上下降前的首行，共21个行位置。

计算式：

> 下降间隔数＝［-0.10－（-0.50）］÷0.02＝20。
>
> 最大行数＝下降间隔数＋1＝21。
>
> 第几行的纵向位置＝-0.10－（行号－1）×0.02；行号从1开始。

| 行号 | 纵向位置 | 边界核对 |
| --- | --- | --- |
| 第1行 | -0.10 | 首行，非空时在下降换行之前执行打印。 |
| 第2行 | -0.12 | 第一次下降后的行位置。 |
| 第3行 | -0.14 | 第二次下降后的行位置。 |
| 第20行 | -0.48 | 最低位置之前的行位置。 |
| 第21行 | -0.50 | 最低位置，非空时仍执行最后一行打印，空行跳过横向动作。 |
| 第22行 | -0.52 | 超出最低位置，不属于本轮给定范围。 |

因此，机械动作最多覆盖21个行位置，包含空行；全部21行非空时，最多执行21行打印动作。此上限不限制任务文件的数据总行数。

对于完整的21行数据：实际横向打印次数＝21－空行数。对于更多行的数据：实际横向打印次数等于前21行中的非空行数；第22行及后续内容不再追加横向打印动作。

动作时长影响总耗时，不改变由首行位置、行距和最低位置决定的容量。

### 超过机械动作容量的文件

用户补充确定：需要打印的文件超过机械动作能够支持的最大行数时，打印动作执行到相应位置的最大程度，即按机械动作容量完成本次打印；剩余行数同步显示。

例如，文件包含25行且全部非空时，前21行对应机械打印动作并逐行显示；机械打印达到最大范围并完成两根打印杆的复位后，剩余4行同步显示，不再继续下降至第22行位置。

用户补充确认：两根打印杆全部复位后，判定本次打印完成，同步显示剩余行并开放取走。剩余内容的显示仍遵循一页范围内的截断规则。

## 六 通知中心聚焦与打印启动

### 待打印任务事件与测试入口

通知中心收到待打印任务，由事件触发。当前阶段使用测试按键 i（任务通知测试键）触发该事件，再进入待打印提示状态。按键只是本阶段的事件测试入口，不直接替代点击打印按钮的流程。

### 待打印任务提示

当通知中心存在“待打印任务”时：

1. mesh_quest_machine_light_0（待打印任务提示灯网格）切换为 [mat_glow_orange_0.tres（橙色发光材质零号）](D:/autolysis/main-autolysis/assets/materials/glow_color/mat_glow_orange_0.tres)，并持续闪烁。
2. 循环播放 [sfx_machine_notice_0.wav（待打印任务提示音零号）](D:/autolysis/main-autolysis/assets/audio/sound_fx/machine/sfx_machine_notice_0.wav)。
3. 在此状态下，可以点击 button_print_quest（任务打印按钮）开始打印。

闪烁使用 emission（自发光）的 energy multiplier（能量倍率），在0至2.0之间进行 lerp（线性插值）。用户指定暂定频率为每秒2次从0到2.0或从2.0到0的单向插值；按单向次数核算，每段0.5秒，完整往返1秒。首次闪烁从哪一端开始尚未指定。

### 点击打印按钮后的顺序

1. mesh_quest_machine_light_0（待打印任务提示灯网格）恢复为 [mat_base_red_3.tres（基础红色材质三号）](D:/autolysis/main-autolysis/assets/materials/base_color/mat_base_red_3.tres)，结束待打印闪烁。
2. 停止待打印任务提示音的循环播放。
3. 创建一个空白 quest_paper（任务文件）实例，放在 quest_paper_slot（任务文件放置锚点）之下。
4. 执行第二节的打印动作，并根据行完成过程显示任务数据。
5. 本次打印完成前，任务文件保持不可取走。

### 打印完成后等待取走

打印完成且玩家尚未取走任务文件时：

1. 允许在通知中心聚焦状态下，通过交互取走本次任务文件并放入现有携带栏。
2. mesh_quest_machine_light_1（已打印文件待取提示灯网格）切换为 [mat_glow_blue_0.tres（蓝色发光材质零号）](D:/autolysis/main-autolysis/assets/materials/glow_color/mat_glow_blue_0.tres)，按待打印提示灯的相同方式闪烁。
3. 循环播放 [sfx_machine_scanning_0.wav（文件待取扫描提示音零号）](D:/autolysis/main-autolysis/assets/audio/sound_fx/machine/sfx_machine_scanning_0.wav)。
4. 持续提示直到玩家取走任务文件。

用户补充确认：文件打印完成但尚未被取走时，禁止再次打印。玩家取走文件后，结束本次待取闪烁与扫描提示音，第二盏提示灯恢复为 [mat_base_red_3.tres（基础红色材质三号）](D:/autolysis/main-autolysis/assets/materials/base_color/mat_base_red_3.tres)。

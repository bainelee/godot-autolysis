## 一 需求基线与实施范围

### 已确定的行为

| 项目 | 实施要求 |
| --- | --- |
| 当前入口 | O（测试字母键）向指定电话发送一次来电请求；正式游戏流程以后复用请求接口，本阶段不接入。 |
| 一次运行一次 | 请求进入等待也消耗机会。场景重载、电话重新入树、取消或异常均不恢复机会；退出游戏后重新启动才重置。 |
| 挂机时收到请求 | 听筒已稳定放回时立即激活来电并循环响铃，不等待2秒。 |
| 持筒时收到请求 | 保存请求，不响铃；正常放回成功后等待完整2秒。持续聚焦不阻止计时。 |
| 延后期间再次取下 | 成功取下使本次计时失效；再次正常放回后重新等待完整2秒，不累计此前时间。 |
| 接听 | 已激活来电的电话成对取筒提交成功后停止响铃并开始对应对话。等待阶段取筒不算接听。 |
| 通话限制 | 对话正常结束之前不能放回听筒；允许保持聚焦、主动退出聚焦，并在现有限位内移动。接听不自动退出聚焦。 |
| 字幕 | 白色文字、字号24、纯黑实心背景，整体水平居中；背景底边距道具栏顶边8像素，左右内边距各16像素。 |
| 字幕尺寸 | 单行背景高40像素；背景宽随内容变化，总宽最多1000像素且包含内边距。超长文本自动换行，高度随实际排版增长。 |
| 逐句时序 | 当前句文字、背景与对应语音同时开始；语音自然结束后保留默认1.5秒，再整体渐隐0.2秒，随后开始下一句。句后等待可配置。 |
| 最后一句 | 同样等待和渐隐；文字与背景全部消失后，才提交一次正常完成并解除匹配的归还限制。玩家仍持筒，自行归还。 |
| 暂停 | 来电延后、铃声、语音、句后等待与渐隐暂停并保留原进度；恢复后继续。暂停不等于取消或完成。 |
| 文本维护 | 首次建立独立原文与中文本地化文件，九句初始内容逐字一致。后续由用户手动维护本地化，不增加自动同步或启动覆盖。 |

### 本轮补充确认与设计定案

本轮用户明确选择以下两项，取代讨论文档中对应的未定状态。

| 事项 | 结论及实施影响 |
| --- | --- |
| 运行时文本来源 | 读取中文本地化配置，原文只用于维护。原文单独修改不改变游戏字幕；中文配置重新导入并重新启动测试运行后改变显示。 |
| 听筒会话异常 | 终止本次来电并记录实际原因，不自动重新等待或重播，不发正常对话完成，不恢复测试机会。 |

其余实施选择如下：中文表格由引擎导入为翻译资源，播放器显式读取中文资源；窄视口在1000像素上限之内再按可用宽度换行，新增可配置屏幕左右留白，初值各16像素；铃声使用电话位置的空间音频，通话语音使用非空间音频。以上属于本计划的设计选择，不写为用户此前指定的需求。

本阶段完成一个电话入口和 chat_0（第一段对话），不增加拨号、分支选择、跳句、跳过对话、自动挂机、存读档、其他语言、语言切换界面或正式任务推进。通用播放接口可以由其他事件调用，其他入口的玩法另行设计。

## 三 模块职责与接入接口

### 职责划分

| 拟定模块 | 所有者与职责 | 调用方无需了解的内容 |
| --- | --- | --- |
| AutolysisRuntimeSession（运行会话） | 自动加载的运行级节点，只保存本次运行已使用测试机会的事实；提供一次性领取接口。 | 场景重载、电话入树或播放器重新创建不会重置机会。 |
| AutolysisTelephoneCallTestTrigger（电话来电测试入口） | 主测试场景组件，显式引用电话和本地玩家的播放上下文；处理测试字母键并发送请求。 | 不驱动响铃计时、不保存听筒归还许可。 |
| AutolysisTelephoneCallController（电话来电控制器） | 每台电话独立拥有，保存来电序号、延后阶段、接听归属、归还限制和铃声表现；接收受控取放完成事实。 | 不读取字幕控件、字体度量或逐句音频进度。 |
| AutolysisDialogueDefinition（对话定义） | 独立资源，保存对话编号、有序行编号、对应语音和中文翻译资源引用；加载后提供本次只读快照。 | 原文编辑不需要重复长语音路径或界面参数。 |
| AutolysisDialoguePlayer（通用对话播放器） | 玩家场景组件，拥有单一当前播放会话，处理语音、句后等待、渐隐、取消、依赖失效和完成。 | 不依赖电话类、聚焦设备或听筒节点；其他事件可复用同一入口。 |
| AutolysisDialogueSubtitle（对话字幕） | 独立界面场景，管理白字、黑底、真实字体排版、道具栏上方定位和整组透明度。 | 不提交库存、不解除电话归还限制。 |

来电控制和对话播放分别拥有“始终处理的会话所有者＋可暂停的时序子树”。暂停由第八节的统一事实控制。字幕显示期间不设置玩家的界面占用或移动暂停标记，不接管相机、聚焦或鼠标模式。

### 必要接口

| 接口名称拟定 | 输入及返回语义 |
| --- | --- |
| consume_telephone_test_once（领取一次电话测试机会） | 运行级同步调用，首次领取成功，之后均拒绝；不因电话受理失败而退还。 |
| request_call（请求来电） | 输入对话定义与明确的播放上下文；返回请求是否受理，不表示已响铃或接听。受理后保存来电序号。 |
| is_handset_return_blocked（查询听筒归还限制） | 只读匹配来源电话、玩家和原持有会话；不调用电话或库存许可，不产生副作用。 |
| commit_handset_business_completion（提交听筒业务完成事实） | 由成对提交的唯一受控边界调用，输入方向、玩家、原持有会话及本次事务身份；只建立业务状态和待执行表现。 |
| prepare_dialogue（准备对话会话） | 校验全部中文条目、语音、字幕和播放依赖，成功即独占本次播放容量及令牌；准备不显示字幕或播放音频。 |
| start_prepared_dialogue（启动已准备对话） | 输入匹配的准备令牌；在条目开始边界同时显示本句并播放语音。仅接受当前未失效会话。 |
| cancel_dialogue（取消对话） | 输入播放令牌与真实原因；先失效回调，再幂等清理，不发布正常完成。 |
| dialogue_finished（对话正常完成观察信号） | 携带播放令牌、对话编号和来源身份；正常完成业务回调先处理匹配归还限制，之后才发布观察信号。 |
| dialogue_aborted（对话异常终止观察信号） | 携带匹配会话和原因；不能代替正常完成或听筒归还。 |

播放接口只绑定一个业务完成接收者和一个异常接收者，观察通知允许多个订阅者。调用方不能通过新增观察订阅抢占语音、转移听筒或解除其他会话的锁。所有调用及通知前后保留对象存活、来源身份、当前令牌和重入检查。正常收尾进入受保护的完成提交阶段，固定不可变终态结果；业务完成与观察发布结束之前保留播放互斥，新准备返回忙碌，旧收尾不清理后来会话。

本阶段不增加播放队列。准备完成、待启动、暂停待启动、正式播放和完成发布期间均占用播放器容量，新会话准备返回忙碌；只有匹配的取消、提交失败撤销、异常清理或正常完成收尾才能释放。电话保持已激活来电及响铃，忙碌时取筒请求不提交接听，也不覆盖原准备或播放。对话定义或必要播放依赖失效则按异常结束该来电，并恢复无通话限制的普通电话操作。

## 四 来电状态与听筒事务

### 状态推进

| 当前阶段 | 实际事实 | 处理结果 |
| --- | --- | --- |
| 未请求 | 测试入口领取运行机会并发送请求，听筒稳定挂机 | 保存请求并立即激活来电，循环响铃。 |
| 未请求 | 同一请求到达，听筒处于有效持有 | 保存请求，进入等待放回，不响铃。 |
| 未请求 | 请求到达时已有取放准备、取消恢复或物理清理 | 保存请求并等待事务得到实际结果；不把过渡状态判为挂机。未形成成功持有的取下失败后，稳定挂机可立即激活；确实存在过成功持有的请求进入延后规则。 |
| 等待放回 | 匹配电话正常归还成对提交成功 | 建立新等待序号，开始完整2秒延后。 |
| 放回后延后 | 匹配电话正常取下成对提交成功 | 失效旧等待序号，清除已计时间，回到等待放回。 |
| 放回后延后 | 归还取消或失败 | 不新增计时；沿用真实持有或已建立的等待状态。 |
| 放回后延后 | 本次2秒自然到期 | 记录到期事实；未暂停、序号匹配、稳定挂机且无待转移或清理时激活。 |
| 来电已激活 | 匹配电话正常取下成对提交成功且播放准备有效 | 绑定接听玩家、原持有会话和播放令牌，建立归还限制；停止响铃并启动对话表现。 |
| 对话进行中 | 匹配会话最后渐隐自然完成，字幕已隐藏 | 先解除本次归还限制，记录来电完成，再发布完成观察；不放回听筒。 |
| 任一非终态 | 匹配会话取消，来源或必要依赖失效 | 失效来电、等待和播放令牌，记录原因，终止本次来电，不自动重播。 |

稳定挂机以持有会话为零、无待完成转移与物理清理、来源及挂机展示仍有效、现有限位已按现有机制确认停用为依据。几何端点、模型名称、观察者数量和音频长度不参与来电业务许可。

延后计时与聚焦是否持续无关。取下准备发生在到期附近时，先保留到期事实并等待该事务结果：取下成功则废弃旧计时；取下取消或回滚且重新稳定挂机，可处理已经真实到期的本次等待，不伪造一次归还或重新累计。计时尚未到期时，未成功取下的预处理不重置等待；实际成功取下才触发完整重置规则。

### 成对完成边界

在[库存取下最终复核](/D:/autolysis/main-autolysis/player/components/autolysis_inventory_controller.gd:187)通过后、当前第191行起的候选引用清除及事务收尾之前，增加受控业务完成调用。归还在[库存归还最终复核](/D:/autolysis/main-autolysis/player/components/autolysis_inventory_controller.gd:213)通过后、当前第216行起的断连、持有重置、清除事务及销毁显示之前接入。两者均先完成业务事实，再发布外部观察。具体顺序如下。

1. 取放准备继续保留当前互斥、物理同步和失败回滚。来电控制只预检；尚未成对成功时不宣告接听、不播放语音、不解除原事务保护。
2. 激活来电取筒时，在提交前准备有效对话快照和独占播放令牌。准备失败为忙碌时拒绝本次取下；配置或必要依赖失效时终止该来电并记录原因。取放取消时释放仅属于本次准备的令牌。
3. 双方提交及全部必要复核通过后，同步提交来电业务事实：接听归属和归还限制，或归还成功对应的新等待序号。此调用先完整验证再一次提交，不发信号、不播放音频、不创建外部表现，也不跨等待帧；拒绝时不留下部分来电状态。库存的公开提交必须执行该唯一来源完成入口，直接调用或夹具不能用省略回调绕过；未配置来电的普通电话在同一入口完成无来电分支。
4. 业务完成调用失败按当前事务身份撤销本次双方状态及来电准备。取下此时已有库存临时持有和已提交手持显示，须新增专用撤销，同时恢复来源占用、清除匹配库存持有、撤销匹配显示并释放本次对话准备，再沿现有取消恢复确认限位停用；不能只调用[现有来源回滚助手](/D:/autolysis/main-autolysis/player/components/autolysis_inventory_controller.gd:356)。归还此时尚未清除库存持有与显示，恢复电话原持有后按原归还取消流程恢复限位。回滚及显示移除的可调用边界再次复核本次身份，不撤销后来会话；普通拒绝不冒充听筒异常。进入正常观察发布后，不因观察者尝试取消已完成事务而回滚成功状态。
5. 保留原持物变化与电话完成观察通知。最早观察者读取到的接听状态和归还限制必须已一致。观察期间释放来源、玩家或播放依赖时，匹配异常清理使待表现令牌失效。
6. 在成对成功后的受控表现阶段停止旧铃声并启动匹配对话，或启动匹配延后计时。先复核对象及令牌，暂停时保留待启动，不播放；恢复后启动同一会话。归还通知中的电话待转移标记尚未清除属于现有同步收尾，不立即判为故障。

这里的回滚保护仅撤销尚未完成的本次提交；来源仍有效的普通取下失败应保留原已激活来电与铃声。必要来源确实失效、已提交听筒会话异常终止或播放依赖无法继续时，才进入终止来电分支。

## 五 原文 中文本地化与语音配置

### 文件格式与运行读取

新增对话系统目录，原文采用 dialogue_source.cfg（对话原文配置文件），使用 ConfigFile（配置文件）支持的分节键值格式。chat_0（第一段对话）为独立分节，各句按原编号一行一个带引号字符串、等号对齐，分节间留空行。原文文件不逐句重复长语音路径、字号或等待参数。[官方配置格式](https://docs.godotengine.org/en/4.6/classes/class_configfile.html#description)支持该结构；运行及自动检查不调用保存来重新格式化用户原文。

中文采用 dialogue_zh.csv（对话中文本地化文件），表头为 keys（文本键）及 zh（中文语言列），第一列保留原编号。使用 UTF-8（八位统一字符编码）且不带 BOM（字节顺序标记）；引号、逗号和换行按表格规则转义。[官方本地化表格格式](https://docs.godotengine.org/en/4.6/tutorials/i18n/localization_using_spreadsheets.html#formatting)说明键区分大小写与转义要求。

引擎导入后，以对话定义中的明确引用加载 dialogue_zh.zh.translation（中文翻译资源），逐个按有序编号调用 Translation.get_message（翻译资源取得译文方法）。这是本阶段唯一运行文本来源，不回退原文，不根据操作系统语言选择。字幕接收已解析的中文字符串，关闭该显示节点的自动翻译，避免再次按全局语言替换。[翻译查询接口](https://docs.godotengine.org/en/4.6/classes/class_translation.html#class-translation-method-get-message)和[指定版本导入器](https://github.com/godotengine/godot/blob/4.6.1-stable/editor/import/resource_importer_csv_translation.cpp#L223)为实现依据。

保留引擎默认压缩翻译，通过已知清单逐条查询，不依赖翻译资源的键枚举。重复键、表格列数和初次逐字一致由静态配置验收检查；缺失键或空译文由准备阶段拒绝并记录具体编号。对话开始时固定本次文本、语音和时序配置快照，文件后续修改不在一句中途混入当前会话。中文修改后按“重新导入并重新启动测试运行”生效，不增加运行时热重载；这样也避免默认资源缓存继续引用旧翻译实例。[官方资源缓存模式](https://docs.godotengine.org/en/4.6/classes/class_resourceloader.html#enum-resourceloader-cachemode)

原文与中文配置首次同步建立，此后只人工维护；正常启动、播放、导入验收和异常恢复均不自动覆盖中文文件。用户单独改原文后，运行字幕保持中文文件内容；后续人工更新中文文件、重新导入并重新启动运行才更新显示。

## 六 通用逐句播放与音频

### 播放阶段

| 阶段 | 推进依据 | 处理 |
| --- | --- | --- |
| 准备 | 全段配置与必要依赖校验成功 | 固定本次有序文本、语音及参数快照，取得唯一播放令牌；准备字幕尺寸。 |
| 当前句开始 | 当前布局就绪且会话有效、未暂停 | 在同一次条目开始调用中恢复整组不透明、显示文字和背景并播放对应语音。 |
| 等待语音 | 本次播放器的 finished（自然播放完成信号） | 核对播放令牌、条目索引、当前阶段和来源，转入句后等待。 |
| 句后等待 | 本次一次性 Timer（计时器）自然到期 | 保留文字与背景至到期，再创建本次渐隐。 |
| 渐隐 | 本次 Tween（补间）自然完成 | 文字与背景整体透明并隐藏；非末句准备下一句，末句进入完成提交。 |
| 正常完成 | 末句已经渐隐结束且字幕隐藏 | 保持收尾互斥，固定本次终态结果，先调用唯一业务完成接收者，再发布一次完成观察；发布安全结束后解除匹配播放占用。 |
| 取消或失效 | 明确取消事实或必要依赖失效 | 固定旧会话异常结果并保留清理互斥，先失效令牌、停止音频计时与补间并隐藏字幕，再调用唯一业务异常接收者清理匹配归还限制及记录来电终止，最后发布异常观察并解除匹配占用。 |

语音推进使用 AudioStreamPlayer（音频流播放器）的自然完成。调用 stop（停止播放）及播放器离树不会发出自然完成信号，因此不能仅等待该信号处理释放，也不能把“不在播放”直接视为已正常结束。[官方完成语义](https://docs.godotengine.org/en/4.6/classes/class_audiostreamplayer.html#signals)

播放器的自然完成信号本身不带条目编号。每次连接或登记完成处理都保存当前播放令牌和条目索引；停止、换流、取消、新会话及依赖释放必须使旧处理失效。任何计时与补间回调同样匹配阶段及令牌；多次完成、旧完成和重入只能提交一次。正常终态业务提交成功后不再接受该令牌的取消；通知使用已固定的旧结果，不读取新会话字段补齐身份或执行清理。

当前句布局在显示前准备，语音不提前启动；下一句开始恢复文字与背景的不透明状态。准备不使用透明度或文字长度作为业务许可。缺失文本或语音不跳句，末句完成不以语音总时长、音频位置或预估文本阅读时间代替。

### 铃声与语音资源

铃声固定使用讨论指定的 [sfx_phone_default_0.wav（默认电话音效文件）](/D:/autolysis/main-autolysis/assets/audio/sound_fx/phone/sfx_phone_default_0.wav)。当前目录中另有新增铃声文件，不据此替换指定资源。

铃声使用 AudioStreamPlayer3D（三维音频流播放器），挂在电话位置；语音使用通用播放器内的 AudioStreamPlayer（音频流播放器），退出聚焦和限位内移动不改变语音位置或重启当前句。二者暂接现有 SFX（音效总线），音量及铃声衰减在场景中显式可调，采用引擎默认值作为初始调试配置，实际听感不写为已验收。[官方空间音频说明](https://docs.godotengine.org/en/4.6/classes/class_audiostreamplayer3d.html#description)

铃声运行时复制 AudioStreamWAV（波形音频流）资源，仅对电话专用副本设置 LOOP_FORWARD（正向循环模式）及完整样本区间；语音保持 LOOP_DISABLED（关闭循环模式）。循环区间按引擎解析后的实际样本数确定，不能按压缩文件字节数换算。具体采用采样率与引擎返回时长还原整数样本数，实施探针核对端点和跨循环播放。[官方循环属性](https://docs.godotengine.org/en/4.6/classes/class_audiostreamwav.html#class-audiostreamwav-property-loop-mode)、[铃声实际压缩配置](/D:/autolysis/main-autolysis/assets/audio/sound_fx/phone/sfx_phone_default_0.wav.import:24)和[引擎样本长度源码](https://github.com/godotengine/godot/blob/4.6.1-stable/scene/resources/audio_stream_wav.cpp#L457)为依据。

时长及采样率读取只用于铃声副本循环端点和验收观测，不用于普通接听许可或逐句完成。副本配置不得改写共享导入资源或把九句语音设成循环。

## 七 字幕排版与界面定位

使用独立 CanvasLayer（画布层）及同一显示根组织纯黑背景、内边距和 Label（文本标签）。背景采用无边框、无圆角的 StyleBoxFlat（纯色样式框），白字、黑底同受显示根 modulate（整体调制颜色）透明度影响，整体渐隐；不分别启动两个可能失步的补间。

排版步骤如下。

1. 取得当前实际字体、字号和完整中文字符串，用 Font.get_string_size（字体取得单行字符串尺寸方法）测量单行自然宽度；不使用“字符数乘字号”。中文与长词的换行设置使用 AUTOWRAP_WORD_SMART（智能词语换行模式）。[字体度量依据](https://docs.godotengine.org/en/4.6/classes/class_font.html#class-font-method-get-string-size)、[文本换行依据](https://docs.godotengine.org/en/4.6/classes/class_label.html#class-label-property-autowrap-mode)
2. 背景目标宽为“自然文本宽度加32像素内边距”，再取1000像素上限与当前视口可用宽度中较小者。先约束文本可用宽度，再完成自动换行和高度布局；短句背景保持自适应，不能设置1000像素固定宽度或最小宽度。[控件最小尺寸语义](https://docs.godotengine.org/en/4.6/classes/class_control.html#class-control-property-custom-minimum-size)
3. 单行背景精确使用40像素并垂直居中。上下留白依据实际单行字体高度确定；多行高度使用文本真实排版高度加相同上下留白，最低40像素，不用“行数乘40”替代排版。若所用字体无法在字号24、背景40像素内完整显示，先调整字体配置并复验，不悄然裁切或缩小字号。
4. 背景横向按当前视口居中，底边定位在道具栏实际顶边上方8像素；文本在背景中水平、垂直居中。道具栏矩形和字幕矩形先统一到同一界面坐标系，保持相同画布变换；不能把世界坐标、窗口原生像素和界面像素混用。
5. 条目变化、视口尺寸变化、道具栏布局变化和字体配置变化后重新排版。布局回调携带字幕会话及条目序号，旧布局结果不能改新句；本句开始前完成尺寸准备。
6. 字幕及其背景控件使用 MOUSE_FILTER_IGNORE（忽略鼠标模式）和 FOCUS_NONE（不取得焦点模式），不拦截聚焦点击、滚轮、测试按键或暂停输入。

字体采用现有主题字体作为首次验证起点，逐字验证九句中文及引号等标点的字形支持。缺字时更换或增加明确的中文回退字体，记录实际文件、许可来源与测量结果后再验收；不把当前默认字体视为已经通过中文验证。

本阶段较窄视口按实际可用宽度换行，不新增最小视口尺寸门禁。极小尺寸下的可读性或边距冲突记录为布局适配与展示测量问题，不因屏幕宽高终止来电或解除通话限制；真正的字幕对象、播放器或来源失效仍按必要依赖异常处理。背景颜色、宽高、字体度量和屏幕留白只作为表现配置或测量；电话普通取放不检查这些数值。

## 八 当前菜单与场景树暂停

不以字幕展示触发暂停。新增统一只读暂停查询，组合 SceneTree.paused（场景树暂停属性）、玩家 is_movement_paused（移动暂停标记）和 is_showing_ui（界面占用标记）；后二者沿用当前[基础输入许可](/D:/autolysis/main-autolysis/player/autolysis_player.gd:175)的菜单与界面事实。播放上下文提供该查询，通用播放器不自行访问电话。

给玩家上述标记建立变更入口或属性设置器，在当前 menu（菜单输入动作）切换和直接赋值时同步发布暂停状态。电话来电控制和通用播放所有者接入同一事实；接入时立即同步当前值，不能只等下一次变化。

每个所有者保留 PROCESS_MODE_ALWAYS（始终处理模式）以处理取消、来源释放和完成待同步；计时器与音频置于明确的时序子节点之下，继承该子节点的处理模式。该节点正常使用 PROCESS_MODE_PAUSABLE（可暂停处理模式）；菜单或界面标记为真时使用 PROCESS_MODE_DISABLED（禁用处理模式），二者都恢复后改回可暂停模式。外部场景树仍暂停时，该子树仍不能推进。渐隐绑定同一时序节点并使用 TWEEN_PAUSE_BOUND（绑定节点暂停模式），不要把补间绑定在始终处理的电话或播放器根上。

节点处理许可变化产生暂停、恢复通知并传给继承模式的子节点，音频据此保留并暂停或恢复流；这是该接法的引擎依据。[指定版本节点通知源码](https://github.com/godotengine/godot/blob/4.6.1-stable/scene/main/node.cpp#L647)、[指定版本音频暂停源码](https://github.com/godotengine/godot/blob/4.6.1-stable/scene/audio/audio_stream_player_internal.cpp#L107)、[补间暂停模式](https://docs.godotengine.org/en/4.6/classes/class_tween.html#enum-tween-tweenpausemode)

暂停不调用停止，不重新设置当前语音流，不重建计时或渐隐。来电等待保留剩余时间，铃声和语音保留位置，句后等待保留剩余时间，渐隐保留当前透明度。恢复继续原会话，不产生新的开始、完成或异常结果。

引擎信号在节点暂停时仍可能调用连接函数，因此每个完成回调还须核对统一暂停事实。暂停当帧已经到达的自然完成先保存为本次阶段的“完成待同步”，恢复后复核身份并推进一次；不要重播已自然结束的当前句。[官方暂停与信号说明](https://docs.godotengine.org/en/4.6/tutorials/scripting/pausing_games.html#process-modes)

实施时先运行最小无图形时序探针，核实处理模式切换对计时、音频和绑定补间的实际冻结及恢复顺序，再接入完整流程。本阶段补齐本功能对真实菜单暂停的适配，不重写全世界暂停行为或新增完整暂停菜单界面。

## 九 配置依赖与异常处理

每项检查记录业务事实、引擎依赖和来源，按实际影响限制入口。

| 检查或异常 | 保护的事实与依据 | 处理范围 |

显式取消或播放故障清理只解除匹配的对话归还限制。听筒本身仍有效时继续持筒并保留道具切换锁和限位，玩家重新聚焦原电话后可以按既有规则归还；来源、玩家或听筒必要依赖已失效时，则由现有听筒异常清理处理。两种结果都不向未来正式流程发正常完成。

异常原因记录包含来电序号、播放令牌、对话编号、当前句索引、来源和原持有会话；重复异常或旧回调只清理一次，不能清除后来建立的持有或播放。来源离树时失效本次请求，场景重载不恢复该来电或测试机会。

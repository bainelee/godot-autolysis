# 电话来电与对话系统讨论第一部分

记录日期：2026年10月6日。状态：需求讨论，已回填本轮补充确认；具体实施设计尚未定案。

本轮讨论电话来电的触发、延后、响铃、接听及听筒归还限制，以及可由不同入口启动的逐句对话显示。当前阶段用测试按键代替游戏流程事件，不接入正式游戏流程。下文分别记录用户已确定需求、当前工程事实和拟定设计；拟定设计与待确认项不表示已经实现或获得确认。

目标为 [machine_telephone_0.tscn（电话零号预制场景）](/D:/autolysis/main-autolysis/scenes/prefabs/prefab_machines/machine_telephone_0.tscn:65)。本轮交付讨论文档；配置文件格式在本文讨论，实际原文配置、中文本地化配置与运行功能在后续制作时建立。

## 一 本轮范围与术语

| 术语 | 本轮含义 |
| --- | --- |
| 来电请求 | 游戏流程通知电话有一通来电；当前由测试按键代替。请求可以等待，收到请求不等于已经响铃。 |
| 来电激活 | 来电满足听筒状态及延后条件，正式开始响铃。 |
| 接听成功 | 来电已经激活，玩家聚焦该电话并成功取下听筒，随后停止响铃并开始对应对话。 |
| 对话段 | 一组有明确顺序的文本和对应语音。本轮首段为 chat_0（第一段对话）。 |
| 对话条目 | 对话段中的一句文本及其语音。编号末尾数字表示顺序，从零开始。 |
| 正常对话完成 | 最后一句按约定显示流程结束后发出的完成事件。与暂停、取消及来源失效分别处理。 |

当前进入对话的方式只有接听电话；对话播放与字幕显示需要独立于电话入口，以便未来由其他事件启动。本轮不设计其他入口的具体玩法。

## 二 用户已确定的电话规则

### 测试触发

1. 来电由游戏流程事件触发；当前阶段用 O（测试字母键）发送一次来电请求。
2. 每次运行游戏只能使用一次该测试按键。一次请求进入等待也已消耗测试机会，不能因尚未响铃而再次触发。
3. 不需要讨论按键连续按下或重复按下的处理；运行一次只能触发一次是本轮需求。

### 持筒触发与延后

| 情境 | 已确定行为 |
| --- | --- |
| 来电请求到达时，玩家正在手持听筒 | 不激活来电，不响铃；请求进入等待。 |
| 来电请求到达时，听筒已经放在电话上 | 立即激活来电并响铃，不等待2秒。 |
| 等待中的来电，玩家将听筒放回 | 放回后等待2秒；连续满足条件后才真正激活来电。 |
| 放回后的2秒期间，玩家保持电话聚焦 | 允许继续聚焦，计时不要求玩家先退出聚焦。 |
| 计时期间再次取下听筒 | 本次计时失效；下一次放回后重新等待完整2秒，不累计此前已经经过的时间。 |
| 2秒条件完成 | 正式激活来电，开始循环响铃。 |

用户补充确认：2秒等待只用于持筒触发后延后的来电，不适用于请求到达时听筒已经放回的情况。

### 响铃与接听

响铃使用用户指定的 [sfx_phone_default_0.wav（默认电话音效文件）](/D:/autolysis/main-autolysis/assets/audio/sound_fx/phone/sfx_phone_default_0.wav)，在来电激活后循环播放。

来电激活期间，玩家聚焦电话并成功取下听筒：停止响铃，开始该来电对应的对话。等待阶段取下听筒仅影响等待计时，不表示接听了尚未激活的来电。

对应对话完成之前，玩家不能放回听筒。当前实现阶段，对话结束只发出对话完成事件，使玩家恢复放回听筒的许可。完成事件不自动放回听筒，不额外推进正式游戏流程。

用户补充确认：对话期间允许退出电话聚焦，并在现有电话限位范围内移动；本轮只增加放回听筒的限制。接听后不自动退出聚焦，玩家仍按现有操作自行退出或保持聚焦。

## 三 用户已确定的对话显示规则

### 显示区域

| 项目 | 已确定需求 |
| --- | --- |
| 位置 | 位于道具栏上方。 |
| 字号 | 暂用24。 |
| 背景 | 文字下方为纯黑色实心背景，渐隐阶段与文字一起变化。 |
| 单行背景高度 | 40像素。 |
| 背景宽度 | 随本条文字内容自适应，不固定铺满整行。 |
| 最大宽度 | 背景总宽最多1000像素，包含左右内边距。 |
| 超长文本 | 到达宽度上限后自动换行，背景高度随实际行数自适应。 |
| 换行后的宽度 | 最大宽度仍保持1000像素。 |
| 换行用途 | 为本地化后更长的文本保留适应能力；原语言的单条文本按设定不会超过一行。 |

用户补充确认布局：字幕整体水平居中，文字为白色；背景底边距离道具栏顶边8像素，左右内边距各16像素；1000像素计入背景总宽。不能把1000像素写成每条字幕的固定宽度，也不能把40像素固定到多行字幕。

### 逐条播放

每条字幕与本条编号对应的语音在同一条目开始时出现、播放。条目按以下顺序推进：

1. 显示当前条目文字及黑色背景，同时播放对应语音。
2. 等待本条语音播放完成。
3. 语音完成后继续保留本条文字1.5秒；此等待时长可以配置。
4. 用0.2秒将文字与背景一起渐隐。
5. 渐隐结束后显示下一条文字，同时播放下一条语音，重复上述过程。

下一条开始时需要恢复文字与背景的不透明状态，不能继承上一条的透明结果。逐句推进由语音完成决定，不能只按文本字数或估算音频时长推进。

用户补充确认：最后一句也在语音结束后等待1.5秒，再用0.2秒渐隐；字幕与背景全部消失后，才发出对话完成事件并恢复放回听筒的许可。等待时长仍采用可配置的当前值，1.5秒为默认值。

### 暂停与恢复

用户补充确认：打开游戏暂停菜单时，来电等待、铃声、对话语音、句后等待与渐隐全部暂停。恢复游戏后继续原进度，不重新开始当前句，也不把暂停视为完成或取消。

## 四 原文配置与中文本地化配置

### 两份配置的职责

| 配置 | 用户已确定的用途 |
| --- | --- |
| 原文配置 | 保存用户提供的原文，作为开发过程中主要编辑的文件。结构易读、换行明确、字符尽量对齐，配置信息简单清晰。 |
| 本地化配置 | 独立于原文配置；初次制作原文配置时同步制作。本轮只同步中文内容，不要求翻译其他语言。可采用便于开发、稳定清晰的格式。 |

两份文件在初始中文内容相同的情况下仍然具有不同职责，不能将原文配置直接改名充当本地化配置，也不能因暂不实现本地化功能而省略中文本地化文件。

### 拟定文件格式与维护方式

以下是格式建议，不是用户已经指定的文件名或格式。

原文建议采用 ConfigFile（配置文件）支持的分节键值格式，文件名可用 dialogue_source.cfg（对话原文配置文件）。每段对话独立分节，一句一行，句子保留引号，等号位置对齐，段落之间留空行。原文区域主要保留行编号和文本，不逐句重复长语音路径及界面参数。[官方分节键值格式说明](https://docs.godotengine.org/en/4.6/classes/class_configfile.html#description)确认引擎可解析该格式。

本地化建议采用 CSV（逗号分隔值）格式，文件名可用 dialogue_zh.csv（对话中文本地化文件），包含 keys（文本键）和 zh（中文语言列）两列。第一列保留用户指定的行编号，中文列初次逐字同步原文；文本中的引号、分隔符或换行按该格式转义。采用 UTF-8（八位统一字符编码）且不带 BOM（字节顺序标记）。[官方本地化表格格式说明](https://docs.godotengine.org/en/4.6/tutorials/i18n/localization_using_spreadsheets.html#formatting)确认翻译键区分大小写，语言列采用引擎支持的语言代码。

原文中的 chat_0（第一段对话）以及各句编号保持用户给定拼写。本文的中文括注用于解释标识；实际资源映射必须使用原编号。播放顺序需要明确记录；本轮按末尾数字零至八递增，不依赖可能变化的文件枚举顺序。

语音资源映射放在开发配置或条目加载规则中，不要求用户修改每句原文时同时编辑长路径。修改文本不能自动重新编号，因为编号还用于关联语音与本地化条目。

用户补充确认：暂时无需自动同步，后续中文本地化维护由用户手动处理。本轮仍保留“初次制作原文配置时同步制作中文本地化配置”的要求；后续不增加自动同步工具，不在启动游戏时自动覆盖用户维护的本地化文件。

当前阶段运行时读取原文还是固定中文本地化配置，用户尚未指定。建议本阶段读取原文，便于直接调整文本进行测试；此项保留为实施设计事项，不将建议写为已确认需求。完整语言切换与其他语言语音映射仍不属于本阶段。

## 六 拟定职责与状态推进

以下是依据需求与现有代码提出的接入设计。

### 职责边界

| 职责 | 拟定负责内容 |
| --- | --- |
| 测试触发入口 | 保存本次游戏运行是否已经触发；向指定电话发送来电请求。未来正式游戏流程复用来电请求入口，不依赖测试按键。 |
| 电话来电控制 | 保存请求、等待及激活状态，处理放回后的2秒计时、重置与响铃；接听后绑定本次对话和听筒会话，管理归还限制。 |
| 通用对话播放 | 按对话编号取得有序条目，驱动语音完成、等待与渐隐，发布对应会话的正常完成事件。无需知道电话聚焦或听筒节点。 |
| 字幕显示 | 管理文字、纯黑背景、字号、宽度限制、换行、道具栏上方定位及整体渐隐。 |
| 文本与语音配置 | 保存文本来源、本地化编号与语音映射，不承担电话持有许可。 |

每次运行一次的测试机会应由运行会话拥有，不能放在每次电话重新进入场景就会重置的初始化逻辑中。按“每次运行一次”的要求，场景重载仍不得重新获得测试机会；只有结束运行后重新启动游戏才重置。本轮不据此增加存读档。

### 电话状态推进

| 当前状态 | 触发事实 | 拟定处理 |
| --- | --- | --- |
| 未收到请求 | 本次测试请求到达，听筒被持有 | 保存请求，进入等待放回。 |
| 未收到请求 | 本次测试请求到达，听筒已放回 | 立即激活并循环响铃，不经过2秒等待。 |
| 等待放回 | 本电话正常归还成功 | 从归还成功开始新的2秒计时。 |
| 放回后计时 | 正常取下成功 | 清除已计时间，恢复等待放回。 |
| 放回后计时 | 满2秒，听筒仍已放回且没有未完成的取放 | 激活来电并循环响铃；旧计时不再生效。 |
| 来电已激活 | 本电话正常取下成功 | 绑定本次听筒会话，停止响铃，开始对应对话并禁止归还。 |
| 对话播放中 | 收到匹配本次来源、对话和持有会话的正常完成 | 清除本次对话归还限制；继续持筒，等待玩家自行放回。 |
| 等待、计时或对话期间 | 听筒会话异常终止，或来源、玩家、必要展示及限位依赖失效 | 进入独立异常处理，失效旧计时与播放回调，清理匹配会话资源和归还限制；不冒充正常放回或对话完成。异常后的来电恢复策略在实施设计中定案。 |

计时不依赖玩家是否正在聚焦。计时到期与取放请求相邻时，需要复核真实持有状态及待完成转移，避免在取下提交过程中激活来电。取消归还不能开启2秒等待；异常终止不冒充正常放回。

接听与计时以实际取下、归还完成事实为依据；对应观察通知为 handset_taken（听筒取下完成信号）与 handset_returned（听筒归还完成信号），异常通知为 handset_aborted（听筒异常终止信号）。当前[库存完成发布顺序](/D:/autolysis/main-autolysis/player/components/autolysis_inventory_controller.gd:374)先发送持物变化通知，再调用电话的完成发布，所以仅增加普通信号订阅不能保证业务锁先于全部外部观察回调建立。

拟定在成对提交的受控完成边界先建立来电状态、接听归属与归还限制，再发布观察通知和启动对话表现；失败回滚同步恢复相关状态。具体接入方式在实施计划中明确，不能依赖信号订阅顺序维护业务许可，也不能提前将准备中的取筒当成成功接听。[现有共享分发语义](/D:/autolysis/main-autolysis/components/interactions/autolysis_interaction_component.gd:86)仅确认请求已经分发。

归还限制应绑定来源电话、玩家与本次持有会话，在电话许可、库存归还入口和最终提交复核中使用同一事实。对话完成只解除匹配会话的限制，不能解除听筒本身的道具切换锁或移动限位；这些限制仍随实际听筒归还处理。

归还限制应作为独立只读事实查询，避免电话许可与库存许可彼此调用形成递归。归还事务的新令牌不等于原持有会话，对话完成仍匹配原持有会话；依据为[库存归还事务准备](/D:/autolysis/main-autolysis/player/components/autolysis_inventory_controller.gd:124)与[电话原持有会话保存](/D:/autolysis/main-autolysis/scenes/prefabs/prefab_machines/scripts/autolysis_telephone.gd:160)。

### 对话时序与表现

语音完成采用 AudioStreamPlayer（音频流播放器）的 finished（自然播放完成信号）。官方说明调用 stop（停止播放）或播放器离树不会发出这一完成信号，因此取消和释放必须单独处理，不能误报正常完成，也不能仅等待完成信号而永久挂起。[官方自然完成信号说明](https://docs.godotengine.org/en/4.6/classes/class_audiostreamplayer.html#signals)。

铃声循环单独配置；AudioStreamWAV（波形音频流）支持循环模式，语音保持非循环。[官方循环模式说明](https://docs.godotengine.org/en/4.6/classes/class_audiostreamwav.html#class-audiostreamwav-property-loop-mode)。铃声的空间衰减与语音的音量配置在实施设计中确定，不由文件名称推断。

字幕建议使用 Label（文本标签）与容器布局，按实际字体排版适应宽度及高度。到达上限后由文字控件换行，不用“字符数乘以字号”估算本地化文本宽度。[官方文本换行说明](https://docs.godotengine.org/en/4.6/classes/class_label.html#class-label-property-autowrap-mode)。40像素用于单行背景高度；多行高度依据实际排版增长，不直接假定每行均为40像素。

1000像素是最大宽度条件，不能通过将 custom_minimum_size（自定义最小尺寸）设为1000来实现；该属性设置的是下限。[官方尺寸属性说明](https://docs.godotengine.org/en/4.6/classes/class_control.html#class-control-property-custom-minimum-size)。

建议文字和背景放在同一显示根下，整体调整透明度；逐句更换时重新执行尺寸布局并恢复透明度。字幕为显示控件，不抢占聚焦点击或键盘焦点；需要验证所选字体确实支持九句中文。较窄视口下是否进一步限制为可用宽度，见第八节。

| 现有电话回归 | 空手取筒、道具切换锁、限位、取放取消、重新聚焦归还及来源清理继续符合既有规则。 |

## 八 补充确认与实施设计事项

| 补充事项 | 用户确认结果 |
| --- | --- |
| 听筒已经放回时触发 | 立即响铃；只有持筒触发的请求需要放回后等待2秒。 |
| 通话期间操作 | 允许退出聚焦并在现有限位内移动，只禁止放回听筒。 |
| 字幕布局 | 整体水平居中、白色文字、左右内边距各16像素；背景底边距道具栏顶边8像素；1000像素计入背景总宽。 |
| 最后一句完成 | 同样等待并渐隐，全部消失后发送完成事件，恢复归还许可。 |
| 游戏暂停 | 来电等待、铃声、语音、句后等待与渐隐全部暂停，恢复后继续原进度。 |
| 后续本地化维护 | 暂时无需自动同步，由用户手动处理；初次制作仍同步中文。 |

以下事项在实施计划中定案，不据此扩大本轮需求：

| 事项 | 当前状态与建议 |
| --- | --- |
| 运行时文本读取来源 | 用户未指定读取原文或中文本地化；建议本阶段读取原文以便直接调整测试。 |
| 较窄视口 | 用户规定最大宽1000像素；建议视口更窄时进一步限制为当前可用宽度，并继续自动换行，边距采用确认后的布局配置。 |
| 听筒异常后的来电恢复 | 旧等待、播放与归还限制先按异常处理结束；必要依赖恢复后是否重新等待该来电，在实施设计中定案。异常恢复不视为正常放回，不重新获得测试触发机会。 |

异常取消不属于正常完成。来源电话或玩家释放，或听筒展示、限位等必要依赖导致现有持有会话异常终止时，建议沿用既有异常清理，取消本次播放及等待，清除匹配会话的资源与归还限制；未完成的对话不向未来游戏流程发送完成。缺失文本或语音时的提示和恢复行为在实施设计中明确，不能悄然跳过条目并报告正常完成。

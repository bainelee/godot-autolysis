# 任务板聚焦与任务文件取放实现计划

编制日期：2026年10月7日。实施状态：代码已落地；最终无图形解析及9项行为测试通过，共1705条有效断言。图形可读性与原生操作未验证。实际改动、历史失败、修正与来源见[实施记录](D:/autolysis/docs/project-autolysis/00-discuss/交互系统/任务板实施证据/20261007/实施记录.md)。下文保留原编制基线与拟定方案，当前完成状态以实施记录为准。

目标是使[任务板预制场景](D:/autolysis/main-autolysis/scenes/prefabs/prefab_machines/quest_board_0.tscn)接入现有聚焦交互：通过 collision_board（板面碰撞形状）进入聚焦；手持任务文件时，点击任意空的 collision_quest_paper_slot（任务文件槽碰撞形状），将该文件放到对应 quest_paper_slot（任务文件槽锚点）下；再次交互取回同一件文件。

实施采用三个独立槽位入口、现有逐件道具资源和库存控制器主导的取放事务。纸面使用已有纯展示场景，任务标识、完整正文和分组随同一逐件实例往返。实施第一步删除三张示意纸，保留用户当前配置的槽位、板面和相机位置。

本次交付为计划及参考证据。用户已完成三槽物理体与碰撞父级调整，已重新读取保存后的场景核实。本轮代理未修改生产场景或脚本，聚焦登记和取放行为仍待实施。

## 一 需求与操作规则

1. 普通模式通过板面入口进入本任务板聚焦，使用 focus_camera（聚焦参照相机）。进入、退出、暂停和手持物随相机跟随，沿用现有玩家聚焦流程。
2. 三个槽位均可独立取放。命中哪个槽位就操作哪个槽位，不搜索首个空槽，不自动将文件移到另一槽位。
3. 放置成功后，当前选中道具格变为空格，对应槽位保存同一件任务文件，并在该槽锚点下显示纸面；其他道具格及其他槽位保持原有内容。
4. 取回成功后，该槽位变为空槽，原逐件实例进入当前选中的空道具格并恢复手持显示。选中格编号保持不变。
5. 退出聚焦后，板上的文件继续保留；重新聚焦后仍能取回。槽位占用不依赖原打印设备继续存在。
6. 实施时删除 quest_paper_0（零号示意纸）、quest_paper_1（一号示意纸）和 quest_paper_2（二号示意纸），并删除不再使用的示意纸场景引用。

取回条件沿用当前库存规则：空手指当前选中道具格为空，且没有听筒独占持有或交接。其他道具格有物品不影响空手。当前格有物品时，玩家先切到空格再取回；不自动寻找其他库存空格。依据为[当前格接收条件](D:/autolysis/main-autolysis/player/components/autolysis_inventory_controller.gd:557)和[普通手部互斥](D:/autolysis/main-autolysis/player/components/autolysis_inventory_controller.gd:303)。

| 聚焦与槽位状态 | 当前手持状态 | 本次交互结果 |
| --- | --- | --- |
| 已完成本板聚焦，槽位为空 | 有效任务文件 | 放入命中的槽位。 |
| 已完成本板聚焦，槽位有文件 | 空手 | 取回该槽原文件。 |
| 已完成本板聚焦，槽位为空 | 空手或其他类型物品 | 不转移物品。 |
| 已完成本板聚焦，槽位有文件 | 任意物品 | 拒绝取回和替换，保留双方来源。 |
| 未聚焦本板、聚焦过渡中、暂停或输入关闭 | 任意状态 | 拒绝槽位取放。 |
| 指定槽位正在转移 | 任意状态 | 拒绝第二次转移。 |

本次范围为场景运行期间的聚焦和文件取放，不扩展任务接取、任务完成、奖励、跨次运行存档或新的取放动画。

## 三 场景结构与聚焦接入

保留 quest_board_0（任务板根物理体）及现有板面、装饰和相机。根上新增任务板脚本、interactable（可交互）分组、唯一直属 AutolysisInteractionComponent（交互组件）和唯一直属 AutolysisFocusTarget（聚焦目标描述）。根组件使用 FOCUS（聚焦模式），分别绑定只读进入许可与唯一进入执行回调，执行调用现有 try_enter（尝试进入聚焦），复用[进入退出流程](D:/autolysis/main-autolysis/player/components/autolysis_focus_controller.gd:70)。

复用用户已调整的 quest_paper_slot_0（零号任务文件槽）、quest_paper_slot_1（一号任务文件槽）和 quest_paper_slot_2（二号任务文件槽），三者现均为独立 StaticBody3D（静态物理体），继续作为原位置的文件锚点。对应 collision_quest_paper_slot（任务文件槽碰撞形状）已直属各槽，实施不重复迁移；仅补充槽位脚本及一个直属交互组件。纸面作为命中槽节点的子节点挂接；其局部变换由槽位显示配置决定，默认使用锚点原点，不应用手持姿态。

当前三个槽体尚未序列化专用物理层，仍采用默认常规实体层。实施将槽位物理层设为第6层“聚焦内部对象”，层值32，碰撞掩码为0。现有聚焦查询掩码35包含此层，普通查询掩码3不包含此层，依据见[层名称](D:/autolysis/project.godot:136)、[聚焦掩码](D:/autolysis/main-autolysis/player/components/autolysis_focus_ray_query.gd:5)和[普通掩码](D:/autolysis/main-autolysis/player/components/interaction_raycast.gd:7)。根物理层保留当前常规实体配置，普通模式命中 collision_board（板面碰撞形状）后进入聚焦。

槽组件采用 DIRECT（直接模式），供聚焦控制器对已登记内部目标调用。模式名称不表示普通状态可以取放：槽体不参加普通射线，槽许可和库存事务均要求玩家已完成本板聚焦。现有[内部组件分发](D:/autolysis/main-autolysis/player/components/autolysis_interaction_controller.gd:323)已按此方式执行。

在聚焦描述中新增 configure_quest_board（配置任务板登记）、get_quest_board_slot_for_target（取得命中的任务板槽位）及对应登记清理。所有已有配置入口清理任务板旧登记，任务板配置入口清理其他设备登记。通过显式引用登记互异的槽体，不按节点名称或命中形状编号推断槽号。

在聚焦射线新增任务板首命中分支：首命中为本板已登记槽体时返回该槽；首命中为墙、其他设备或其他任务板槽时拒绝，不排除遮挡继续查询。保留现有点击队列对聚焦会话、选格、逐件身份和持有修订的复核，不增加新的鼠标轮询、系统指针定位或独立输入入口。

根、参照相机或核心登记失效时结束聚焦。单槽碰撞或交互组件失效只停止该槽入口，不因一槽故障使其他槽位退出。槽纸面失效仅停止其显示，保留已有资源登记与有效取回入口。装饰网格和纸面材质不参与根聚焦许可。

## 五 取放事务与失败恢复

只读许可查询不创建显示、不修改库存、不占槽、不发布通知。执行时同时持有库存互斥和命中槽互斥。事务记录玩家、库存、呈现器、聚焦控制器、描述器、会话序号、选中格编号、持有修订、指定槽、锚点、槽占用修订、逐件实例、内容快照和本次转移令牌。不同玩家或另一请求不能借用已有令牌。

### 放置顺序

1. 核对本板聚焦已完成、玩家输入许可、普通手部可用、当前格为有效任务文件、命中槽为空、来源对象存活且未排队释放。
2. 锁定库存及该槽；实例化现有纯展示纸张，调用 apply_instance（应用逐件实例）绑定原实例与全文，再临时挂到该槽锚点下。候选只属于本次事务，尚不发布正式占用。
3. 在入树、显示更新和可见性回调后，复核会话、选格、修订、原实例、内容快照、槽引用和候选实际父级。失败则移除本次候选并解除锁；原当前格和手持显示保留。
4. 暂存呈现器原手持显示和实例订阅；将当前格及目标槽暂存为转移后状态，暂存手持空显示。完成全部展示边界复核后，确立库存、槽占用和显示的统一最终提交点。
5. 最终提交后释放旧手持显示、发布库存与槽位观察通知，再结束本次互斥。完成后的清理或观察回调不撤销已经成功转移的逐件资源。

### 取回顺序

1. 核对本板聚焦、普通手部许可及当前格为空，确认槽资源登记与原实例身份一致。槽纸面存在时复核其父级和实例绑定；纸面已缺失时仍可从有效资源登记取回。
2. 锁定库存及该槽；先准备原实例的完整手持显示。准备失败时槽中来源保持不变。
3. 暂存撤销槽占用，保存匹配的资源回滚记录；原槽纸面仍存在时保留该纸面。将原实例暂存写入当前空格，挂接预备手持显示。尚未最终成功时不得释放原槽纸面。
4. 在显示挂接、实例绑定、可见性变化后再次复核上下文和来源身份。复核成功才完成双方提交，并清理仍存活的原槽纸面；失败则撤回本次库存写入和手持候选，恢复仍存活槽位的原资源占用。只恢复仍有效且与本次来源匹配的旧纸面，不在已释放节点上伪报显示恢复。
5. 成功后发布观察通知，当前格编号不变。后续继续点击已空槽不产生第二份文件。

现有 commit_prepared（提交预备显示）会提前隐藏、移除并排队释放旧显示，见[呈现器实际提交](D:/autolysis/main-autolysis/player/components/autolysis_held_item_presenter.gd:93)。因此新增可撤回替换必须保留旧显示至最终提交，不能仅恢复两个资源字段而遗留空手或重复纸面。已有[打印纸张成对提交](D:/autolysis/main-autolysis/player/components/autolysis_inventory_controller.gd:1180)与[匹配身份回滚](D:/autolysis/main-autolysis/player/components/autolysis_inventory_controller.gd:1267)作为事务边界参考，任务板实现采用自己的槽位来源合同。

回滚仅撤销本次令牌对应的实例、格和候选，不覆盖其他请求已经建立的来源。对象已释放时先确认有效性，不对已释放节点恢复父级或访问成员。最终提交前任务板或槽位释放时，放置仍保留原库存来源；取回尚未成功时按来源释放处理，禁止在不存在的槽位上伪报恢复。任务板整体释放代表世界来源生命周期结束，不在本次范围增加自动返还玩法。

退出聚焦、暂停或输入关闭若发生在暂存回调期间，则本次上下文失效并撤回；已经完成的取放保持终态。成功通知期间继续拒绝重复执行、普通获取和切格，只读查询可以读取最终状态。多个观察者只增加观察，不增加业务执行次数。依据为[唯一执行组件](D:/autolysis/main-autolysis/components/interactions/autolysis_interaction_component.gd:23)和[库存通知互斥](D:/autolysis/main-autolysis/player/components/autolysis_inventory_controller.gd:1631)。

# 原药混合器拉杆交互实现计划

编制日期：2026年10月2日。

本计划用于实现原药混合器的鼠标拖动拉杆、最低位置完成通知和自动回弹。当前只编写计划与保留取证记录，未修改功能代码、场景或输入配置，未运行游戏功能测试。下列新增脚本、接口与验收均为待实施内容。

需求依据为本轮用户描述及答复。工程现状以本轮实际读取的场景和脚本为准；既有[聚焦交互术语](D:/autolysis/docs/project-autolysis/00-discuss/交互系统/CONTEXT.md)继续适用。

## 一、已确认需求

1. 目标设备为 machine_blend_0（零号原药混合器），拉杆父节点为 switch_handle_blend_mechine_can_reset（可自动复位的混合器拉杆）。实际移动对象为其子节点 handle_interaction（拉杆交互体），交互碰撞形状为 collision_handle_interaction（拉杆交互碰撞形状）。保留现有节点拼写。
2. 拉杆相对父节点的初始位置为（0，0.12，0），最低位置为（0，−0.12，0）。仅改变局部纵向位置，横向和深度保持为0。
3. 在拉杆上按住鼠标左键，向下移动鼠标时下拉；鼠标纵向位移按可配置比例换算为拉杆位移。向上移动时回推，上限为初始位置。
4. 拖动期间保持鼠标指针可见；指针到达上下边缘后从相对边缘继续移动。循环定位不计为拉杆位移。
5. 用户所述“至少移动半个纵向屏幕”是操作体验描述，不是确定的像素数量或固定屏幕高度比例。检查器提供可调比例，最终数值通过真实操作调校确定。
6. 首次到达最低位置即完成本次交互。本期只发出一次完成信号，供后续功能接入；不据节点名称推断混合加工或设备复位效果。
7. 完成后在最低位置保持0.1秒，再用0.2秒匀速返回初始位置。保持及返回期间不接受新的拉杆交互。
8. 未到最低位置即松开左键，立即从当前位置匀速返回，不经过最低保持、不发出完成信号。回弹速度按最低至初始的0.2秒换算。

## 二、待确定参数与工程提案

### 2.1 比例调校

拟导出 mouse_to_handle_ratio（鼠标位移到拉杆位移比例），单位为“局部坐标单位／鼠标纵向输入单位”，必须大于0。先提供配置与位移计算，再在正式聚焦相机下试拉，记录所用比例、实际指针行程、窗口尺寸及用户体验验收结果。当前不编造最终默认数值，也不把“半屏”转写为固定0.5、540像素或其他需求阈值。

本计划拟采用 relative（相对位移）的纵向分量，与可见指针的游戏视口坐标一致。该字段会受到内容缩放影响，因此调校与验收需明确窗口尺寸及内容缩放配置；不要混用物理屏幕像素和视口坐标。[鼠标移动事件官方说明](https://docs.godotengine.org/en/4.6/classes/class_inputeventmousemotion.html#class-inputeventmousemotion-property-relative)说明了该缩放行为。

### 2.2 可见指针循环

用户已确认指针可以穿过边缘并从另一边继续。本期将这一规则用于正在进行的拉杆拖动：下拉到游戏画面底边时定位到顶边内侧；上推到顶边时定位到底边内侧。定位保留横向位置，指针保持可见，绑定对象和拖动进度不改变。未拖动、最低保持及自动回弹期间停止循环，不让普通聚焦点击受到影响。

拟调用 Input.warp_mouse（输入系统定位鼠标）完成循环。其参数是游戏窗口左上角为原点的像素坐标；调用前必须将画面边界与目标坐标转换到同一窗口坐标空间，并验证内容缩放及嵌入运行时的实际坐标关系。[官方定位鼠标说明](https://docs.godotengine.org/en/4.6/classes/class_input.html#class-input-method-warp-mouse)给出了坐标约定。

循环包含三个顺序步骤：先处理本次真实纵向移动，再进行边缘定位，最后继续处理后续真实移动。程序定位的跳变不得被当成向上回推或向下完成；不能按位置突变的正负直接驱动拉杆，也不能无条件丢弃定位后的第一个事件。实施时先验证指定引擎和本机后端产生的事件序列，再确定定位事件归零或坐标基准重置方式，并保留连续循环、快速反向及同帧松开的图形运行证据。

此处存在已取证的引擎行为：指定版本的可见鼠标定位会改变系统指针位置，鼠标移动消息再根据新旧坐标产生相对位移；screen_relative（未缩放相对位移）也不自动排除定位跳变。事件累积还可能把定位与真实移动合并。因此，循环接入前需记录定位前后实际位置、事件位置、相对位移及事件顺序，验证补偿只移除程序定位分量；不能用低频净位置采样替换有序输入后，仍声称完整保留同帧下拉再上推的路径。依据为[指定版本定位实现](https://github.com/godotengine/godot/blob/4.6.1-stable/platform/windows/display_server_windows.cpp#L886)、[鼠标移动消息实现](https://github.com/godotengine/godot/blob/4.6.1-stable/platform/windows/display_server_windows.cpp#L5212)及[移动事件合并实现](https://github.com/godotengine/godot/blob/4.6.1-stable/core/input/input_event.cpp#L943)。

指定版本的[引擎内部循环实现](https://github.com/godotengine/godot/blob/4.6.1-stable/scene/main/viewport.cpp#L1364)已说明定位与真实移动可能混合，并采用区域尺寸相关的启发式处理。该内部方法不能直接当作项目脚本接口使用；本计划只将其作为补偿算法与边界验收的参考。若实施中临时调整输入累积设置，必须在完成、取消和退出时恢复原值，并记录其对其他输入的影响。

### 2.3 本计划采用的工程提案

以下属于接入方案，不冒充用户额外提出的玩法规则。

| 项目 | 拟采用行为与理由 |
| --- | --- |
| 交互模式 | 沿用现有设备聚焦模式：稳定聚焦当前混合器后才允许开始拖动，进入和退出过渡期间拒绝。当前设备内部操作已经通过此链路处理。 |
| 拖动绑定 | 按下时必须实际命中拉杆；开始成功后，本次拖动绑定该拉杆与当前聚焦会话。指针离开拉杆碰撞区域仍继续拖动，不要求每次移动重新命中。 |
| 循环停止 | 完成、松开或取消时清理边缘定位状态，不强制把指针移回初始点击位置。自动阶段指针继续可见。 |
| 手持道具 | 拉杆操作不消耗道具，不要求空手。切格使尚未解析的开始序列按既有规则作废；已经绑定的拖动使用独立移动／释放队列，不依赖道具快照，不因切格清除。 |
| 其他槽位 | 拉杆拖动期间不把同一左键序列转交给其他对象。最低保持和回弹只锁定拉杆，不对四个槽位增加全局锁。 |
| 中断 | 右键退出聚焦、菜单打开、窗口失焦或拖动依赖失效时取消尚未完成的拖动；存活的拉杆按同一速度回弹，不发完成信号。 |
| 已完成后的退出 | 已经发出的完成信号不撤销。最低保持与回弹继续，由设备自身负责，不能因玩家离开就重复完成或永久停在最低位置。 |
| 暂停 | 主动拖动中发生场景树暂停时，由现有始终处理的交互控制器取消绑定；拉杆转为回弹，但暂停期间不推进。已经处于最低保持或回弹时只冻结计时。恢复后续接自动流程，新的拖动仍须新按下。菜单若没有暂停场景树，取消后的回弹继续。 |
| 新一轮操作 | 回到初始位置后，必须收到一次新的左键按下才能开始。保持左键不松开不会自动启动第二轮。 |

## 五、位移与回弹算法

### 5.1 拖动

每个有效移动事件读取鼠标纵向相对位移。屏幕向下为正，拉杆向下为局部纵向减小，因此：

**新的纵向位置＝限制到［−0.12，0.12］范围内的（当前纵向位置−鼠标纵向位移×配置比例）。**

只使用纵向分量，横向移动不改变拉杆。鼠标位移已经表示本次移动距离，不再乘帧间秒数。鼠标不动时，拉杆保持当前位置；向上移动以相同绝对比例回推。每个事件单独限位，超过端点的多余位移不积存为反向操作的死区。

到达下限后先把位置固定为−0.12，进入最低保持状态并锁定，再发出完成信号。不得用接近最低的视觉位置或提前触发的容差代替真正到达下限。完成通知的同步回调若删除拉杆或设备，后续流程必须检查对象仍存活。

### 5.2 回弹

**全行程＝0.12−（−0.12）＝0.24。**

**回弹速度＝0.24／0.2＝1.2局部坐标单位／秒。**

**任意位置的回弹时长＝（0.12−当前纵向位置）／1.2。**

| 松开时纵向位置 | 剩余行程 | 返回时间 |
| --- | --- | --- |
| 0.12 | 0 | 0秒 |
| 0.09 | 0.03 | 0.025秒 |
| 0.06 | 0.06 | 0.05秒 |
| 0 | 0.12 | 0.1秒 |
| −0.06 | 0.18 | 0.15秒 |
| −0.12 | 0.24 | 0.2秒 |

物理帧中以“1.2×本帧有效秒数”为步长向0.12推进，到达后精确归位并解除锁定。不采用缓入缓出，不对每个松开位置都使用固定0.2秒。

最低保持计时只在完成后启动。保持达到0.1秒后，若该帧还有剩余有效时间，将其用于回弹，避免每次转换额外增加一整帧。实际可见完成时刻允许按物理帧采样，验收同时记录理论时间、帧间隔与实际时间。

上述行程、速度、六个位置的回弹时间及碰撞层交集已进行十进制算术核验，结果见[数值核验记录](D:/autolysis/docs/project-autolysis/00-discuss/交互系统/原药混合器拉杆交互计划证据/数值核验记录.txt)。这是参数计算证据，不是游戏运行通过证明。

## 六、状态及完成信号

| 当前状态 | 输入或条件 | 动作与下一状态 |
| --- | --- | --- |
| 待机 | 当前设备稳定聚焦，左键新按下且实际命中拉杆 | 建立唯一拖动绑定，进入拖动。 |
| 拖动 | 左键持续按住，收到有效纵向移动 | 按比例改变位置并限位；未到最低则继续拖动。 |
| 拖动 | 到达最低位置 | 立即锁定为最低保持；释放玩家拖动绑定；发出一次完成信号。 |
| 拖动 | 最低前松开、退出或其他取消 | 释放绑定，不发完成信号；有剩余距离则进入回弹，已在顶部则待机。 |
| 最低保持 | 未满0.1秒 | 固定最低位置，拒绝新拉杆请求；松开不缩短保持。 |
| 最低保持 | 满0.1秒 | 进入回弹。 |
| 回弹 | 尚未回到顶部 | 匀速回弹，拒绝新拉杆请求。 |
| 回弹 | 到达顶部 | 精确恢复（0，0.12，0），进入待机；等待新按下。 |

拟新增 interaction_completed（交互完成信号），携带 actor（执行角色）参数，类型为 Node3D（三维节点）。信号只在“拖动转为最低保持”时发出；松开取消、回弹完成和后续重复点击均不发出。每个完整拉动周期最多一次。先改变状态再发信号，避免监听者同步调用交互造成重入。

## 七、模块与拟修改文件

### 7.1 拉杆功能

在[混合器脚本目录](D:/autolysis/main-autolysis/scenes/prefabs/prefab_machines/scripts)拟新增 autolysis_blend_handle.gd（混合器拉杆脚本），类型名拟为 AutolysisBlendHandle（混合器拉杆）。挂在 handle_interaction（拉杆交互体）上，负责初始和最低位置、比例配置、拖动限位、最低保持、匀速回弹、一次完成信号及自身配置校验。

拟提供 can_begin_drag（能否开始拖动）、try_begin_drag（尝试开始拖动）、apply_vertical_motion（应用纵向鼠标位移）、release_drag（松开拖动）、cancel_drag（取消拖动）、is_dragging_for（是否由指定角色拖动）接口。许可查询只读；开始接口返回实际开始结果。对象不自行监听全局鼠标，不操作道具栏，也不修改鼠标显示模式。

### 7.3 输入顺序及可靠释放

1. 开始沿用玩家的 _unhandled_input（未处理输入回调），尊重界面对左键的消费；在物理帧使用真实射线确认目标，经过唯一交互组件及业务许可。
2. 同一物理帧内可能出现“按下→移动→松开”。为拉杆保存有序事件，逐项处理，不能仅查询帧末按钮是否按住，也不能先求所有位移净和而漏掉中途到最低的完成。
3. 按下尚未由物理帧解析时，也需保存其后的移动与松开。只有确认按下命中拉杆才将对应序列交给拉杆；普通槽位点击保持现有语义。
4. 每个事件核对当前聚焦会话及绑定对象。已建立绑定的移动不重新射线选取对象，避免指针离开碰撞就丢失拖动。
5. 已建立或待解析的拖动序列必须收到移动、释放与取消。拟由统一输入层的 _input（输入回调）补充移动及释放观察，不在这一前置回调中开始世界交互；记录事件序号，防止同一事件又在未处理输入入口重复入队。以物理帧按钮状态作兜底，兜底在有序事件处理后执行。界面消费移动或释放、鼠标按钮事件的 canceled（已取消标记）、失焦及会话结束都不得留下永久拖动。
6. 输入队列、拉杆状态和物理位置由明确顺序推进；只有拉杆脚本写其位置。为物理帧中查询后开始的拖动确定处理顺序，实际验收保持和回弹没有额外一帧偏移。
7. 可见指针循环由交互控制器的本次拖动会话管理，拉杆对象只接收经核验的真实纵向位移。到边后先检查该移动是否已完成交互；已经完成则不再定位。松开、会话失效、窗口失焦和菜单取消时清理定位标记；改变窗口尺寸或内容缩放时取消本次拖动，避免继续沿用旧边界。
8. 分开管理尚未解析的开始请求与已经绑定的持续事件。既有 clear_pending_clicks（清空待处理点击）在切格时只作废开始请求；会话终止、菜单或暂停通过明确取消接口同时清理持续绑定，不将所有事件混放在会被切格清空的原点击队列中。
